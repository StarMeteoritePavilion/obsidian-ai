# gpu-unlock 让显卡性能翻倍！

RTX 4090 和 RTX 6000 Ada 都使用 AD102 GPU，出厂时分别保留了 512 个和 568 个 Tensor Core。仅按核心数量计算，RTX 4090 约为 RTX 6000 Ada 的 90%。作者认为，游戏性能大致符合这一比例，但在采用 FP32 累加的矩阵计算中，RTX 4090 的峰值算力只有 RTX 6000 Ada 的约一半。两张卡的首发价分别为 1,599 美元和 6,800 美元，后者超过前者的四倍。2026 年 10 月出现的开源项目 gpu-unlock，使部分 RTX 20、30、40 系列显卡的 FP32 累加吞吐接近翻倍。要理解这个结果，需要先区分矩阵乘加的精度、硬件吞吐和实际任务耗时。

## 为什么矩阵乘法常用 FP16 相乘、FP32 累加

矩阵乘法中的一个输出元素可以由成对的数字相乘，再将乘积相加得到。大模型大量使用这类计算，GPU 中的 Tensor Core 专门处理矩阵乘加。作者以混合精度为例，说明相乘和累加可以采用不同的数据类型。

FP16 占用空间小、计算快，最大有限值为 65,504。许多模型计算中的乘法使用较小的数，FP16 可以满足这一步的需求。累加数千乃至数万项时，FP16 更容易溢出或丢失精度。FP32 的最大有限值约为 3.4 × 10³⁸，表示范围和精度更高，因而常用于累加。将 FP16 输入与 FP32 累加结合，可以兼顾吞吐、显存占用和数值精度。

RTX 4090 在 FP16 累加时可以全速运行。切换至 FP32 累加后，硬件降低向 Tensor Core 发出指令的频率，吞吐约减半。以 FP16 输入的峰值算力为例，RTX 4090 在两种累加模式下分别约为 330 和 165 TFLOPS。按作者给出的对比口径，RTX 6000 Ada 在两种模式下均约为 364 TFLOPS。游戏画面的常规渲染主要由 CUDA Core 承担，游戏一般很少使用这种 FP32 累加路径，因此这项限制对游戏的影响很小。

## 固件如何保护性能设置

作者将控制累加吞吐的内部开关称为速度选择寄存器。RTX 4090 通电后，FP32 累加默认为半速。作者推测，厂商保留调整空间可能是为了方便工程调试。GPU 有从 Level 0 到 Level 3 的硬件权限层级，主机侧的访问处于最低层级，操作系统的 root 权限也不会提升 GPU 侧的访问级别。更改这项受保护设置需要 GPU 内部的高权限，SEC2 安全核心运行的固件在加载时还要进行数字签名验证。

研究人员于 2026 年 6 月发现，SEC2 固件的一个接口存在边界检查缺陷，可能引发缓冲区溢出，进而造成安全核心上的任意代码执行。缺陷发生在已签名的固件处理外部输入的过程中。作者以 gpu-unlock 为例，说明固件漏洞可能影响受保护的性能设置。

## 峰值吞吐如何转化为实际提速

作者以 RTX 4090 的 FP32 累加为例，给出的峰值算力从 165.6 TFLOPS 增至 331.6 TFLOPS。作者提到，ComfyUI 生成图像、模型微调等实际任务中的 RTX 4090 提速约为 15% 至 35%，并用约 20% 概括其量级。这里的峰值数字对应特定精度的矩阵计算，实际任务还包含其他计算和数据搬运。

两个因素会限制整体提速：

- **功耗上限**。RTX 4090 默认的功耗上限为 450 W，显存和其他电路也占用功耗预算。Tensor Core 加快后，显卡更容易达到上限并自动降频。作者给出的 RTX 30 系列提速约为 25% 至 55%，并将较高增幅归因于较少的核心、较低的功耗和更大的功耗余量。
- **显存带宽**。运行模型还需要在显存和计算核心之间搬运数据。Tensor Core 可以更快完成矩阵乘加，搬运速度仍受显存带宽约束。数据搬运在任务中所占的时间越多，单独提高矩阵吞吐带来的整体收益就越有限。

gpu-unlock 最初面向 Linux，随后也有社区项目面向 Windows。作者称，RTX 50 系列的 FP32 累加吞吐依然约为相应全速档位的一半，但首发固件没有出现同一漏洞，硬件也不兼容前代固件。此前几代显卡的结果因此有明确的适用范围。

## 固件修补与旧设备兼容性

按作者在视频发布时的说法，较新驱动配套的固件已修复该缺陷。作者也提出让新固件在初始化时重设性能档位，但这种处理的效果取决于实际加载的版本。如果硬件仍接受较早的签名固件，旧版本所含的缺陷仍有可能重新暴露。作者提出以一次性可编程熔丝（OTP fuse）记录最低允许固件版本。该记录只能单向提高。硬件加载固件时按此检查版本，最低版本一旦提高，被淘汰的固件便无法重新加载。

手机、游戏机等一体化设备也会使用防回滚机制。将同一机制用于可以在不同主机间迁移的独立显卡，涉及额外的兼容性取舍。例如，旧操作系统可能只能使用早期驱动，二手显卡也可能被装入这样的系统。对这类场景，永久提高最低固件版本会缩小可用的驱动范围。

整件事经历了制造工艺提高芯片性能、厂商按产品定位设置限制、研究者找回部分吞吐的过程。作者认为，付出大量时间只换来约两成实际提速，从经济上看并不划算。探究硬件的运行方式本身仍能带来乐趣。
