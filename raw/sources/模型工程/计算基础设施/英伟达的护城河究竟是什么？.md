> “AI技术”合集／AI 计算硬件独立专题

CPU 可以执行 AI 模型需要的运算。计算卡的价值并非让原本不能运行的模型变得可运行，而是用高带宽内存、大量并行计算核心、卡间互联和成熟软件栈，把推理与训练加速到可用、可扩展的程度。

## CPU 能计算模型，但数据搬运可能先成为瓶颈

在只使用普通计算机的情况下，硬盘保存模型参数，模型启动时先把参数载入内存，CPU 再读取参数并执行计算。只要内存容量足以容纳全部参数，理论上 CPU 可以运行任何 AI 模型。硬盘通常只在模型加载时参与，因此持续推理时更重要的是 CPU、内存及二者之间的数据传输。

以 Llama 3.1 405B 为例，资料用教学估算说明瓶颈的位置。405B 即 $4.05\times10^{11}$ 个参数；若生成一个 Token 时，每个参数近似参与一次乘法和一次加法，则需要约 $8.1\times10^{11}$ 次浮点运算。资料根据 AMD EPYC 9965 的核心数、默认频率和 AVX 指令集，估算其理论吞吐约为每秒 $2.8\times10^{13}$ 次浮点运算，单看算力足以达到每秒三十多个 Token。然而，资料给出的实际生成速度约为每秒 0.7 个 Token。

差距来自内存带宽。若 405B 参数采用 FP16，每个参数占 2 字节，模型约为 810GB。12 通道 DDR5 的峰值带宽约为 600GB/s，完整读取一次参数约需 1.35 秒。自回归生成下一个 Token 时又要再次使用绝大多数参数，而 CPU 缓存只有 MB 数量级，无法长期保留数百 GB 参数。因此，在该简化模型中，每生成一个 Token 都近似需要重新读取全部参数，速度最终接近带宽上限，而不是理论计算上限。

上述数字是视频发布时针对指定模型、精度和硬件的教学估算。实际速度还会受到量化、批量、算子实现、内存访问模式和推理框架影响。

## HBM 用更短的物理路径换取高带宽

HBM（High Bandwidth Memory，高带宽内存）把内存与计算单元紧密封装，以较短的物理线路提高带宽。资料给出的 HBM3 单堆栈极限速度为 0.82TB/s；H100 使用五个堆栈，理论值约 4TB/s，为稳定性运行在较低频率，总带宽为 3.35TB/s；B200 使用 HBM3e，总带宽达到 8TB/s。

这类带宽足以在一秒内多次读取约 800GB 的参数，使单请求生成速度进入每秒数个到数十个 Token 的可用范围。HBM 通常不采用普通内存条的可插拔形态，因为插槽、内存电路和主板走线都会增加距离与限制。资料据此判断，即使出现可插拔 HBM，也会付出性能损失。

HBM 加高性能 CPU 并不经济。EPYC 9965 刚发售时价格接近 15,000 美元，能够容纳约 800GB 参数的 HBM 成本更高。这类方案面向同时服务大量请求的企业级场景，而不只是个人推理。

## 批量请求把瓶颈从带宽转向并行计算

单个请求按照模型顺序使用参数，难以让同一批参数在一次生成中反复复用；多个互不相关的请求却可以共享参数搬运。系统可以先把一部分参数放入缓存，再用这部分参数同时计算一批请求，然后继续加载下一部分。资料用“每次搬运 100MB 参数，同时处理 1,000 个请求”说明：完整搬运一次约 800GB 参数后，可以为 1,000 个请求分别生成一个 Token。

此时内存带宽被摊薄，计算核心数量成为新瓶颈。通用 CPU 只有数十到上百个复杂核心，还要支持条件判断、异常处理和虚拟内存管理等 AI 数值计算不需要的功能。计算卡则保留大量适合并行数值运算的核心，以较少的通用能力换取吞吐。

英伟达在 2006 年发布的 GeForce 8800 GTX 中引入了这类可编程并行计算能力。资料列出的 2026 年 B300 配置为 20,480 个 CUDA 核心，FP16 算力为 2,500 TFLOPS，即每秒约 $2.5\times10^{15}$ 次浮点运算，约为前述 EPYC 教学估算的 90 倍。H100 则包含 16,896 个 CUDA 核心和 80GB HBM；B300 包含 20,480 个 CUDA 核心和 288GB HBM。把大量并行核心与 HBM 集成在同一硬件中，就形成了面向 AI 计算的计算卡。

## 推理与训练需要不同的卡间通信

单张 H100 的 80GB HBM 无法容纳 FP16 下约 810GB 的 Llama 3.1 405B。模型可以沿参数顺序拆到多张卡上：第一张卡保存前段参数，后续卡保存后段参数，推理时依次传递中间激活。资料将这类中间结果概括为几十到几百 MB，因此串联卡之间的传输通常不构成与参数同等规模的负担。需要扩大并发时，还可以增加多组模型副本；不同请求之间不必交换生成数据，甚至可以分布在不同机器上。

训练的通信要求更高。Llama 3.1 405B 的训练使用了 15 万亿个 Token。为缩短训练时间，系统需要并行运行多组计算卡；每组根据各自数据计算梯度后，还要跨组聚合与平均，再更新参数。梯度规模与模型参数同量级，H100 单卡一次便可能需要传输约 80GB 数据。

PCIe 5.0 的资料口径为 64GB/s，传输约 810GB 数据需要十余秒，无法满足高频梯度同步。NVLink 为计算卡间的高速通信定制：H100 的 NVLink 4.0 约为 900GB/s，B200／B300 的 NVLink 5.0 达到 1.8TB/s。PCIe 追求通用连接能力，NVLink 则用更窄的目标换取 AI 集群所需的带宽。

## 硬件规格不是英伟达唯一的壁垒

AMD MI355X 展示了硬件层面的直接竞争。视频画面列出的配置为 16,384 个流处理器、2,517 TFLOPS FP16 算力和 288GB HBM；B300 为 20,480 个 CUDA 核心、2,500 TFLOPS 和 288GB HBM。AMD 的 Infinity Fabric 带宽为 1,075GB/s，低于 NVLink 5.0 的 1.8TB/s，但仍处于同一数量级。视频发布时的画面价格为 MI355X 25,000 美元以上、B300 40,000 美元以上。

开场还转述了“MI350 约 15,000 美元”的市场说法；后文正式比较及画面展示的是 MI355X 与 25,000 美元以上的价格。两处不是同一精确型号与价格口径，不能合并。

硬件差距缩小以后，软件兼容性成为更深的门槛。研究者通常用 PyTorch 描述模型和算子，代码默认可以在 CPU 上执行；使用英伟达 GPU 时，PyTorch 会经由 cuBLAS、cuDNN 等中间层调用 CUDA 内核。英伟达长期维护的底层实现覆盖大量科学计算，并成为研究和工程事实上的优先支持目标。新算法与优化往往先适配这一体系，进一步强化软件与硬件的共同生态。

AMD 以 ROCm 支持其计算卡并兼容更多围绕英伟达生态开发的算法，但资料认为其兼容性仍落后于 CUDA。华为昇腾除兼容性问题外，还受到视频所述 7nm 制程限制；资料同时肯定其从零开始做到稳定运行部分模型的工程进展，并指出后续挑战仍然很大。

这些判断反映视频发布时的产品、软件与政策状态，不应外推为长期不变的厂商排名。

## TPU 选择另一套完整技术栈

Google TPU 没有沿用 CUDA 兼容路线。硬件上，MXU 承担矩阵计算，ICI 提供互联；软件上，OpenXLA 另建面向 AI 的开源标准。它没有覆盖英伟达生态中的全部科学算法，上下层软硬件选择也更有限，但已经贯通推理和训练各环节。

Google 的商业模式不是单独出售计算卡，而是在 Google Cloud 中出租 TPU。价格可以相对更低，开发者也需要承担更高的迁移与适配要求。Google Gemini 完全使用 TPU 训练；视频还提到 Anthropic 已开始租用 TPU 进行训练。

不同路线很难只凭峰值算力判断优劣。英伟达的核心优势不是某一块芯片，而是计算核心、HBM、互联、底层库、框架支持和研究者习惯共同形成的二十多年积累。竞争者可以追平部分硬件规格、降低价格或重建技术栈，却仍要补足长期生态投入。英伟达最深的护城河，归根结底是时间。
