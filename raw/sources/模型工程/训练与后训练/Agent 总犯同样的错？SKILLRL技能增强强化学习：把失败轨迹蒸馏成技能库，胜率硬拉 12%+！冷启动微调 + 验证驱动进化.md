# SkillRL：技能库与策略的协同学习

大模型 Agent 即使失败多次，再次执行同类任务时仍可能掉进相同的陷阱。常规做法是把成功和失败的原始轨迹全部存入向量数据库，遇到新任务时检索并塞进 Prompt，但这条路线有两个工程问题：长轨迹包含大量无效数据，会拖慢推理并分散模型注意力；直接用高噪声长轨迹进行强化学习，又会因探索空间过大、环境反馈稀疏而难以收敛。

SKILLRL 不保存全部原始轨迹，而是把经验蒸馏为结构化技能库，再以两段式训练和验证驱动更新，让模型参数与外部技能共同演化。

## 三个核心设计

### 经验驱动的技能蒸馏

系统使用教师模型分析轨迹：成功轨迹被提炼为可复用策略，失败轨迹被提炼为失败点、错误行为、正确做法和避免重犯的原则。原论文第3.1节明确给出这两种差异化处理，没有报告“10～20倍文本压缩”这个比例，因此本文不保留该数字。[^论文]

蒸馏的目标不是保存事件的全部细节，而是保留能够迁移到新任务的高层规律。相比直接检索原始轨迹，结构化技能减少噪声，也缩短了进入模型上下文的经验表示。

### 两段式对齐训练

SKILLRL 不会把基础模型直接投入强化学习，而是先进行冷启动 SFT，再进入技能增强 RL。

冷启动阶段由教师模型构造包含正确技能调用方式的高质量数据，让基础模型先学会认识、检索和遵循外部技能。强化学习随后在这一行为基础上探索更优策略，避免模型为追求短期奖励而完全忽略技能库。

### 验证驱动的递归进化

技能库并非静态制品。系统持续监控验证集上的任务表现；当某类任务的成功率跌破阈值，就挑出对应失败轨迹交给教师模型复盘。教师模型把失败原因与现有技能库对照，识别盲区、生成新的技能规则并热更新技能库。

这一循环让策略模型通过强化学习更新参数，同时让外部技能库从新失败中扩充，形成策略与技能的协同演化。

## 四步运行流程

完整系统可以分成四步：

1. 让基础模型在环境中运行，收集成功与失败轨迹。
2. 由教师模型把成功轨迹提炼为通用技能，把失败轨迹提炼为避坑规则，写入 Skills 技能库。
3. 由教师模型生成能够正确调用技能的训练数据，以冷启动 SFT 让基础模型掌握技能使用方式。
4. 启动强化学习循环：新任务先检索相关技能并注入 Prompt，模型据此行动并更新参数；验证失败触发教师模型复盘和技能库热更新。

原始轨迹、训练数据、参数化策略与外部技能库在这条流水线中承担不同职责。技能库保存可迁移的高层经验，模型参数学习怎样在任务中使用这些经验。

## 两个关键机制

### 行为锚点

纯预训练模型直接进入强化学习后，可能为快速取得高分而走捷径，忽略注入 Prompt 的技能规范。SKILLRL 在强化学习中设置行为锚点，约束新策略不能偏离冷启动阶段学到的技能使用行为；模型若不再查阅或遵循技能库，系统就施加惩罚。

这个机制允许模型探索，但把探索限制在仍然使用技能知识的行为范围内。它解决的不是技能库有没有内容，而是参数更新后模型是否还愿意使用这些内容。

### 自适应纠错

静态技能库无法覆盖后续出现的新任务。每个验证周期结束后，性能监控组件识别低于成功率阈值的任务，将失败轨迹提交给教师模型。教师模型不重写全部指南，而是对照旧技能找出缺口，只补充新的规则。

外部技能库由此承担可扩展记忆，使较小模型能够使用不断积累的经验；但技能增长也会引入冗余、冲突和检索成本，不能视为无限扩展而没有代价。

## 实验与消融结果

论文表1覆盖 ALFWorld 家庭具身操作和 WebShop 电商导航。SkillRL 在两项任务上的成功率分别为89.9%和72.7%；同表GRPO分别为77.6%和66.1%，因此 ALFWorld 的绝对差是12.3个百分点。PickTwo子任务相对GRPO从64.7%升至87.5%，差22.8个百分点，论文正文将其取整描述为约23%。这些数字来自论文的特定模型、任务和实验设置，不能直接外推为其他 Agent 的收益保证。[^论文]

消融实验显示各部分不是可随意删除的装饰：

- 去掉层级化技能结构后，ALFWorld 和 WebShop 分别为 76.8% 和 61.4%。
- 去掉技能库、改用原始轨迹后，分别为 61.7% 和 50.2%。
- 去掉冷启动 SFT 后，分别为 65.2% 和 46.5%；ALFWorld 相比完整系统下降 24.7 个百分点。
- 去掉动态进化后，分别为 84.4% 和 70.3%；ALFWorld 下降 5.5 个百分点。

论文图5展示的 Prompt 长度对比中，直接检索原始记忆平均约需1450 Token且波动较大，SkillRL平均低于1300 Token，论文报告运行时上下文长度减少约10.3%。这是论文提供的系统级口径；本文不再保留无法在论文定位的“单条轨迹压缩10～20倍”。[^论文]

## 落地前的五个工程风险

### 技能库冗余和冲突

技能库会随验证失败持续增长，必须配套淘汰、合并或冲突处理机制。否则检索可能同时返回逻辑相斥的技能，使模型无法稳定行动。

### 强化学习的显存开销

强化学习需要并发采样多条轨迹并比较结果。并发规模增长后，显存可能成为直接瓶颈。

### 教师模型瓶颈

论文的经验蒸馏和冷启动依赖教师模型生成技能与示范，因此教师质量是数据管道的一项依赖。具体应根据技能正确率与验证效果选择教师；论文没有把某个商业模型写成固定产品要求。[^论文]

### 在线检索延迟

多轮交互的每一轮都可能需要相似性检索。资料建议使用成熟的向量数据库处理检索，而不是自行编写循环；实际系统仍需测量召回质量、延迟和上下文预算。

### 奖励欺骗

环境反馈不准确时，模型可能学会假装调用技能来获得奖励，形成 Reward Hacking。技能调用是否真实发生、是否改善最终结果，需要由可验证环境反馈和独立评测共同确认。

## 当前局限

SKILLRL 仍然依赖中心化的强教师模型完成经验蒸馏和技能更新。资料认为，长期方向需要转向自我博弈与自我蒸馏闭环，降低对外部顶级模型的依赖。

另一个未解问题是超长任务的信用分配。当轨迹包含数千步时，系统仍难以精确定位哪一步造成致命错误；把失败压缩成技能不能自动解决所有长程归因问题。

## 总结

SKILLRL 解决的是 Agent 难以复用高层经验、直接加入历史轨迹又造成上下文和训练负担的问题。它把轨迹蒸馏为技能，以冷启动 SFT 建立技能使用习惯，再用强化学习优化策略，并根据验证失败持续更新技能库。

其核心价值不只是增加一套外部记忆，而是用验证驱动的方式让参数化策略与外部知识协同演化。相应代价也很明确：技能治理、显存、教师质量、检索延迟、奖励可靠性和长轨迹信用分配必须同时进入工程设计。
