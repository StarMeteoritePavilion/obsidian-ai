> 大模型后训练独立专题

大模型训练通常默认“想让模型掌握什么能力，就提供对应数据”：处理百万 Token 任务需要长文本训练样本，进入新领域需要新的领域环境。MIT 研究者 Alex Zhang 与 Omar Khattab 在《Language model harnesses are compositional generalizers》中提出了另一种路径：用强化学习训练 Recursive Language Model（RLM）的 Harness，使短任务中学到的分解方法迁移到更长任务和陌生领域。

资料所述核心判断不是神经网络不重要，而是 Agent 的组合泛化可能主要来自模型外部的 Harness。相同模型、算法和训练数据，在不同 Harness 中会形成不同的泛化曲线。

## 组合泛化与“被错误管理的天才”

组合泛化指把已经掌握的基本能力重新组合，用于解决未见过的问题。人学会查资料、做笔记后，可以整理一本没有读过的书；但 Transformer 面对新领域或远长于训练分布的输入时，往往需要新的对应数据。

资料将这一问题概括为“被错误管理的天才”：许多人类关心的复杂任务可以拆成一组小任务，而这些小任务没有超出当前模型的能力。模型缺少的未必是完成每个局部步骤的能力，而是一个能够拆分、调度和隔离信息的管理层。

如果每份训练投入只能得到一个任务或领域的能力，数据 Scaling 很难形成复利；如果模型学到的是可组合的解题骨架，同一训练投入便可能覆盖整类任务。

## Harness 决定模型每次看到什么

Harness 是模型与环境之间的程序层。环境中的文件、命令、工具返回和网页以什么方式进入 Context，模型输出后执行什么动作，都由 Harness 决定。Claude Code、Codex 等 Agent 产品都包含这类程序层。

资料认为，工具调用只是 Harness 的表层能力，更关键的权力是控制每次模型调用看到的信息。主流 Agent 常把工具输出和中间推理持续追加到主 Context；任务越长，Context 越容易形成训练数据中罕见的混合结构。资料把这种退化称为 Context Rot，并以 384,000 Token 的工具输出与推理混合上下文作为示意。

研究提出的可靠性标准是“局部分布内”（locally in-distribution）：完整任务可以处于分布外，但 Harness 应保证拆分后的每次模型调用单独看仍接近模型熟悉的输入分布。任务无论多长、领域多陌生，模型每次只处理规模和结构可控的局部问题。

## Harness 折叠任务等价类

局部分布内不仅用于控制可靠性，还能让表面不同的任务在模型看来具有相同结构。资料比较网页资料多跳检索与数据集统计：两者内容无关，但都可以抽象为摸清数据规模、切块、并行派发子任务和汇总结果。

RLM Harness 隔离具体内容后，主模型主要看到这套分解骨架。两条任务轨迹可以接近逐 Token 相同。研究把解法相同的任务视为等价类：模型不必分别记住大量具体任务，只需学习少量可复用的程序化套路，再把同一套路应用于不同长度和领域。

## RLM 的两个隔离机制

### Context Offloading

任务原始材料不直接进入主模型 Context，而是保存在代码环境的变量中。主模型只获得变量名，通过代码逐步探查数据，例如打印长度、开头 500 个字符和结尾 500 个字符。

资料展示的一条训练轨迹包含 78,000 字符，评测轨迹包含 618,000 字符，长度相差约 8 倍；两条轨迹第一步却是相同的 Python 代码：

```python
print(len(corpus), corpus[:500], corpus[-500:])
```

主模型观察到的主要差异只是打印出的长度数字和少量样本，而不是八倍增长的原始材料。

### Programmatic Subcalls

子模型和工具被包装为代码函数，例如 `sub_llm(...)`、`search(...)`、`count(...)` 与 `summarize(vars)`。调用结果保存在变量中，在函数之间传递；主模型不必看到每个子任务的完整输入与返回，只在需要汇总时让新的子调用读取相关变量。

Context Offloading 隔离原始输入，Programmatic Subcalls 隔离中间结果。主 Context 因而主要保留代码、少量探针输出和与领域无关的分解逻辑。

## 长度泛化实验

研究使用强化学习训练一个 30B 开源模型，训练只提供短任务，包括 64K Token 的检索题；评测把任务长度扩大 8～32 倍，最长达到 2M Token。训练共运行 150 步，每 10 步在长版本上评测一次。

六个环境分别从输入长度、输出长度和指令数量增加难度，涵盖大海捞针式检索、图遍历、长文档选择和统计聚合等任务。带 RLM Harness 的长任务成绩随短任务训练奖励同步提高；在六项基准中的四项上，训练过的 30B 系统追平或超过以 GPT-5.5 为底座、但没有经过该训练的 RLM 系统。

直接训练对照组使用相同模型、算法和短任务，却不套 RLM Harness。资料展示的训练末端奖励约为 0.93，高于 RLM 组的 0.85，但长任务评测分数只有 11，RLM 组为 78。该结果说明训练内奖励更高并不等于能够迁移到长任务；这些数值只属于资料所述实验设置。

### 短任务捷径与可泛化分解

RLM 提供了可泛化的路径，但强化学习不一定自动找到它。一个环境中，模型发现把完整问题原样交给单次子调用即可在短任务上得分；长度增加后，这条捷径退化为普通长 Context 处理并失效。研究者在提示中增加一句先说明分解计划的要求，才引导模型使用可泛化方案。

另一个环境中，模型起初也使用短任务捷径，却在继续训练后自行放弃，并找到更通用的分解方法；其长任务提升幅度最终超过短任务。两种结果共同说明，Harness 让通用算法成为可探索路径，但训练是否发现这条路径仍取决于奖励、探索与必要的引导。

## 跨领域泛化实验

第二组实验保持长度不变，直接更换领域。训练任务要求从散文集合中找出可能由同一作者写作的文章，评测任务要求从数学题中找出推理过程相同的问题。文本内容没有重叠，底层流程却都是逐项打分、过滤和排序。

RLM 在陌生领域的成绩随原领域训练奖励同步提高。直接训练对照组在训练任务上的奖励更高，但陌生领域只因学会答案格式获得一次有限提升，随后趋于平坦。资料据此区分了记住训练任务与学习可跨领域复用的解题骨架。

## 固定倍数的训练成本

RLM 每条训练样本需要多轮模型调用并等待子任务，耗时是直接训练的 1.5～3.0 倍。它不是免费获得泛化，而是用相对固定的额外调用成本换取受控的主 Context。

直接训练的成本会随任务长度和 Context 膨胀快速上升。资料以 8 张 H100 训练 30B ReAct Agent 为参照，指出 Context 增长已经造成明显负担；RLM 的主 Context 保持较短，额外成本更接近固定倍数。因此，任务越长，固定倍数与随长度快速增长的成本之间的差异越重要。

## 归纳偏置可以写在程序层

研究并不主张为每类任务手工写死 MapReduce 或动态规划。作者对“苦涩教训”的回应是，数据 Scaling 仍是能力进步的主要来源，但数据进入什么系统，会影响模型更容易学到什么；这种倾向就是归纳偏置。

Transformer 在组合泛化上的归纳偏置较弱。当前模型已经具备较强的语言和编程能力，因此部分归纳偏置不必全部固化在神经网络结构中，也可以写入网络之上的程序层，再通过强化学习对整个系统进行端到端训练。RLM 的通用约束只有一个：把复杂问题转换成一串局部分布内的模型调用，而不是预先写死具体领域的解法。

这也使 Context Engineering 从节省 Token、减少混乱的工程问题，扩展为影响后训练泛化效率的学习问题。中间结果保存在变量和文件中，主模型只接收完成当前局部决策所需的信息；同一份训练投入由此可能学会一类任务，而不是一道任务。

## 适用边界

资料提出两项保留意见。第一，实验任务多为检索、图遍历和聚合等天然适合切块的结构；当子问题高度耦合、无法干净拆分时，RLM 是否仍能泛化，研究没有回答。第二，实验只验证一个 30B 底座；更换模型后，Harness 的相对优势会扩大还是缩小，仍需验证。

因此，“泛化主要来自 Harness”是这组实验支持的研究结论，不是所有 Agent 和模型的普遍定律。Harness 与模型架构的边界可能逐渐模糊，但 RLM 的有效性仍取决于任务可分解性、训练能否找到通用路径、调用成本和基座模型。

## 结论

RLM 把后训练对象从孤立模型扩展为模型与 Harness 组成的系统。模型可靠性不仅取决于任务整体难度，也取决于每次调用看到什么；好的 Harness 通过 Context 卸载、程序化子调用和局部分布内约束，让模型反复处理熟悉的局部结构。

泛化也不必全部发生在神经网络参数中。分解与调度逻辑可以存在于模型外部的程序层，并与模型共同接受训练，使短任务上的学习迁移到长任务，一个领域的学习迁移到另一个领域。
