> 上下文工程系列 第二期

这次我们钻进底层，讲信息容器的物理规律。

上下文窗口不是无限大的口袋，它有硬性上限，还有个“中间容易忘”的毛病。Token 也不是一字一词这么简单，它直接挂钩成本和延迟。窗口开大了，不代表模型变聪明了，很多时候恰恰相反。

三个词说清楚这期内容：

- **上下文窗口**：模型一次能看到的最大 Token 数。容量固定，塞不下就丢。
- **Token**：处理文本的最小单位，不是字，也不是词，是切出来的片段。
- **有效 vs 声称**：说明书写 128K，实际能稳定用的可能只有 64K。窗口越大，管理越重要。

## 上下文窗口

上下文窗口就是模型一次推理能塞进去的全部信息：指令、对话历史、检索文档、工具定义，加上模型自己生成的输出。输入、输出共用一个容量池。

打个比方，人的工作记忆同时只能 hold 住七正二个信息块，LLM 的上下文窗口就是它的工作记忆，超了就丢、忘中间。

公式很简单：

> 输入 + 输出 = 总窗口

但用起来很难。8K 窗口塞 6K 输入，输出只剩 2K。8K 窗口把文档全扔进去，看着窗口够大，其实输出空间被挤压得很惨，生成质量跟着打折。

## 窗口不能无限大的三层约束

### 第一层：位置编码

老方案是绝对位置编码，训练时只见过 2K，推理到 4K 就懵了。

现在主流用 RoPE，靠旋转矩阵编码相对位置，训练 8K 能推理到 128K 甚至更高。ELLIE 更激进，直接在注意力分数上“谁远罚谁”，天然支持任意长度。

### 第二层：KV 缓存

每生成一个新词，都要跟前面所有词的 Key、Value 做点击。缓存下来能省重算，但缓存大小跟上下文长度成正比。

其实 B 模型开 128K 上下文，KV 缓存能吃掉数十 GB 显存。这直接决定你能不能部署，不是理论问题。

### 第三层：注意力计算

每个 Token 要看所有 Token，复杂度是 O(n²)。1K Token 是 100 万次交互，100K 就是 100 亿次。

Flash Attention 之类的优化能缓解，但改不了这个物理规律：长上下文天生就贵。

## Lost in the Middle

长上下文最大的坑是中间会被忘掉。这个现象叫 Lost in the Middle，学术上叫 U 型注意力分布。

你把一篇论文塞进模型，问中间某段数据，模型往往只引用开头、结尾，中间直接跳过。不是没看到，是注意力分配出了问题。

经典测试叫 Needle in a Haystack：把一句关键信息像针一样藏进长文档的不同位置，看模型能不能找到。

结论扎心：多数声称 128K 窗口的模型，过了 64K，检索准确率就开始跳水。声称不等于有效，关键信息放哪，比放了多少更重要。

## Token 是什么

Token 是模型看世界的基本像素。它不是字，也不是词，是分词算法切出来的片段。“上下文工程”五个字可能是 3～8 个 Token，看用的什么分词器。

三种主流算法：

- **BPEGPT 系列**：基于频率合并，高频词保持完整。
- **Word Piece BT 系列**：合并标准是自然增益，用标记表示非词首片段。
- **Sentence Piece**：L L M A A、Mistro 这些开源模型的首选，直接在字符级别操作，中文、日文天然友好。

为什么在意 Token？它直接挂钩三件事：

- **容量**：算错了就超窗口、被截断。
- **成本**：输出 Token 通常比输入贵 2～4 倍。
- **延迟**：推理速度跟 Token 数正相关。

建议用官方分词器精确计数。别拿“一个字算俩 Token”这种经验估算法糊弄，翻车率不低。

## Token 预算管理

Token 预算管理，就是把有限的窗口当钱花。每一项都要有预算，每一笔都要清楚花了多少。

典型分配：

- **系统提示词：5%～15%**。尽量精简，冻结不变。
- **检索知识：30%～50%**。这是核心信息区。
- **对话历史：20%～30%**。简单任务少留，多轮复杂任务多留。
- **输出预留：15%～25%**。别塞太满，把生成空间挤没了。

任务不同，权重也不同：知识密集型加码检索，多轮对话扩充历史，长文本生成加大输出预留。

最关键的是用官方 API 的 Token Counting 取精确值。别拿字符数除以四，这种估算法糊弄代码、JSON、中文、多模态内容。不同 Tokenizer 差异很大，一踩一个坑。

## 总结

六句话说完：

1. 上下文窗口是模型的工作记忆，容量固定，输入、输出共享。
2. 底层压着三层约束：位置编码决定能走多远，KV 缓存决定显存够不够用，注意力决定速度跟不跟得上。
3. 长上下文最大的坑是 Lost in the Middle，中间信息天然弱势，关键内容要放首尾。
4. 窗口大小和有效使用是两回事，多数模型 64K 开外检索就崩了。
5. Token 不只是计数单位，直接挂钩成本、容量、延迟，每个 Token 都在花钱。
6. Token 预算管理就是把窗口容量切好块、算好账，按任务动态调。
