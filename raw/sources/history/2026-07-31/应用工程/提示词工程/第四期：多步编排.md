> 提示工程系列 第四期

## 开篇：单条推理链的隐患

这是提示工程系列的第四期。上一期讲了思维链（CoT），在 prompt 里写出推理步骤，让模型先想再说。但 CoT 有个隐患：推理链只有一条，一旦走偏，整条就报废。

换个陷阱题：我六岁时，妹妹是我年龄的一半，那我 70 岁时妹妹几岁？CoT 大概率答 35，而正确答案是 67。

这期给出两个解法：

- **自我一致性（Self-Consistency）**：同一个 prompt 多问几遍，独立推理后投票选最优。
- **链式提示（Chained Prompting）**：大任务搞不定，就拆成子任务串行执行。

从"想一次"到"多想几次再输出"，从"一把梭"到"分而治之"，这两个方法把提示工程带入了多步编排的阶段。

## 先说结论

今天两个方法，一个解决答案不靠谱，一个解决任务太复杂。

- **自我一致性**：CoT 推理链只有一条，走错整条报废，那就多生成几条独立推理链，哪个答案出现次数最多就选哪个。不改 prompt，只改解码方式。
- **链式提示**：任务太复杂，单个 prompt 搞不定，就把大任务拆成子任务，每步写独立 prompt，前一步输出喂给下一步，多次 LLM 调用串行完成。

两个方法内在逻辑一致：单次靠不住，就上多步。一个是同 prompt 并行多步，一个是不同 prompt 串行多步。

## 四个方法的关系

在展开前，先把上期和这期的四个方法关系捋清楚。

- **最左边是思维链（CoT）**：单个 prompt 内写出推理步骤，是所有多步策略的底座。
- **向右上方是自我一致性**：CoT 改的是 prompt 内容，自我一致性改的是解码方式——同一条 prompt 多次采样、投票出结果，这是解码维度的增强。
- **向下方是链式提示**：把任务拆成多个子任务，前一步输出做后一步输入，这是工作流维度的增强。
- **再往右是思维树（ToT）**：在链式基础上加入分支、评估和回溯。

四个方法的关系可以这样理解：CoT 是地基，自我一致性在解码维度加固，链式提示在工作流维度加长，思维树在搜索维度加宽。不同维度各司其职。

## 第一个方法：自我一致性

### 解决什么问题

先说它解决什么问题。CoT 的默认解码方式是贪婪解码：每生成一个 token，就选当前概率最高的那个。听起来合理，但有个致命缺陷——推理链很长，中间任何一步走错，整条链就废了。这是典型的错误传播问题。

自我一致性的解法很直接：你不是有概率走错吗？那就让你多走几次，哪条路走到正确终点的次数最多就选哪条。

### 具体两步

1. **多次采样**：用同一条 prompt 多次调用模型，每次独立生成一条完整推理路径，从问题出发，经过中间推理到最终答案，互不干扰。
2. **投票统计**：统计 N 条路径的最终答案，票数最多的当选。

这里有个容易被忽略的关键前提：多次采样必须产生不同的推理路径。如果 temperature 为零（贪婪解码），每次一模一样，你只是把同一个答案投了 N 票，毫无意义。

所以 Self-Consistency 强制要求非零 temperature，经验值 0.5 到 0.7 最佳。Temperature 在这里从调优细节变成了方法的生命线。

### 提升的是鲁棒性

Self-Consistency 提升的不是绝对正确率，而是鲁棒性——用多次独立推理，对冲单条链走错的风险。如果单条推理正确率是 70%，那么 13 条独立推理里至少两条对的概率，远高于 70%。

代价也很直观：N 次采样就是 N 倍的 token 消耗和延迟。但它有一个巨大优势：不改 prompt，只改解码。现有的 CoT prompt 不用动，加一个采样循环和投票逻辑就行，工程改造极小。

### 案例：妹妹几岁

这道题值得单独拿出来看，因为它是理解 Self-Consistency 价值的绝佳案例。

题面：叙述者六岁时，妹妹是叙述者年龄的一半，那 70 岁时妹妹几岁？年龄差固定三岁，70 − 3 = 67，不复杂。

但靠贪婪解码为什么答 35？因为它在推理过程中，把"叙述者六岁时妹妹是一半"这句话，错误泛化为了"妹妹永远是叙述者的一半"。这一步走错，7 ÷ 2 = 35，整条链报废。

Self-Consistency 为什么能救回来？非零 temperature 让每次采样都有随机扰动：其中两次走向了"年龄差三岁"的正确思路，一次走向了"一半比例"的错误思路，投票二比一，正确答案胜出。

这个案例揭示了 Self-Consistency 的本质：不是让模型更聪明，而是用冗余计算换取概率。跟安全工程里的三模冗余同一个道理——三个传感器同时测，两个以上一致才采信。

但也点到为止：如果模型的系统性偏见足够强，三条路径全掉进同一个坑，投票也救不了。Self-Consistency 提升的是鲁棒性，不是绝对精度。

## 第二个方法：链式提示

### 解决什么问题

链式提示解决的是另一个维度的问题：任务太复杂，单次 LLM 调用搞不定。

典型案例是长文档问答。假设有篇几万字的文档，用户问了一个需要综合多处信息才能回答的问题，怎么做？

一把梭的做法：把整篇文档和问题全塞进一个 prompt，要求模型一次完成阅读、定位、作答。结果往往不好——信息过载，模型容易遗漏关键信息或者产生幻觉。

### 链式提示的做法

把任务拆成两步：

- **提示一**：从以下文档中提取与问题相关的引文，用引文标签包裹。
- **提示二**：参考以下原始文档和引文，回答用户问题。

提示一的输出直接嵌入提示二的输入。

为什么更好？因为每一步的目标变得单一且明确：提示一只管找相关文字，提示二只管基于引文作答。目标拆分，让每一步都在自己最擅长的窄任务上工作，整体质量自然更高。

### 一个工程细节

这里有个容易被忽略的工程细节：前一步的输出必须结构化，用引文标签、井号、JSON 等格式包裹，确保后一步 prompt 能准确解析格式。不规范，链条在传输层就断了。

### 和 CoT 的区别

CoT 和链式提示的中文名都带"链"字，但机制完全不同：

- CoT 是在单个 prompt 内部写推理步骤。
- 链式提示是在多次 prompt 之间传递中间结果。

一个是让模型在一次回答里学会推理，一个是把大任务拆给多次 LLM 调用协作。记住这个区别就不会混淆。

### 最大价值在工程层面

链式提示最大的价值在工程层面：因为每一步输出都可见，你可以在任何一步定位问题、修改 prompt，甚至替换模型。不像一把梭的 prompt，出了问题根本不知道哪步崩了。这就是透明度和可控性的实际含义。

## 两个方法怎么选

把两个方法放一起对比，选择逻辑就清楚了。

**什么时候用自我一致性？** 任务本质是推理题，答案空间可以枚举：数学题、常识判断、逻辑推理。CoT 能做但不够稳。你不是改 prompt，你是改解码方式——多采样几次，投票出结果。

**什么时候用链式提示？** 任务太复杂，单个 prompt 装不下、模型一次处理不了：长文档问答、多步数据处理、agent 工作流。把大任务拆成子任务，多次 LLM 调用串行完成。

**能不能一起用？** 当然可以。在链式提示的关键步骤上（比如提取引文，这一步要求高准确率），就叠加 Self-Consistency，多采样几次再投票。两者不冲突，反而互补。

## 更上层的框架

回到更上层的框架：

- **CoT 是地基**：让模型在一次回答里学会推理。
- **自我一致性在解码维度加固**：让推理结果更可靠。
- **链式提示在工作流维度扩展**：让复杂任务可以分而治之。
- **思维树在搜索维度丰富**：让推理有分支和回溯能力。

四个方法，四个正交维度各司其职，可以自由叠加。

## 总结

| 方法 | 核心 | 适用场景 | 代价 |
| --- | --- | --- | --- |
| 自我一致性 | 同 prompt 多次采样 + 投票，不改 prompt 只改解码 | CoT 推理链可能走偏时，用多条路径对冲风险、投票纠错；对封闭答案空间的推理题效果显著 | N 倍 token 消耗 |
| 链式提示 | 任务拆分 + 串行执行，大任务变成小任务流水线 | 每步目标明确、可独立调试，带来透明度和可控性；对复杂多步任务不可或缺 | 多次 API 调用的延迟叠加 |

两个方法共同代表了提示工程从"单次对话"到"多步编排"的范式升级：CoT 是底座，自我一致性做解码加固，链式提示做流程扩展。

但大模型能力的边界不止于思考，它还需要记忆和行动。CoT 是在 prompt 里写知识，如果知识量太大，或者需要实时信息呢？下一期的解法是让模型自己生成知识，或者直接接上搜索引擎和外部工具——生成知识提示、RAG、工具调用，从"让 AI 会想"到"让 AI 能查、能算、能动手"。

这期就到这里。下一期我们讲知识增强与工具调用，让大模型长出记忆和手脚。
