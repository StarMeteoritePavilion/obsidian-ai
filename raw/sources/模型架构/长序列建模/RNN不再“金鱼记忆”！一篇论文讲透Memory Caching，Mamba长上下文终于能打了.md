> Memory Caching：为 RNN 增加可增长的记忆

Google Research 的 Memory Caching 工作试图解决一个长期矛盾：RNN 推理高效，却容易在长序列中遗忘早期信息；Transformer 能够查询完整历史，但显存与计算代价很高。Memory Caching 不改造 RNN 内核，而是在外部增加分段检查点和跨段检索，让计算成本与长程召回能力可以通过段长连续调节。

## Transformer 与线性 RNN 的两种困境

Transformer 依靠 Attention，将历史 Token 保存在 KV Cache 中。记忆容量随上下文长度增长，能够查询完整历史；资料同时强调，其显存与计算成本会随序列增长迅速上升，其中 Attention 计算具有平方级代价。

线性 RNN 包括资料列举的 Linear Attention、Mamba 和 Titans 等方法。它们把历史压缩进固定大小的隐状态矩阵，每个新 Token 到来时更新一次，计算量随序列长度线性增长。问题在于，固定容量无法随序列同步扩展：新信息不断写入后，早期信息会被覆盖。在 Needle-in-a-Haystack 这类长程召回任务中，即使答案确实存在于历史位置，模型也可能无法取回。

因此，两类架构分别面临记忆成本和固定容量瓶颈。Memory Caching 的目标是在二者之间建立一条工程上可调的路径。

## 核心机制：为隐状态保存检查点

Memory Caching 将长序列切成若干段，例如每 256 个 Token 一段。每段内部仍由原有 RNN 处理并更新隐状态；一段结束后，系统冻结当时的记忆状态，将其作为检查点放入缓存池。

当前 Token 需要生成输出时，不仅查询当前段的在线记忆，还会查询历史检查点，再聚合各段结果。后续内容即使覆盖在线隐状态，早期信息仍保存在对应检查点中，可以重新检索。

这个最朴素的版本称为 Residual Memory。它为每段保留快照，但如果等权聚合全部检查点，无关段落也会以相同权重混入输出，造成噪声。

## 四种缓存与聚合策略

### Residual Memory：等权聚合

Residual Memory 查询全部历史检查点并直接聚合结果。它解决信息被后续内容覆盖的问题，实现简单，但没有判断各段与当前查询是否相关的能力。

### GRM：按相关性门控

GRM 在查询前计算当前 Token 与每个历史段的相关程度。系统使用当前 Token 的语义向量和各段的平均语义摘要进行相似度评分，再通过 Softmax 得到权重分布：相关段获得较高权重，无关段减少参与或不参与。

这种机制相当于在段级而非 Token 级执行一次粗粒度注意力检索，成本低于完整 Attention。权重又会随当前输入动态变化，因此即使底层记忆模块是线性的，整体系统也不会退化为单一的固定容量记忆。

资料对 GRM 全称存在内部差异：旁白称其为 Gated Residual Memory，画面写作 Gated Recurrent Memory。本文保留缩写 GRM，不在来源之外判定其中一种写法。

### Memory Soup：融合参数后查询

Memory Soup 不对各段输出加权求和，而是对各段记忆模块的参数进行加权插值，生成专属于当前 Token 的新记忆模块，再执行一次查询。

在线性记忆中，这种方法与 GRM 在数学上等价；对于 Titans 一类深度非线性记忆，两者则不同。GRM 相当于分别查询多个记忆后投票，Memory Soup 则先融合多个记忆模块，再用融合结果查询。

### SSC：只激活少量检查点

当历史段达到数百或数千个时，每个 Token 查询全部检查点仍然昂贵。Sparse Selective Caching（SSC）借鉴 Mixture of Experts 的路由方式：先快速评估所有历史段，只激活相关性最高的少数检查点，其余直接跳过。

只要激活数量固定，每个 Token 的实际检索开销就不会随历史段数量同步增长，更适合超长序列推理。

## 为什么均匀分段优于 Log-Linear

资料还比较了使用 Fenwick Tree 组织历史隐状态的 Log-Linear 方法。它把历史构造成对数层级，复杂度为 $O(L\log L)$，从计算角度比 Memory Caching 的等长分段更节省。

但资料转述的实验显示，Log-Linear 在长序列检索任务上反而较差。其早期层级可能让单个记忆模块压缩最长达到总序列一半的历史，信息损失集中。Memory Caching 使用均匀分段，把压缩压力分摊到每一段，使各段都能较充分地学习和保留信息。

## 解耦结构与工程代价

Memory Caching 由分段器、段内 RNN 和跨段聚合器组成，三个子系统彼此解耦：分段策略不限定底层 RNN，RNN 的更新规则不限定聚合方式，聚合器也可以替换。因此，它可以作为插件接入现有 RNN，而不必修改其内部结构。

代价是检查点缓存会随段数线性增长。对于 Titans 一类参数量较大的深度记忆模块，缓存显存尤其需要评估，不能不受限制地增加段数。

## 长程召回与常识推理结果

资料引用论文 Table 2 的 Needle-in-a-Haystack 结果。在资料所称最难的 16K 上下文召回设置中：

- DLA 基线准确率为 4%，加入 GRM 后达到 18.2%，提高约 14 个百分点。
- Titans 基线为 21.2%，加入 GRM 后达到 32.2%。
- Transformer 达到 40.8%，仍高于 Titans + GRM。

这些数字表明，GRM 明显改善了两个 RNN 类基线的长程召回，但没有消除它们与 Transformer 的差距。结果只适用于资料转述的对应实验设置。

在 1.3B 规模的常识推理实验中，资料给出的平均准确率为：Titans + GRM 58.33%，Samba 56.12%，Transformer 53.19%，Titans 基线 51.87%，DLA + GRM 49.25%。在该组实验中，Titans + GRM 比 Transformer 高 5.14 个百分点，也超过了混合 Attention 的 Samba。该结果说明 Memory Caching 在这组任务上提升长程召回的同时没有损害基础语言能力，但不能据此外推到其他模型规模和任务。

## 从线性到平方级的连续旋钮

段长决定检查点数量与每段压缩强度。段切得越细，系统保存的检查点越多，长程召回可能越强，成本也越接近 Transformer；段切得越粗，系统越接近线性 RNN，效率更高，但更多历史会被压入同一状态。资料进一步将 Attention 视为段长为 1 的 Memory Caching 极限情形。

Memory Caching 因此把效率与记忆之间的取舍变成连续可调的工程参数：长程召回要求高且预算充足时缩短段长；更看重效率且任务对长程召回不敏感时增大段长。这种可调性是该工作的主要价值，同时也要求实际部署根据模型、任务和显存重新测量最佳位置。
