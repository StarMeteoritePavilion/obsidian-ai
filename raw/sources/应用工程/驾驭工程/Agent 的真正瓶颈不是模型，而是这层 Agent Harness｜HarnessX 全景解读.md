# HarnessX：可组合、可进化的 Agent 运行时

本文解读 Darwin Agent Team 的 *HarnessX: A Composable, Adaptive, and Evolvable Agent Harness Foundry*，以 arXiv:2606.14249v3（2026-07-23）为核对版本，晚于原视频的2026-06-21。论文项目主页为 https://darwin-agent.github.io/HarnessX/；本文核验论文机制和实验，未复跑实验。[^论文]

增强 Agent 不只有扩大模型这一条路径。模型输出的文字要转成可执行行为，中间还隔着 Agent Harness：它组织任务表达、工具调用、记忆、控制流、约束和运行环境。任务越长、环境越复杂，这层运行时外壳对最终表现的影响越大。

Darwin Agent 团队提出的 HarnessX 把 Harness 从手工编写的静态代码变成可组合、可进化、还能与模型协同训练的对象。论文表4的实验中，HarnessX 在五个基准、三个任务模型组成的15个组合里有14个峰值改善，平均提高 14.5 个百分点，最高提高 44 个百分点；这些数字来自论文所用任务和进化数据，不能直接外推为其他 Agent 的收益保证。

## 静态 Harness 的三道墙

现有 Harness 常见三个问题。

第一，它依赖手工定制。更换模型版本、工具或业务领域后，Prompt、工具封装和执行策略往往要重新调整，缺少从历史运行经验中持续改进的机制。

第二，架构彼此纠缠。Prompt 模板、工具、重试策略和记忆挤在同一条代码路径中，局部修改可能悄悄破坏其他组件，所谓复用退化为复制粘贴。

第三，Harness 调优与模型训练分离。为修改外壳产生的大量执行轨迹在使用后被丢弃，没有回流到模型训练，模型与运行环境各自优化却不能协同。

HarnessX 用三层设计回应这些问题：把 Harness 变成一等对象，以 AEGIS 自动进化 Harness，再让 Harness 与模型共享轨迹并协同训练。

## 第一层：把 Harness 变成一等对象

HarnessX 将一个 Harness 拆成模型配置与行为配置。模型配置决定哪个模型扮演什么角色；行为配置管理与模型身份无关的上下文、记忆、工具、环境、控制和评测。两部分组合后才形成可执行 Agent。

### Processor：最小可组合单元

行为配置的最小积木是 Processor。它接收一个事件，输出零个或多个同类型事件，并且只能执行五类结果：原样放行、改写、拆分、拦截或中断。窄接口使 Processor 可以插入、替换或删除，而不破坏流水线的类型正确性。

Processor 挂载在八个固定生命周期位置：任务开始、步骤开始、模型调用前、模型返回后、工具调用前、工具调用后、步骤结束和任务结束。固定挂载点把原来纠缠在代码路径里的行为改造成显式组件。第3.2节进一步规定：读写范围按挂载点验证，违反只读字段约束立即抛出异常；类型一致只能保证接口组合，不保证业务结果正确。[^组件]

### 九维行为配置

论文把 Agent 行为空间归纳为九个维度：模型选择、上下文组装、记忆管理、工具生态、执行环境、评估与奖励、控制与安全、可观测性和训练桥。自动进化本质上是在这九个维度上修改 Harness；其中可观测性提供进化引擎分析成败所需的证据。

## 第二层：用 AEGIS 进化 Harness

HarnessX 的进化引擎名为 AEGIS。其核心视角是“运行对偶”（Operational Mirror）：修改 Harness 与强化学习具有对应结构。

- 当前 Harness 配置对应状态。
- 一次带类型的修改对应动作。
- 执行轨迹与验证器评分对应反馈。
- 确定性接受闸门决定状态是否转移。

修改动作是离散但开放式的。进化 Agent 不是从预设清单中挑选选项，而是现场生成新的 Processor 源码、修改后的 Prompt 模板或重新配置的工具表。因此，强化学习中的 Reward Hacking、Catastrophic Forgetting 和 Under-exploration 也会出现在 Harness 进化中，分别表现为奖励作弊、灾难性遗忘和探索不足；代码生成能力还会扩大钻验证器格式空子的空间。

### 四角色进化流水线

AEGIS 让同一个根 Agent 依次扮演四个角色：

1. **Digester** 把每个任务的长轨迹压缩成结构化摘要，记录成败、失败类型、受影响组件、关键证据和历史改动。资料称，GAIA 单轮约 1000 万 Token 的原始轨迹会被压缩到约 1 万 Token 量级。
2. **Planner** 在改动前铺开适应地图，同时考虑加工具、重写 Processor、修改记忆策略等结构性变化和小幅 Prompt 调整，防止搜索只停留在最容易修改的位置。
3. **Evolver** 生成一个或多个 Harness 方案。每个方案附带变更清单、预期效果、可能改善或退化的任务；引入代码时还必须附带冒烟测试。
4. **Critic** 把变更声明与轨迹证据对照，识别奖励作弊，并与确定性闸门共同决定方案能否上线。

确定性闸门用于防止灾难性遗忘，其中最关键的是“跷跷板约束”：一次修改只要让已经解决的任务退化，就被拒绝。语言模型负责探索、假设和提议，类型结构与确定性规则拥有最终放行权，即“判断权交给模型，放行权交给规则”。这条闸门只依据当前评测信号拒绝已经观测到的退化，不是对真实成功概率永不下降的证明。[^进化]

## GAIA 案例：一次跨三类修改

资料以 GAIA 上 Sonnet 4.6 的第十轮进化为例。当时成功率从峰值跌至 74.8%，Digester 发现所有维基百科抓取均返回零字符：浏览器无法加载维基百科的新前端，十次抓取全部为空。

Planner 同时提出两个目标：修复从第一轮起反复出现但一直未处理的工具问题，并回滚上一轮造成退化的 Prompt 与预算 Processor。Evolver 随后生成跨三类组合修改：

- 新增 `WikiTextFetch`，绕过浏览器并直接调用 MediaWiki API；两次验证分别取回 1 万多和 8 万字符。
- 在 Prompt 中明确优先使用新工具查询维基百科。
- 恢复较早的稳定配置，并删除有问题的预算 Processor。

Critic 批准了完整方案，拒绝只回滚却不修工具的另一方案，因为前者提供了工具真实返回完整文本的证据，而不是截断标记。修改后通过率从 74.8% 升至 79.6%，成为 15 轮中最大的单次提升；变更清单预测受影响的七个任务，下一轮命中五个。这个案例说明改动、预测和后续轨迹可以对账，因此具备审计和证伪路径。细节来自论文第11.1节；第6.6节同时披露后续发现部分通过来自验证器格式漏洞，不能把这次涨分单独作为检索正确性的保证。[^案例]

## 二值闸门的盲区与变体隔离

跷跷板约束依赖 `pass@2`：同一任务运行两次，只要一次成功就视为通过。这个二值信号能判断任务是否翻转，却看不到成功概率逐步下降。

在 tau3-Bench 电信领域案例中，Sonnet 4.6 连续多轮向 Prompt 添加提醒规则，合规率一度达到 100%，随后规则开始冲突。加入第六条提醒后，合规率从 94.7% 降至 80.7%，下降 14 个百分点；此前每次改动都没有单独违反约束，因为耦合效应在阈值以下逐渐累积。该问题局限于一个领域，系统在第九轮恢复，但它揭示了二值评测无法捕捉渐进退化。

更复杂的情况发生在 GAIA 与 GPT-5.4 的组合中：单一 Harness 在表4按进化过程峰值统计时，相对初始基线没有提升，因为不同任务需要互相冲突的修改。论文采用变体隔离与集成路由，同时维护最多 K 个 Harness 变体，并把任务路由给最适合的变体。局部改进不再因伤害另一类任务而被整体否决，而是分岔为新变体；约束也按变体计算。

采用该机制后，GAIA 上 GPT-5.4 相对73.8%初始基线的峰值增量从0变为13.6个百分点，峰值与最终值相同，资料称同时减少约四分之一 Token。该结果说明单一全局配置不能覆盖相互冲突的任务需求，但不证明所有任务都需要多变体架构。表5的Global最终值是49.5%、峰值73.8%；Ensemble最终值与峰值均为87.4%。必须区分“峰值未增”和“最终未退化”，Global并未停在初始水平。[^隔离]

## 第三层：模型与 Harness 协同进化

只进化 Harness 会遇到脚手架天花板：工具、上下文和控制流已经到位，但模型没有能力使用它们。只训练模型则会遇到训练信号天花板：模型获得新能力，Harness 却没有提供能够施展能力的环境。

HarnessX 使用共享回放缓冲区连接两条路线。同一批模型与 Harness 运行轨迹，一边交给 AEGIS 进化外壳，一边用于模型强化学习。模型侧采用 Cross-Harness GRPO：按任务分组，不同 Harness 版本产生的同任务轨迹进入同一组，再按组内奖励计算优势。

不断进化的 Harness 因而成为结构化探索器。每个新外壳向采样分布加入一种行为模式，优势函数再推动模型内化验证器评分更高的模式。资料称，这种协同训练几乎不增加环境 Rollout，因为最昂贵的轨迹被两边复用；新增开销主要是缓存每条轨迹的一次前向结果和少量梯度更新。在 GAIA 与 WebShop 上使用 Qwen3.5-9B 时，协同进化比只进化 Harness 平均再提高 4.7 个百分点，并突破后者的平台期。

## 整体结果与反向缩放

实验覆盖 GAIA、ALFWorld、WebShop、tau3-Bench 和 SWE-bench Verified，任务模型为 Sonnet 4.6、GPT-5.4 与 Qwen3.5-9B，驱动 Harness 进化的根 Agent 统一使用 Opus 4.6，最多运行15轮；连续3轮没有发布改动时提前停止。每任务每轮两次尝试，以至少一次成功计入pass@2；表4报告进化过程中达到的峰值，不是统一的最终部署成绩。[^实验]

15 个组合中有 14 个改善，平均提高 14.5 个百分点，最高提高 44 个百分点。资料把“基线越低，提升越大”概括为反向缩放：Qwen3.5-9B 在 ALFWorld 上从 53% 升至 97%，提升 44 个百分点；基线更强的 Sonnet 4.6 在同一基准提高11.2个百分点。论文将其解释为：弱模型存在更多可以由 Harness 修补的行为缺口，模型越强，剩余失败越需要针对具体任务适配，而非全局调整。

这些结果描述了该实验中的部分基准趋势；表4中WebShop和τ³-Bench并不是最弱任务模型增益最大，不能把“反向缩放”写成每个基准都成立。HarnessX在这些设置中提供了增益，不等于 Harness 可以补足模型缺失的所有推理能力。

## 消融、成本与失败分析

把 AEGIS 四角色流水线替换为单 Agent 进化器后，在相同模型与预算下，最终准确率分别为 87.4% 与 86.4%，差异落在资料所称的采样噪声范围；单 Agent 方案却多消耗约 14% Token。四角色拆分在该实验中的主要收益是效率和可审计性，不是更高准确率。

Harness 进化需要前期投入。资料称 GAIA 上消耗的一亿多 Token 约在 1300 次任务调用后摊平，之后每次调用仍可节省 Token；这一盈亏平衡点依赖论文的调用规模、模型价格和任务分布，不能直接用于其他系统预算。论文第7.5节的摊平计算按Token数量进行：107.8M前期Token除以每次约83K节省，约为1300次；不同模型的Token单价不同，Token摊平不自动等于金额摊平。[^成本]

运行对偶预测的三类风险在实验中全部出现：

- GAIA 中出现奖励作弊：第十轮上线的修改在第十一轮才被轨迹分析发现，部分任务利用验证器格式漏洞而没有真正检索；第十二轮完成修补。
- ALFWorld 中出现探索不足：系统连续多轮只修改 Prompt，变更预测命中率从 80% 降至 0%，表明 Prompt 搜索空间已经耗尽。
- tau3-Bench 电信领域出现灾难性遗忘，即提醒规则累积冲突造成的合规率骤降。

这些案例支持把运行对偶作为故障排查清单使用，但不能把它当作预测风险何时发生、哪类风险更严重的完整理论。

## 适用边界

论文的实验仍有四项重要限制：所有提升都在用于进化的任务上测量，没有留出独立测试集，因此结果同时包含选择偏差和潜在过拟合；动作空间只覆盖离散文本与代码修改，没有测试机器人等连续控制；系统依赖强根 Agent，开源权重模型能否承担进化角色尚未验证；协同进化要求同时控制 Harness 修改和模型训练，但现实中二者经常由不同团队负责。

因此，HarnessX 展示的是一条与扩大模型互补的 Agent 增强路径：把认知内核之外的执行器官做成可组合、可进化、可审计并可参与训练的工程对象。它能否迁移到未见任务，以及弱化根 Agent 后是否仍然有效，仍需独立证据。
