# 第七期：从事后评估到生产护栏，差的是挡住还是知道？

评估帮助团队发现系统已经发生的错误；在线护栏决定某个请求、输出或工具动作能否继续。两者可以共享检测器，但进入请求关键路径后，还必须处理误报、延迟、超时和服务可用性。下文是基于原资料整理的工程设计建议，指标算例为明确假设下的计算，不是行业统一门槛。[^原文]

## 离线评估与在线护栏

离线评估可以在结果产生后汇总问题，适合比较版本、分析失败类型和调整数据。输入护栏位于模型调用前，检查请求范围、敏感输入与滥用；输出护栏位于内容交付前，检查隐私、内容规则和业务约束。两道关口不能互相替代：合规输入仍可能产生不合格输出。

把检测器移入在线流程时，要同时测量准确性、误报、漏报、延迟和故障行为。不能把离线总体准确率直接作为上线许可，也不能用一个固定毫秒预算覆盖不同硬件、模型和业务。

## 五个组件与责任边界

| 组件 | 职责 | 必须验证的行为 |
| --- | --- | --- |
| 检测器 | 规则、分类器或语言模型输出风险信号 | 对不同风险和合法业务分别测量漏报、误报；不假设更大模型必然更准 |
| 阈值 | 将分数转换为放行、复核或拦截 | 用业务成本和留出数据校准，不把分数直接当作已校准概率 |
| 动作 | 放行、替换、拦截或人工复核 | 响应与风险相称；轻微语气问题不必与隐私泄漏采用同一动作 |
| 回退 | 检测器超时、异常时按预设策略处理 | 关键权限检查失败时不执行受保护动作；辅助格式检查可采用降级输出 |
| 反馈 | 汇总申诉、人工覆盖和真实错误 | 保护隐私，区分误报与真实违规，按版本回归测试 |

规则、机器学习分类器和小语言模型可以组成分层检测流程。应按目标任务实测成本与效果，决定哪些请求需要升级到下一层，而不是默认每次串行调用所有检测器。

## 用成本矩阵校准阈值

本节把**违规请求定义为阳性**。真阳性率衡量违规请求被识别的比例；误报率衡量合法请求被误拦的比例，真负率则是合法请求被正确放行的比例。

提高拦截阈值通常会改变误报与漏报的取舍。用留出集绘制 ROC 或 PR 曲线，并结合业务成本矩阵：合法请求被拒绝的损失、违规请求放行的损失、人工复核成本以及延迟成本。违规率变化也会影响拦截结果中真正违规的占比，所以离线阈值仍需在真实分布下验证。

不要只优化总体准确率。若合法请求占绝大多数，一个几乎全部放行的检测器也可能有很高的总体准确率，却没有有效风险识别能力。

## 串联护栏的误报级联

设 $L$ 表示合法请求，$A_i$ 表示第 $i$ 层放行。串联时必须所有层都放行，整体合法通过率为：

$$
P(A_1\cap\cdots\cap A_5\mid L)
=P(A_1\mid L)\prod_{i=2}^{5}P(A_i\mid L,A_1,\ldots,A_{i-1}).
$$

这个条件概率连乘式不要求各层独立。只有在各层对合法请求的放行事件相互独立时，才能直接相乘它们各自单独测得的真负率。

作为教学算例，假设五层独立、每层合法放行率都为90%，则整体合法放行率为 $0.9^5=59.049\%$，整体误报率为40.951%。若每天10万次请求**全部合法**，期望误拦约40951次；若合法请求占比为 $q$，期望误拦为 $100000q\times0.40951$。不能把全部请求数直接充当合法请求分母。

在同样的五层独立同质假设下，每层99.5%的合法放行率意味着整体误报率：

$$1-0.995^5\approx2.4751\%.$$

因此它不满足“整体误报率低于2%”这个假设的业务目标。要达到该目标，每层合法放行率 $t$ 应满足：

$$1-t^5<0.02\quad\Longrightarrow\quad t>0.98^{1/5}\approx99.5968\%.$$

若采用并联策略，必须先明确合并规则。任何一层报警就拦截，与上述“所有层放行”逻辑等价；只有全部层报警才拦截，在独立同质假设下整体误报率是单层误报率的五次方，但也会改变漏报风险。多数投票又是另一种规则。实际检测器共享训练数据和风险特征，各层高度相关时，不能直接使用这些独立算例；应测量条件通过率和完整链路的误报、漏报。

## 从影子模式到渐进上线

影子模式让检测器观察真实流量并记录判断，但不改变用户结果。它用于确认实际负载下的延迟、分数分布、误报案例及离线集遗漏的边界。运行多久应由样本覆盖和风险决定，不存在统一的一个月要求。

原资料的六个月路线可以用作示例计划：先搭建评估与人工复核流程，再收集基线、调优检测器、筛选进入关键路径的检查、运行影子模式，最后逐步启用。这里的顺序表达依赖关系，月份并非最低行业周期。进入下一阶段的条件应是可验证的指标和回退能力，而不是日历已经翻页。

首次启用时，限定业务范围和流量，记录规则版本，持续观察误报与申诉；出现异常时能够回退到上一版本。不能把“先拦最高置信度的1%”写成所有业务通用的比例。

## Agent 的动作级控制

文本输出过滤不能代替工具权限。删除数据、修改配置和外发信息都会改变外部状态，应在操作发生前由执行层检查资源范围、身份权限和必要确认。自然语言中的“不要删除”不等于数据库权限已经收紧。

对可重试动作，定义幂等标识或重复执行的安全语义，避免超时后重试导致重复扣款或重复发送。对可撤销操作，明确保存状态、回滚入口和成功检查；对不能回滚的外发或删除，先验证权限和授权，再执行，不能把“出了问题再回滚”当作保障。独立审查应检查实际状态变化及日志，不能只采信 Agent 自述。
