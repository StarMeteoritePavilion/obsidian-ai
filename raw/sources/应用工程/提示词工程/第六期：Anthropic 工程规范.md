> 提示工程系列 第六期（完结篇）

## 开篇：从"能用"到"可迁移"

这是提示工程系列的最后一期。前五期介绍了如何通过零样本、少样本、CoT、自我一致性、知识增强和工具调用向大模型表达任务。

同一 Prompt 可能在一个模型上表现稳定，更换模型后却偏离预期。提示工程不只是文字技巧，还需要形成能够进入生产环境的工程规范。

本期从六个模块说明如何使 Prompt 具备可验证、可复用和可迁移的特征。

## 六个核心模块

六个模块的作用如下：

- **XML 标签**：对指令、文档和示例进行分层，使模型明确区分内容类型。
- **system prompt**：独立于对话的全局设定，负责角色和底线，避免每次重复长上下文。
- **长上下文技巧**：长文档放上面，问题放最下面。
- **adaptive 思考**：无需手动设置思考预算，由模型自行决定推理量。
- **防幻觉**：先读取并核实引用内容，不推测未读取的信息。
- **输出控制**：明确要求采用的格式，而非只说明禁止采用的格式。

## 六个模块是一条流水线

这六个模块不是孤立的，而是一条流水线：

- **XML 标签是基础设施**：其他模块都要建立在结构化 prompt 之上才能稳定生效。
- **system prompt 是全局常量层**。
- **长上下文是排序策略**。
- **adaptive 思考控制推理行为**。
- **防幻觉和输出控制是质量底线**。

与第五期的生成知识、编程推理和工具调用相比，本期关注如何稳定编写同一组 Prompt、迁移到不同模型，并支持团队成员复用。

## 第一模块：XML 标签

XML 标签是最基础的工程化设施。

当一段自然语言同时包含指令、上下文、示例和输入数据时，模型容易混淆不同内容类型，例如把上下文当作指令、把示例当作输入。

解决方法是使用 XML 标签包裹各类内容：

- `<instructions>` 包指令
- `<documents>` 包文档
- `<example>` 包示例

标签还可以像 HTML 一样嵌套。模型通过标签识别内容的层级与类型，无需自行判断。Anthropic 的模型专门针对 XML 标签进行过训练，因此效果最优。

一项**金标准测试**是把 Prompt 交给不了解任务的同事，检查对方能否直接执行。使人产生困惑的内容通常也会使模型产生困惑。

## 第二模块：system prompt 和输出控制

### system prompt：prompt 工程里的常量层

system prompt 是无需在每次对话中重复的内容，也是独立于用户消息的 API 参数，用于设定角色、语气、底线和规则。它不随用户问题变化，是 Prompt 工程化的第一道门槛。

### 输出控制：正向指令优于负向禁止

输出控制有个反直觉的规律：**正向指令永远优于负向禁止**。

- "不要用 markdown" → 改成"用流畅的自然段落回答"
- "不要加列表" → 改成"以连贯叙述形式呈现"

正向指令的效果通常更好，因为否定形式对模型而言更模糊，“不要 X”无法精确说明“应该做什么”。

一条迁移提示：Claude 4.6 起，预填响应（prefill）已弃用，必须改用正向指令来控制输出。

## 第三模块：长上下文技巧

把一份 20k Token 的文档完整放入上下文后，模型处理后部内容时可能忽略前文。这是长上下文里的注意力分布问题。

两条关键经验：

1. **长内容置顶，问题放最下面**。Anthropic 实测，这样排序响应质量最多提升 30%，因为模型对 prompt 末尾内容的关注度最高。
2. **先引后答**：让模型先摘出文档中的相关片段，再基于引文回答。这相当于执行噪声过滤：20k Token 中可能只有 500 字与问题相关，先定位再回答可以直接提高准确度。

## 第四、第五模块：adaptive 思考与防幻觉

这两个模块的共同点是让模型自行管理推理和核实策略。

### adaptive 思考

过去需要手动设置 `budget_tokens`，规定模型的推理预算。Token 过少可能不足以完成推理，过多则会造成浪费。

现在用 adaptive thinking，模型根据问题复杂度自己决定何时该想、想多久。内部评估显示这样更可靠。

注意一条硬迁移：新版本模型上，手动设预算会直接报错，必须迁移。

### 防幻觉

防幻觉可以通过一条明确约束实现：不得猜测未读取的代码，引用具体文件前必须先打开查看。

这不是对幻觉机制的解释，而是一条有效的行为约束：在 Prompt 中明确要求模型不得编造未读取的信息。

## 六期全系列复盘

六期内容可以归纳如下：

- **第一期**：入门，零样本基础。
- **第二期**：少样本，给例子学新任务。
- **第三期**：推理范式，CoT 和自我一致性。
- **第四期**：多步策略，投票纠错和链式拆解。
- **第五期**：知识增强和工具调用，使模型能够检索、计算和执行操作。
- **第六期**：工程化部署，把上述方法应用到生产环境。

最核心的判断标准是：把 Prompt 交给同事后，对方能够在没有困惑的情况下照做。

其次，XML 标签分层是基础设施，system prompt、长上下文排序、防幻觉和输出控制都建立在此之上。

## 六项要点

- **XML 标签**：区分内容层级，是基础设施。
- **system prompt**：设角色和底线，是常量层。
- **长上下文**：内容置顶、先引后答，是质量放大器。
- **adaptive 思考**：无需手动设置预算。
- **防幻觉**：不得猜测未读取的文件内容。
- **输出控制**：正向指令永远优于负向禁止。
