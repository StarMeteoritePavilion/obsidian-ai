> 提示工程系列 第六期（完结篇）

## 开篇：从"能用"到"可迁移"

这是提示工程系列的最后一期。前面五期讲了怎么跟大模型说话：零样本、少样本、CoT、自我一致性、知识增强、工具调用。

但你有没有遇到过这种情况：prompt 在一个模型上表现完美，换个模型就跑偏？提示工程不只是写几句话的技巧，它是一套能从实验台搬上生产线的工程规范。

这期拆六个模块，让你的 prompt 从"这次灵、下次不灵"变成可验证、可复用、可迁移。

## 先说结论：六个模块

一句话说清楚这六个模块：

- **XML 标签**：把指令、文档、示例分层打包，模型一眼就能分清楚。
- **system prompt**：独立于对话的全局设定，负责角色和底线，不用每次重复长上下文。
- **长上下文技巧**：长文档放上面，问题放最下面。
- **adaptive 思考**：别再手动设思考预算，让模型自己决定想多少。
- **防幻觉**：先查再说，没读过的东西别瞎猜。
- **输出控制**：说要什么格式，别说不要什么格式。

## 六个模块是一条流水线

这六个模块不是孤立的，而是一条流水线：

- **XML 标签是基础设施**：其他模块都要建立在结构化 prompt 之上才能稳定生效。
- **system prompt 是全局常量层**。
- **长上下文是排序策略**。
- **adaptive 思考控制推理行为**。
- **防幻觉和输出控制是质量底线**。

和第五期那三条路（生成知识、编程推理、工具调用）相比，这期讲的是同一批 prompt 怎么写得稳、怎么迁移到不同模型、怎么让同事接手就能用。

## 第一模块：XML 标签

这是最基础的工程化基建。

一段自然语言里混着指令、上下文、示例、输入数据，模型经常搞混：把上下文当指令，把示例当输入。

解法是用 XML 标签把每类内容包起来：

- `<instructions>` 包指令
- `<documents>` 包文档
- `<example>` 包示例

标签还能嵌套，这跟 HTML 一个思路。模型看到标签就知道内容的层级和类型，不需要猜。Anthropic 的模型专门针对 XML 标签做过训练，效果最优。

这里有个**金标准测试**：把 prompt 给一个不了解任务的同事，他能照做吗？他困惑的地方，模型也困惑。

## 第二模块：system prompt 和输出控制

### system prompt：prompt 工程里的常量层

system prompt 是每次对话不用重复说的部分，是独立于用户消息的 API 参数，用来做全局设定：角色、语气、底线、规则。这一条不随用户问题变化，是 prompt 工程化的第一道门槛。

### 输出控制：正向指令优于负向禁止

输出控制有个反直觉的规律：**正向指令永远优于负向禁止**。

- "不要用 markdown" → 改成"用流畅的自然段落回答"
- "不要加列表" → 改成"以连贯叙述形式呈现"

效果好得多。因为否定形式在模型理解里更模糊，"不要 X"没法精确对应到"该做什么"。

一条迁移提示：Claude 4.6 起，预填响应（prefill）已弃用，必须改用正向指令来控制输出。

## 第三模块：长上下文技巧

把一份 20k token 的文档扔进去，模型读到后面可能忘了前面。这是长上下文里的注意力分布问题。

两条关键经验：

1. **长内容置顶，问题放最下面**。Anthropic 实测，这样排序响应质量最多提升 30%，因为模型对 prompt 末尾内容的关注度最高。
2. **先引后答**：让模型先摘出文档里的相关片段，再基于引文回答。这等于帮模型做了噪声过滤——20k token 里可能只有 500 字有用，先定位再回答，准确度直接拉升。

## 第四、第五模块：adaptive 思考与防幻觉

这两个模块的共同点是：让模型管好自己的策略。

### adaptive 思考

过去要手动设 `budget_tokens`，规定模型能想多少。token 不够就凑，多了就浪费。

现在用 adaptive thinking，模型根据问题复杂度自己决定何时该想、想多久。内部评估显示这样更可靠。

注意一条硬迁移：新版本模型上，手动设预算会直接报错，必须迁移。

### 防幻觉

防幻觉更简单，加一句就行：没读过的代码别猜，引用了具体文件就必须先打开看。

这不涉及幻觉的技术原理，就是一条极其有效的行为约束——把"模型不乱编"变成 prompt 里的硬规则。

## 六期全系列复盘

六期全讲完了，拉通复盘一下：

- **第一期**：入门，零样本基础。
- **第二期**：少样本，给例子学新任务。
- **第三期**：推理范式，CoT 和自我一致性。
- **第四期**：多步策略，投票纠错和链式拆解。
- **第五期**：知识增强和工具调用，让模型能查、能算、能动手。
- **第六期**：工程化部署，把这一切搬上生产线。

如果只带走一件事：把 prompt 给同事看，他照做不困惑，就合格了。

如果多带一件：XML 标签分层是第一基建，在此之上再搭 system prompt、长上下文排序、防幻觉、输出控制。

## 六句话收尾

- **XML 标签**：分清层级，是基建。
- **system prompt**：设角色和底线，是常量层。
- **长上下文**：内容置顶、先引后答，是质量放大器。
- **adaptive 思考**：别手动设预算。
- **防幻觉**：没读过的文件别猜。
- **输出控制**：正向指令永远优于负向禁止。
