> 提示工程系列 第四期

## 开篇：单条推理链的隐患

这是提示工程系列的第四期。上一期介绍了思维链（CoT），即在 Prompt 中写出推理步骤，使模型先推理再回答。但 CoT 存在一个隐患：推理链只有一条，一旦路径偏离，后续结果便会受到影响。

以一道陷阱题为例：“我六岁时，妹妹是我年龄的一半，那么我 70 岁时妹妹几岁？”CoT 很可能回答 35，而正确答案是 67。

本期介绍两种解决方法：

- **自我一致性（Self-Consistency）**：同一个 prompt 多问几遍，独立推理后投票选最优。
- **链式提示（Chained Prompting）**：将复杂任务拆分为子任务并串行执行。

这两个方法分别通过多次独立推理和任务拆分，把提示工程带入多步编排阶段。

## 核心结论

两种方法分别解决推理结果不稳定和任务过于复杂的问题。

- **自我一致性**：针对 CoT 单条推理链容易受中间错误影响的问题，生成多条独立推理链，并选择出现次数最多的答案。该方法不修改 Prompt，只调整解码方式。
- **链式提示**：当任务超出单个 Prompt 的处理能力时，将大任务拆成子任务，为每一步编写独立 Prompt，并把前一步输出传递给下一步，通过多次 LLM 调用串行完成。

两种方法的内在逻辑一致：当单次处理不够可靠时，改用多步处理。前者让同一 Prompt 并行执行多次，后者让不同 Prompt 串行执行。

## 四个方法的关系

上一期与本期四种方法的关系如下：

- **最左边是思维链（CoT）**：单个 prompt 内写出推理步骤，是所有多步策略的底座。
- **向右上方是自我一致性**：CoT 改的是 prompt 内容，自我一致性改的是解码方式——同一条 prompt 多次采样、投票出结果，这是解码维度的增强。
- **向下方是链式提示**：把任务拆成多个子任务，前一步输出做后一步输入，这是工作流维度的增强。
- **再往右是思维树（ToT）**：在链式基础上加入分支、评估和回溯。

CoT 是基础，自我一致性在解码维度加固，链式提示在工作流维度延伸，思维树在搜索维度扩展。四种方法分别作用于不同维度。

## 第一个方法：自我一致性

### 解决什么问题

CoT 的默认解码方式是贪婪解码：每生成一个 Token，便选择当前概率最高的结果。这种方式存在一个明显缺陷：推理链较长时，中间任何一步出错都可能影响整条推理链，形成典型的错误传播问题。

自我一致性的解决方法是让模型独立推理多次，并选择到达同一终点次数最多的路径。

### 具体两步

1. **多次采样**：用同一条 prompt 多次调用模型，每次独立生成一条完整推理路径，从问题出发，经过中间推理到最终答案，互不干扰。
2. **投票统计**：统计 N 条路径的最终答案，票数最多的当选。

这里存在一个容易被忽略的关键前提：多次采样必须产生不同的推理路径。如果 temperature 为零，即采用贪婪解码，每次结果都相同，只相当于给同一答案重复投票，无法发挥作用。

因此，Self-Consistency 要求 temperature 非零，经验最佳值为 0.5～0.7。Temperature 在这里不再只是调优细节，而是方法生效的必要条件。

### 提升的是鲁棒性

Self-Consistency 提升的不是绝对正确率，而是鲁棒性——用多次独立推理，对冲单条链走错的风险。如果单条推理正确率是 70%，那么 13 条独立推理里至少两条对的概率，远高于 70%。

代价同样明确：N 次采样会带来 N 倍的 Token 消耗和延迟。但该方法无需修改 Prompt，只需在现有 CoT Prompt 外增加采样循环和投票逻辑，工程改造较小。

### 案例：妹妹几岁

这道题能够清晰体现 Self-Consistency 的价值。

题目是：叙述者六岁时，妹妹是叙述者年龄的一半，那么 70 岁时妹妹几岁？年龄差固定为三岁，因此 70 − 3 = 67。

贪婪解码之所以回答 35，是因为它在推理过程中把“叙述者六岁时妹妹是一半”错误泛化为“妹妹永远是叙述者的一半”。这一步发生错误后，后续以 7 ÷ 2 = 35 计算，整条推理链随之失效。

Self-Consistency 能够纠正这一结果，是因为非零 temperature 使每次采样包含随机扰动：其中两次采用“年龄差三岁”的正确思路，一次采用“一半比例”的错误思路，最终以二比一的投票结果选出正确答案。

这个案例揭示了 Self-Consistency 的本质：它并未提高模型自身能力，而是通过冗余计算提高正确结果获胜的概率。其原理类似安全工程中的三模冗余，即三个传感器同时测量，至少两个结果一致时才采信。

但该方法也有明确边界：如果模型存在较强的系统性偏见，三条路径都采用同一种错误思路，投票仍无法纠正结果。Self-Consistency 提升的是鲁棒性，而非绝对精度。

## 第二个方法：链式提示

### 解决什么问题

链式提示解决任务复杂度超过单次 LLM 调用处理能力的问题。

长文档问答是典型案例。假设一篇数万字的文档包含多处分散信息，而用户问题需要综合这些信息才能回答。

单次调用的做法是把整篇文档与问题全部放入一个 Prompt，要求模型同时完成阅读、定位和作答。这容易造成信息过载，使模型遗漏关键信息或产生幻觉。

### 链式提示的做法

把任务拆成两步：

- **提示一**：从以下文档中提取与问题相关的引文，用引文标签包裹。
- **提示二**：参考以下原始文档和引文，回答用户问题。

提示一的输出直接嵌入提示二的输入。

这种方式把每一步的目标变得单一且明确：提示一只负责查找相关文字，提示二只负责基于引文作答。任务拆分使每一步都聚焦于更窄的目标，从而提高整体质量。

### 一个工程细节

一个容易被忽略的工程细节是，前一步的输出必须结构化，可以使用引文标签、井号或 JSON 等格式包裹，确保后一步 Prompt 能够准确解析。输出格式不规范会使链条在传输层失效。

### 和 CoT 的区别

CoT 和链式提示的中文名都带"链"字，但机制完全不同：

- CoT 是在单个 prompt 内部写推理步骤。
- 链式提示是在多次 prompt 之间传递中间结果。

前者使模型在一次回答中完成推理，后者则把大型任务拆分给多次 LLM 调用协作完成。

### 最大价值在工程层面

链式提示最大的价值体现在工程层面：每一步输出都可见，因此可以在任何阶段定位问题、修改 Prompt，甚至替换模型。相比单次完成全部任务的 Prompt，这种结构更容易确定发生问题的步骤，具备更高的透明度和可控性。

## 两种方法的选择

把两个方法放一起对比，选择逻辑就清楚了。

**适合使用自我一致性的情况**：任务本质上是答案空间可以枚举的推理题，例如数学题、常识判断和逻辑推理。CoT 能够处理但结果不够稳定时，可以保持 Prompt 不变，通过多次采样和投票调整解码方式。

**适合使用链式提示的情况**：任务过于复杂，单个 Prompt 无法容纳或模型无法一次处理，例如长文档问答、多步数据处理和 Agent 工作流。此时可以把大型任务拆成子任务，通过多次 LLM 调用串行完成。

**组合使用**：可以在链式提示的关键步骤上叠加 Self-Consistency。例如，提取引文要求较高准确率时，可以多次采样后投票。两种方法并不冲突，而是相互补充。

## 更上层的框架

从更上层的框架来看：

- **CoT 是地基**：让模型在一次回答里学会推理。
- **自我一致性在解码维度加固**：让推理结果更可靠。
- **链式提示在工作流维度扩展**：让复杂任务可以分而治之。
- **思维树在搜索维度丰富**：让推理有分支和回溯能力。

四种方法分别作用于四个正交维度，可以按需组合。

## 总结

| 方法 | 核心 | 适用场景 | 代价 |
| --- | --- | --- | --- |
| 自我一致性 | 同 prompt 多次采样 + 投票，不改 prompt 只改解码 | CoT 推理链可能走偏时，用多条路径对冲风险、投票纠错；对封闭答案空间的推理题效果显著 | N 倍 token 消耗 |
| 链式提示 | 任务拆分 + 串行执行，大任务变成小任务流水线 | 每步目标明确、可独立调试，带来透明度和可控性；对复杂多步任务不可或缺 | 多次 API 调用的延迟叠加 |

两种方法共同代表提示工程从“单次对话”到“多步编排”的范式升级：CoT 构成基础，自我一致性加固解码过程，链式提示扩展执行流程。

但大模型的能力边界不止于推理，还涉及记忆和行动。CoT 在 Prompt 中写入知识，但知识量过大或需要实时信息时，这种方式并不足够。下一期将介绍生成知识提示、RAG 和工具调用，使模型自行生成知识或接入搜索引擎与外部工具，从“让 AI 会想”扩展到“让 AI 能查、能算、能动手”。

下一期将介绍知识增强与工具调用，进一步扩展大模型获取知识和执行操作的能力。
