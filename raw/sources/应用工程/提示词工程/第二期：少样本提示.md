> 提示词工程系列 第二期

这是提示工程系列的第二期。上一期介绍了仅依靠指令完成任务的零样本提示；本期进一步讨论少样本提示，即在 Prompt 中加入少量示例，使模型在不更新参数的情况下临时适应新任务。

以英译中为例，可以在 Prompt 中提供两组英文与中文示例，再加入新的英文句子，模型便会沿用示例结构输出译文。零样本依赖文字指令，少样本则通过示例展示任务模式。

## 什么是少样本提示

**少样本提示是在 Prompt 中提供少量输入输出示例，使模型按照示例模式完成新输入。**

关键在于不修改模型权重，这与微调完全不同。模型参数保持不变，只在 Prompt 中加入若干示例，模型便能识别任务模式。

这种能力称为上下文学习（in-context learning）。模型把 Prompt 中的示例作为条件，临时理解任务并生成答案。零样本通过指令说明任务，少样本通过演示示例（demonstration）呈现任务模式。

## 全景图：少样本在提示方法体系里的位置

少样本在提示方法体系中的位置如下：

- **左侧是零样本**：只提供指令，由模型直接完成任务。
- **中间是少样本**：提供若干示例，使模型沿用示例模式。
- **右侧是思维链**：除示例外还提供推理过程，使模型沿用相应推理方式。

三者形成递进关系：零样本结构最简单，但难以处理复杂任务；少样本通过示例扩大适用范围；思维链进一步加入推理过程，用于处理更复杂的推理任务。

少样本下面有两个核心概念：

- **左侧是上下文学习**：不更新任何参数，仅通过演示学习任务模式。
- **右侧是涌现能力**：模型规模不足时，增加示例也难以产生预期效果。

这两个概念构成了理解少样本提示的基础。

## 少样本提示长什么样

少样本提示先在 Prompt 中放入若干输入输出示例，再提供待处理的新问题，模型依据示例结构生成答案。

以翻译任务为例，**零样本翻译**的 Prompt 如下：

```
把下面这句话翻译成英文。
你好
```

模型可以执行翻译，但需要自行判断具体要求。

**少样本翻译**则采用以下写法：

```
英文：Hello
中文：你好
英文：Goodbye
中文：再见
英文：Thank you
中文：
```

模型根据前两组示例识别出英译中任务，并在第三行填入“谢谢”。

少样本提示的核心在于：演示是模型生成响应的条件。Brown 等人在 2020 年的 GPT-3 论文中奠定了这一概念，即 Prompt 中的示例分布会直接影响模型的输出行为。

演示数量没有固定标准：简单的任务一个例子（one-shot）就够；困难的任务，三个、五个甚至更多，但受限于上下文窗口长度，也不能无限多。Anthropic 的工程经验是 3~5 个示例最佳。

示例格式并不固定，而应与任务匹配：翻译任务展示原文和译文，分类任务展示文本和标签，代码生成任务展示需求和代码。这种灵活性是少样本提示的优势。

## 上下文学习：不更新参数也能适应任务

少样本提示的特殊之处在于，模型无需更新参数也能临时适应任务。这种现象称为上下文学习（in-context learning），可以通过与微调对比来理解。

**微调**使用成千上万条标注数据，通过反向传播更新模型内部参数，将新任务写入神经网络权重，因此需要 GPU 时间和大量数据。

**上下文学习**只需在 Prompt 中写入若干示例，模型在推理时识别任务模式，参数保持不变。Prompt 结束后，这种临时状态随之消失，且能够即时生效。

### 标签正确性不重要

Min 等人在 2022 年进一步发现：标签本身是否正确并非最重要的因素。

他们在实验中把情感分类示例的正确标签替换为随机标签，例如把“这部电影很棒”标为负面，把“烂透了”标为正面，模型依然能够正确分类新的文本。

原因在于，模型学习的是“这是一项三选一分类任务”，而不是判断具体标签是否正确。标签空间和格式比标签正确性更重要。

上下文学习的关键在于：模型并非记忆答案，而是在临时识别任务结构。

这种方法也有明确上限。对于需要多步推理的任务，仅提供输入输出示例并不足够：模型只能看到问题与答案的表面映射，无法观察中间推理过程，因此还需要引入思维链。

## 涌现能力：这是大模型的特权

上下文学习还有一个关键特征：它是一个涌现能力。

涌现能力是指某种能力在小模型上并不明显，但当模型规模跨过特定阈值后出现显著跃迁。

Wei 等人（2023）和 Kaplan 等人（2020）的研究表明：参数规模在 10 亿以下的模型即使在 Prompt 中加入更多示例，表现也几乎没有提升；当模型规模跨过 100 亿参数的门槛后，提供 3～5 个示例会使性能显著提升。

这个发现跟上一期讲的"指令微调加 RLHF"是相互呼应的：零样本能力需要指令微调做底座，少样本的涌现同样依赖于足够大的模型规模。模型规模不足时，仅调整 Prompt 难以产生相同效果。这是提示工程方法的重要适用前提。

实践含义很明确：

- 对于 GPT-4、Claude 这一量级的模型，少样本提示是一种有效方法。
- 对于小模型，仅增加若干示例难以弥补能力差距，仍需考虑微调。

## 演示示例的选择方法

在实际应用中，演示示例的选择可以遵循学界的三项原则和工程界的三项补充建议。

### 学界三条铁律

1. **标签空间和输入分布最重要**：首先确定任务包含多少个输出标签，再让演示覆盖典型输入类型。例如，情感分类的标签空间包括正面、负面和中性，演示应确保每个标签都有对应示例。
2. **格式一定要一致**：每个示例的分隔符、前缀、排版结构必须整齐划一。格式不一致容易导致输出偏离预期。这与上一期的输出指示相呼应，说明模型对格式较为敏感。
3. **标签正确性最不重要**：即使使用随机标签，只要标签处于合理集合内，模型仍能学习任务模式。实际工程不会故意使用错误标签，但这一结论说明应优先保证标签空间合理与格式一致。

### 工程界三条补充

Anthropic 给出了三条工业级建议：

1. **相关**：演示应贴近真实使用场景，生产系统的 Prompt 不宜直接采用脱离场景的教科书示例。
2. **多样**：示例应覆盖边界情况，不仅包含典型案例，还要包含困难案例和例外情况。
3. **结构化**：用 XML 标签把每个示例包裹起来。这跟 Anthropic 的 XML prompt 风格一脉相承。

数量上，3~5 个示例是最佳经验值。

### 完整方法论

综合上述原则，可以得到以下演示选取方法：

- 先确定标签空间；
- 挑 3~5 个相关且多样的示例；
- 保持格式完全一致；
- 不在标签细节上投入过多精力。

## 少样本的软肋：多步推理

少样本提示存在一个明确的失效场景：多步推理。

Prompting Guide 里给了一个典型案例。问模型：15、30、27、2、14、11 这组数里，奇数之和是偶数吗？无论零样本还是少样本，模型都答不对。

原因在于这道题需要三步推理：

1. 先挑出奇数：15、27、11；
2. 再求和：15 + 27 + 11 = 33；
3. 再判断奇偶：奇数。

少样本演示只提供输入输出的表面映射，即输入一组数字后输出“是否”，却没有呈现中间推理过程。模型无法从示例中观察由输入推导输出的方法，只能直接预测答案，因而容易出错。

这正是少样本提示的主要限制：它解决的是格式适配，使模型学习任务结构和输出模式，而非学习推理方法。若要提高复杂任务的正确率，需要在演示中同时呈现推理步骤，即下一期介绍的思维链提示。

## 总结

下表概括少样本提示在整体方法体系中的位置。

少样本提示的本质是在 Prompt 中加入演示示例。零样本只提供“把这句话翻译成英文”的指令，少样本则在指令前增加若干翻译示例，使模型沿用相同模式。

其底层机制称为上下文学习：模型不更新任何参数，而是把演示作为临时训练数据。但这种能力依赖模型规模，只有跨过相应门槛才会显著涌现，小模型增加示例也难以获得同等效果。

在实际应用中，演示选取有三项原则：标签空间和输入分布最重要，格式一致性次之，标签正确性相对最不重要。Anthropic 还补充了相关、多样、结构化三项建议，并认为 3～5 个示例效果最佳。

少样本提示的主要限制在于多步推理：它展示任务输入与输出，却没有呈现中间推理过程。
