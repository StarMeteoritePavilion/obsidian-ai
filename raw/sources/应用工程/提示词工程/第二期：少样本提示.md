> 提示词工程系列 第二期

这是提示工程系列的第二期。上期我们讲了零样本：不给示例，一句指令就让模型干活。今天升级到少样本提示——在 prompt 里塞几个例子，不给任何训练数据，不动任何参数，模型就能临时学会一个新任务。

比如你想让模型做英译中，不用写代码，不用调 API，你就在 prompt 里写两对英文、中文的例子，然后甩一个新句子，模型照猫画虎，直接输出中文。零样本是"跟模型说话"，少样本是"做给模型看"，效果天差地别。

## 什么是少样本提示

先说结论：**少样本提示就是在 prompt 里放几个输入输出的示例，让模型照着样干。**

注意关键词——不修改模型权重，这跟微调完全不同。你不碰模型的任何参数，只是在 prompt 里加了几个例子，模型就看懂了。

这个能力有个专门的学术名词，叫上下文学习（in-context learning）。模型把 prompt 里的示例当作条件，基于这些条件临时理解任务，然后产出答案。零样本是告诉它做什么，少样本是做给它看。演示示例（demonstration）就是这门手艺的抓手。

## 全景图：少样本在提示方法体系里的位置

在展开之前，先看全景图，定位少样本在整个提示方法体系里的位置。

- **左边是上期讲的零样本**：只给指令，模型猜着来。
- **中间是今天的主角少样本**：给几个示例，模型照着做。
- **右边是下期要讲的思维链**：不仅给例子，还给推理过程，模型跟着想。

三者的关系是递进的：零样本最简单，复杂任务搞不定；少样本补上了，适用覆盖面大增；思维链再把推理过程加进去，攻克最难的那一批任务。

少样本下面有两个核心概念：

- **左边是上下文学习**：不更新任何参数，只看演示就学会。
- **右边是涌现能力**：模型不够大，看再多例子也白搭。

这两个概念构成了少样本的全部秘密。接下来我们一个一个拆。

## 少样本提示长什么样

少样本提示非常直观：在 prompt 里先放几个输入输出的示例，最后放一个待处理的新问题，模型照猫画虎给出答案。

举个例子。**零样本翻译**，你在 prompt 里写：

```
把下面这句话翻译成英文。
你好
```

模型能翻，但它是在猜你到底要什么。

**少样本翻译**，你换一种写法：

```
英文：Hello
中文：你好
英文：Goodbye
中文：再见
英文：Thank you
中文：
```

模型看到前两对示例，立刻就明白这个游戏规则了——你在做英译中，于是它在第三行填上"谢谢"。

这就是少样本的核心：演示是模型生成响应的条件。这是 Brown 等人在 2020 年 GPT-3 论文中奠定的概念——你在 prompt 里放的示例分布，会直接塑造模型的输出行为。

演示数量没有固定标准：简单的任务一个例子（one-shot）就够；困难的任务，三个、五个甚至更多，但受限于上下文窗口长度，也不能无限多。Anthropic 的工程经验是 3~5 个示例最佳。

还有一个关键点：格式不是固定的。你做什么任务就演示什么格式——做翻译就演示原文、译文，做分类就演示文本、标签，做代码生成就演示需求、代码。这种灵活性就是少样本的优势。

## 上下文学习：模型没更新参数怎么学会的

少样本提示最反直觉的地方是：模型没有更新任何参数，它怎么学会的？这个现象有个专门的学术名词，叫上下文学习（in-context learning）。把它跟微调对比一下就清楚了。

**微调是怎么学的？** 你把成千上万条标注数据喂给模型，模型通过反向传播更新内部参数，把新任务刻进神经网络的权重里。这需要 GPU 时间和大量数据。

**上下文学习呢？** 你把几个例子写进 prompt，模型在推理时直接看懂了任务模式，参数一个没动。prompt 一结束，这个临时学会的状态就消失了。零成本，即时生效。

### 标签正确性不重要

更颠覆认知的是 Min 等人在 2022 年的发现：标签本身对不对，根本不重要。

他们做了一个实验，把情感分类示例里的正确标签换成随机标签。比如把"这部电影很棒"标成负面，把"烂透了"标成正面。结果呢？模型依然能正确分类新的文本。

为什么？因为模型学到的是"这是一道三选一的分类任务"，而不是"这个具体标签对不对"。标签空间和格式，比标签正确性重要得多。

这就是上下文学习魔幻的地方：模型不是在记住答案，而是在理解任务的结构。

当然它有上限。需要多步推理的任务，光给输入输出示例是不够的——模型看见问题、答案的表面映射，没看见中间的推理过程。这就是为什么后面要引入思维链。

## 涌现能力：这是大模型的特权

上下文学习还有一个关键特征：它是一个涌现能力。

什么叫涌现能力？就是某种能力在小模型上完全不存在，但当模型规模跨过某个阈值后，突然就冒出来了。不是渐变，而是跃迁。

Wei 等人（2023）和 Kaplan 等人（2020）的研究表明：参数规模在 10 亿以下的模型，你在 prompt 里塞再多示例，它的表现也几乎没有提升；但当模型规模跨过 100 亿参数的门槛，给 3~5 个示例，性能直线飙升。

这个发现跟上一期讲的"指令微调加 RLHF"是相互呼应的：零样本能力需要指令微调做底座，少样本的涌现同样依赖于足够大的模型规模。模型不够大，prompt 写出花来也没用。这是贯穿整个提示工程系列的底层功力。

实践含义很明确：

- 如果你用的是 GPT-4、Claude 这个量级的模型，少样本是你的利器。
- 如果你用的是小模型，别指望塞几个例子就能逆天改命，该微调还得微调。

## 演示示例怎么选

那在一线实战中，演示示例到底怎么选？学界给出了三条铁律，工程界给出了三条补充。

### 学界三条铁律

1. **标签空间和输入分布最重要**：你要先确定好任务有多少个可能的输出标签，然后让演示覆盖典型的输入类型。比如做情感分类，标签空间就是正面、负面、中性，演示里要确保每个标签都有对应示例。
2. **格式一定要一致**：每个示例的分隔符、前缀、排版结构必须整齐划一。格式一乱，模型就容易跑偏。这个跟上一期讲的输出指示呼应——模型对格式非常敏感。
3. **标签正确性最不重要**：这个刚才已经说了，你甚至可以用随机标签，只要标签在合理集合内，模型照样能学会任务模式。当然在实际工程中，没人故意给错标签，但这条意味着你不需要花大量时间纠结每个标签打得对不对。把精力放在选对标签空间和保持格式一致上就行。

### 工程界三条补充

Anthropic 给出了三条工业级建议：

1. **相关**：演示要贴近真实使用场景，别用教科书上的例子做生产系统的 prompt。
2. **多样**：示例要覆盖边界情况，不光有典型 case，还要有难 case 和例外 case。
3. **结构化**：用 XML 标签把每个示例包裹起来。这跟 Anthropic 的 XML prompt 风格一脉相承。

数量上，3~5 个示例是最佳经验值。

### 完整方法论

把这些合在一起，就是演示选取的完整方法论：

- 先确定标签空间；
- 挑 3~5 个相关且多样的示例；
- 保持格式完全一致；
- 不纠结标签细节。

## 少样本的软肋：多步推理

最后说少样本的软肋。它有一个明确的失效场景：多步推理。

Prompting Guide 里给了一个典型案例。问模型：15、30、27、2、14、11 这组数里，奇数之和是偶数吗？无论零样本还是少样本，模型都答不对。

为什么？因为这道题需要三步推理：

1. 先挑出奇数：15、27、11；
2. 再求和：15 + 27 + 11 = 33；
3. 再判断奇偶：奇数。

少样本演示只给了输入输出的表面映射——一堆数字进去，一个"是否"出来，中间没有任何推理过程。模型看不到你是怎么从输入走到输出的，它就只能猜，猜不对。

这就是少样本提示的阿喀琉斯之踵：它解决的是格式适配问题，让模型学会任务的结构和输出模式，而不是思维推理问题——让模型学会怎么想。要想让模型在复杂任务上答对，你得在演示里把推理步骤也写出来。这就是下一期的主角：思维链提示。

## 收尾

回到全景图，用一张表收尾。

少样本提示的本质是在 prompt 里放演示示例。零样本说"把这句话翻译成英文"，少样本在前面补两对英文、中文的例子，模型照猫画虎。

它的底层机制叫上下文学习：不更新任何参数，模型把演示当临时训练数据。但这是大模型特权，只有参数规模跨过门槛，这个能力才会涌现，小模型看再多例子也没用。

在实战中，演示选取有三条铁律：标签空间和输入分布最重要，格式一致性次之，标签对不对最不重要。Anthropic 再加三条：相关、多样、结构化，3~5 个示例最佳。

但少样本有硬天花板：对多步推理任务无能为力，因为它只展示了"是什么"，没展示"怎么想"。
