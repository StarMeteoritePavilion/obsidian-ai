# 10 分钟讲透 AI Agent 8 种主流架构

> AI Agent 架构设计独立专题

ReAct、Plan-and-Execute、Multi-Agent、Reflection、Tools、Memory、RAG 和 Autonomous Loop 分别解决边做边判断、规划长任务、角色分工、检查改进、执行操作、延续经验、获取知识和持续推进目标的问题。这八种模式可以组合成一个完整的 Agent 运行系统。

## 三层能力与运行边界

Agent 接收目标、上下文和约束，通过三层能力组织工作：

- **决策层**决定下一步怎么做，对应 ReAct、Plan-and-Execute 和 Reflection。
- **能力层**提供完成任务所需的能力，对应 Tools、Memory 和 RAG。
- **运行层**负责系统如何扩展和持续运行，对应 Multi-Agent 和 Autonomous Loop。

系统输出既可以是文字，也可以是工具操作和任务状态更新。执行结果返回系统，成为下一轮决策的输入。真正可用的 Agent 还必须具备权限、预算、终止条件和审计，因此可以将其概括为：模型、设计模式与运行边界的组合。

## 一、ReAct：边做边判断

ReAct 将推理与行动结合起来。收到任务后，系统通过“判断下一步—调用工具—观察结果”的循环推进工作。

例如，制作竞品报告时，Agent 先发现缺少市场数据，于是执行搜索；取得结果后，又发现两个来源的数据不一致，于是继续查证；证据足够后，才进入写作环节。

这种模式特别适合无法提前确定完整路线的开放任务。它也可能重复调用工具，甚至持续循环，因此必须设置目标完成、预算耗尽和请求人工等停止条件。ReAct 的核心是先走一步，观察结果，再决定下一步。

## 二、Plan-and-Execute：先规划，再执行

Plan-and-Execute 将规划与执行分离：规划器把目标拆成任务图，执行器再按照依赖关系逐项完成。

竞品报告可以拆成四个步骤：

1. 确定竞品名单。
2. 收集产品数据。
3. 比较价格和评价。
4. 生成结论和引用。

执行器一次只处理当前步骤，并把完成状态交回系统。ReAct 更像边走边找路，Plan-and-Execute 则更像先看地图再出发。但预先规划不意味着固守原计划：某一步受阻时，成熟的系统会重新规划。

这种模式更适合研究报告、软件开发和项目交付等长任务。

## 三、Multi-Agent：通过角色分工协作

Multi-Agent 由主管智能体拆分任务，再交给不同专业角色。在竞品研究中，研究员检索证据，分析师比较数据，撰稿人生成报告，审查员核验事实。各角色通过共享工作区交换任务状态、中间产物和证据。

多智能体适合可以并行处理、确实需要不同专业视角的复杂任务。不过，Agent 数量增加也会带来通信成本、上下文冲突和重复劳动。其价值取决于有效分工。

## 四、Reflection：通过反馈改进结果

反思型智能体把生成与评价拆成两个环节。生成器先给出初稿，评价器再按明确标准检查事实、完整性、格式和引用。

如果评分不达标，系统会给出“缺少来源”“结论过度”等具体反馈，再交回生成器修改，达到标准后正式交付。

Reflection 适合代码、报告、方案等能够定义质量标准的任务。模型自我评价也可能存在共同盲区，因此最好结合外部测试、可靠数据和人工审核，并限制最大反思轮数。

## 五、Tools：让模型具备受控的操作能力

工具增强型智能体通过搜索、数据库、代码执行器、文档系统和企业 API，把模型的内容生成能力连接到实际操作。

模型负责选择工具、生成参数；工具网关负责参数校验、权限检查、路由、重试和日志。执行结果被整理为标准化的 Observation，返回 Agent，供其决定下一步。

真正的难点在于控制操作的副作用。涉及发送消息、删除数据或付款时，必须加入人工审批、幂等控制和审计记录。模型提出行动，由受控运行时负责真正执行。

## 六、Memory：让状态与经验跨轮延续

记忆增强型智能体用工作记忆保存当前任务的目标、事实和状态。记忆管理器提取重要信息，经过去重和冲突处理后写入长期记忆。

长期记忆通常包括三类内容：

- **情景记忆**：过去做过什么。
- **语义记忆**：长期事实与知识。
- **用户偏好和规则**：用户希望系统如何工作。

例如，Agent 可以记住用户更关注商业模式、喜欢表格，并要求所有结论附带来源。

记忆需要处理过期、错误、隐私和删除问题。好的记忆架构既要保留有价值的信息，也要知道何时应该遗忘。

## 七、RAG：主动寻找可验证的证据

普通 RAG 往往检索一次后直接回答；RAG Agent 则会拆解问题、改写查询、选择数据源，并判断是否需要继续搜索。

系统可以访问企业文档、公开网页和结构化数据库，结合相关性、权威性和时间进行去重与重排，形成证据包，最后生成带引用的答案。

例如，两个来源给出的竞品用户数不一致时，验证器会要求继续查询财报或官网公告，而不能任意选取一个数字。

RAG 解决的是答案依据什么知识的问题。其效果上限很大程度取决于检索质量、文档质量，以及引用是否可追溯。

## 八、Autonomous Loop：围绕目标持续推进

用户给出高层目标后，自主循环系统保存目标与当前状态，持续执行观察、决策、行动和评估，直到任务完成、暂停或请求人工介入。

例如，每周跟踪竞品动态时，系统可以按计划搜索新信息，判断哪些变化值得关注，更新报告，并在发生重大事件时主动通知用户。

在本文的八种模式比较中，作者将 Autonomous Loop 视为自主程度最高、风险也最大的一种。因此，系统必须设置权限边界、预算上限、最大循环次数、检查点、审计日志和人工审批。一旦目标理解错误，自动循环就会持续放大错误；自主性越高，停止机制和治理能力就必须越强。

## 从最小闭环开始选择

作者建议从最小闭环起步，按任务需要逐层增加能力：

1. 需要访问外部系统时，从 **Tools + ReAct** 开始。
2. 回答依赖文档或实时数据时，加入 **RAG**。
3. 任务需要跨会话延续时，增加 **Memory**。
4. 任务步骤多、依赖关系明确时，引入 **Plan-and-Execute**。
5. 对交付质量敏感时，加入 **Reflection**。
6. 只有任务确实需要专业分工时，才使用 **Multi-Agent**。
7. 只有系统已经具备权限、预算、监控和终止机制时，才开启 **Autonomous Loop**。

随着自主性提高，工程复杂度也会上升。每增加一层能力，都需要同步增加评估、成本控制和安全治理。

## 组合示例：持续生成竞品简报

围绕“持续生成竞品简报”的目标，Plan-and-Execute 拆解任务，主管 Agent 把任务分配给研究员、分析师和撰稿人。每个角色内部都可以使用 ReAct 循环。

Tools 提供实际操作能力，RAG 提供可引用的知识，Memory 保存偏好、历史和任务状态。初稿完成后，Reflection 负责事实审查、质量评分和反馈修改。

底层的 Autonomous Runtime 负责定时触发、预算、权限、检查点和人工审批，使这些能力在统一边界内协同运行。

成熟的 Agent 应当能在明确边界内，稳定、可评估、可停止地完成目标。架构选择的重点是让各层能力共同服务于这一要求。

后续可从具体业务场景出发，进一步拆解各类架构的完整工作流程与技术实现。
