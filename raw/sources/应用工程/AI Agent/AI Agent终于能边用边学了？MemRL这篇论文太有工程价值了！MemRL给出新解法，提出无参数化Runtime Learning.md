> MemRL：基于情景记忆的无参数化运行时强化学习

AI Agent 上线后，怎样在不修改模型参数的前提下持续学习，直接影响线上系统的长期效果。MemRL 由上海交通大学、MemTensor 等团队联合发布，试图让学习发生在外部记忆库中，使 Agent 能够从执行结果中积累经验。

## 两条常见路线的缺陷

第一个典型场景是操作系统自动化 Agent。系统使用 RAG 保存历史成功操作；面对相似任务时，它可能检索到语义最接近的记录，但记录假设目标用户已经存在，而当前环境中根本没有该用户。直接照搬流程会导致任务失败。检索结果虽然语义相似，却没有功能价值。

第二个场景是让 Agent 通过 Fine-tuning 从错误中学习。RLHF、SFT、GRPO 等参数更新路线可以把经验内化进模型权重，但需要较高算力；持续更新还可能让新权重冲掉旧知识，引发灾难性遗忘。

另一条路线是 RAG 和各类记忆增强系统。它们不更新模型权重，检索策略却通常是静态的。如果只按语义相似度选出记录，系统无法判断这条历史经验是否真正有助于完成当前任务。语义相关性与功能实用性之间存在根本差距。

## 从语义匹配到 Q-value 决策

MemRL 把记忆检索从被动的语义匹配改造成主动的 Q-value 决策问题。模型权重全程冻结，学习只发生在记忆库中，从而绕开持续微调带来的灾难性遗忘。

这里的 Q-value 源自强化学习中的动作价值函数。在 MemRL 中，它表示一条记忆的历史效用：过去把这条记忆用于任务时，Agent 成功完成任务的表现如何。系统据此区分真正有用的经验与语义相似但实际有害的经验。

检索分为两个阶段：

1. 使用余弦相似度粗筛 Top-K 候选，保证记忆与当前任务在语义上相关。
2. 使用从环境反馈中持续学习的 Q-value 对候选重新排序，让历史上有害的干扰记忆自动降权。

余弦相似度只衡量向量空间距离，不关心历史执行结果；Q-value 则随着成功或失败反馈持续更新。两者结合后，系统同时考虑语义相关性与功能实用性。

## 三层系统结构

MemRL 由三层组成：

- **冻结语言模型**：根据上下文生成 Action，权重始终不变。
- **结构化记忆库**：每条记忆不是简单文本，而是由意图、经验和效用分数 Q-value 构成的三元组。
- **检索—更新控制器**：决定检索哪些记忆，并根据执行结果更新 Q-value、写回新记忆。

这种结构把稳定推理与可塑记忆分开：语言模型承担稳定的生成能力，记忆库承担不断变化的经验，控制器连接检索、执行、反馈和更新。

## 推理与 Runtime Learning

推理开始后，系统先用 Embedding 模型将 Query 向量化，以余弦相似度粗筛候选，再按 Q-value 精排。选出的记忆被注入 Prompt，由冻结的语言模型生成 Action，并在环境中执行以取得反馈。

Runtime Learning 发生在执行之后。系统使用环境反馈的奖励，通过蒙特卡洛更新规则调整本次使用记忆的 Q-value：

$$
Q(m) \leftarrow Q(m) + \alpha \cdot (r - Q(m))
$$

这个过程不计算梯度，也不进行反向传播。同时，系统把本次执行轨迹摘要为新的“意图—经验—Q-value”三元组并写回记忆库。记忆库持续增长，语言模型参数保持不变；变化的是记忆条目及其效用分数。

## 实验结果与边界

资料展示的实验覆盖 WebArena、ALFWorld、SciWorld 和 InterCode 四个跨域 Benchmark。MemRL 的平均成功率相对最强基线提高 3.8 个百分点；其中探索密集型任务的提升最高达到 6.2 个百分点，额外推理成本约为零。上述数字来自论文的特定任务、模型与实验设置，不能直接外推为其他 Agent 的性能保证。

MemRL 的主要价值不是简单扩大记忆库，而是让环境反馈改变未来的记忆选择：成功经验逐步升权，失败经验逐步降权。它仍留下两个直接的工程问题：奖励信号是否可靠，以及记忆库增长后如何进行规模管理和淘汰。

当前方案面向单个 Agent 的记忆自进化。多个 Agent 实例共享记忆库时，一个 Agent 的错误经验是否会污染其他 Agent 的决策，仍是需要解决的问题。

## 总结

MemRL 针对的是 Agent 部署后无法低成本持续学习，以及 RAG 语义相关性不等于功能实用性的问题。它以两阶段检索结合蒙特卡洛更新，把记忆检索建模为 Q-value 驱动的决策过程，在冻结模型权重的同时实现无参数化 Runtime Learning。
