# AI知识图谱 GraphRAG 是怎么回事？

传统 RAG 存在分块粒度矛盾：片段过大容易漏检局部细节，片段过小又会切断原本相连的语义关系。GraphRAG 通过构建知识图谱来补充仅依赖片段相似度的检索，在保留细节的同时显式组织实体、关系和层次结构。

GraphRAG 官方实现的默认工作流可以清晰地分为“图谱构建”与“图谱查询”两条主线。

## 图谱构建流水线

GraphRAG 的图谱构建是一个高度依赖大语言模型（LLM）的流水线，负责从纯文本中提取并构建层级化的知识结构。

### 1. 提取属性图（LPG）
知识图谱在 GraphRAG 中通常以属性图（Labeled Property Graph, LPG）的形式存在。LPG 包含三个核心要素：
- **实体（Entity）**：图的节点。
- **关系（Relationship）**：连接节点的边。
- **属性（Property）**：节点和边上附带的键值对描述（如标签、类型、权重、自然语言摘要等）。

### 2. 实体抽取与关系抽取
系统首先对原文进行分块，然后通过 Prompt 交由大模型执行命名实体识别（NER）和关系抽取任务。
官方默认提取的实体类型包括团体（Organization）、人（Person）、位置（Geo）和事件（Event）。模型同时识别实体之间的连接，并为生成的实体和关系生成简要文字描述。

### 3. Data Gleaning 补充提取
由于大模型在单次提取中可能会遗漏信息，GraphRAG 引入了 Data Gleaning（数据拾遗）机制。它会在初始提取后，将生成的图谱与原文再次交给模型，询问是否存在遗漏。如果发现遗漏，系统会继续提取并合并，直到达到配置的最大循环次数（`max_gleanings`）或模型认为无需补充为止。

### 4. 协变量（Covariate）抽取
除了实体和关系，系统还会提取独立的主张（Claims），官方称其为 Covariate。
在代码实现中（如 `extract_covariates` 和 `claim_extractor`），Covariate 不是简单的文字性总结，而是具有主语、宾语、类型、描述和状态等高度结构化的事实陈述。原作者认为该功能的实际业务价值有限。

### 5. 实体消歧与合并
系统会跨片段合并名称相同的实体，把分散在不同节点和边上的描述聚合在一起，再由大模型整理出一份连贯的总结性描述。
**风险提示**：这一步极易出现同名实体合并错误。如果文章中出现两个同名但指代不同的实体（例如两个名叫“张三”的人），模型大概率将它们的特征物理混淆到一个节点上，给后续检索带来严重的方向性偏差。

### 6. Leiden 社区检测与总结
文章越长，图谱越庞大。GraphRAG 采用 Leiden 社区检测算法，将连接密集的节点聚合成子图（社区），并逐层向上抽象。
底层是包含具体实体的细粒度社区，高层是更加宏观的抽象社区。系统会让模型对每一个层级的每一个社区生成一份社区摘要报告（Community Report），形成“叶子节点包含细节，根节点包含全局”的层级树。

### 7. 索引构建
最终，系统将节点、边、Covariate、社区摘要报告以及原始文本块全部生成 Embedding，并存入向量数据库，以便查询时进行不同维度的检索。

## 图谱查询主线

查询阶段，用户问题同样会被转化为向量或直接作为 Prompt 输入。GraphRAG 提供了两种截然不同的检索策略：

### Local Search：从细节向外扩展
- **适用问题**：细节丰富、需要准确定位具体实体和事实的问题（例如“文中提到的某某技术具体有什么优缺点？”）。
- **输入与执行**：从最底层图谱中寻找与问题最接近的实体节点。找到后，系统利用映射关系沿边扩展，提取：
  1. 生成这些节点和边的原始文本片段；
  2. 相关的 Covariate（主张）；
  3. 节点所属的底层社区报告；
  4. 邻接的其他节点和边。
- **返回材料**：将上述结构化片段、摘要和原文块拼接后，与用户问题一起交给大模型，生成具备高颗粒度事实支撑的回答。

### Global Search：从全局向下追溯
- **适用问题**：抽象程度较高的全局性或总结性问题（例如“这篇文章的核心观点和未来趋势是什么？”）。
- **输入与执行**：直接从较高层级的社区入手。系统通过 Map-Reduce 的方式，先让模型针对特定层级（如 Level 2）的所有社区摘要分别生成局部回答，然后再把这些局部回答汇总给模型，生成最终的全局答案。
- **返回材料**：高度依赖模型预先生成的社区层级报告，不深入具体的原始文本块或细碎的邻接实体信息。

## 实施成本与风险

尽管 GraphRAG 补足了传统向量检索缺乏全局关联的短板，但其在实际落地中面临显著的边界挑战：

1. **高昂的图谱构建成本**：不仅全量文本需要过一遍大模型，Data Gleaning 的多轮轮询、实体合并重写以及 Leiden 社区逐层生成摘要报告，都会消耗海量的 Token 及处理时间，使得构建成本远超普通 RAG 系统。
2. **模型推断污染与幻觉注入**：GraphRAG 的社区报告完全由模型生成，模型可能会结合图谱关系自行推断出未在原文中直接表达的结论。一旦这种推断出现幻觉（Hallucination），生成的错误描述就会作为“知识”被固化在社区报告中，进而污染后续所有的 Global Search 结果，而在复杂的层级图中排查这类污染极为困难。
