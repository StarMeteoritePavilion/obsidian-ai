> GraphRAG 独立专题

传统 RAG 会先把文章切成文本片段，再通过 Embedding 将每个片段转化为向量并存入向量数据库。查询时，系统根据问题与片段的相关度召回内容。

这种方法面临一个分块粒度矛盾。片段过大时，问题与整段文本的整体相关度可能不足，局部细节容易漏检；片段过小时，原本相连的语义关系又会被切断。例如，“老王喜欢吃西瓜”同时包含“老王”“喜欢吃”和“西瓜”三层信息。按整句检索可能无法完整回答“文章中一共提到几次西瓜”，按词切分又难以回答“老王喜欢吃什么”。

GraphRAG 用知识图谱补充这种只依赖文本片段相似度的检索方式，在保留细节的同时显式组织实体、关系和层次结构。

## 从文本中建立知识图谱

在“老王爱吃西瓜”这个例子中，“老王”和“西瓜”是实体（Entity），两者之间的“爱吃”是关系（Relationship）。实体还可以带有“人”“水果”等类型或属性。这种同时包含实体、关系和属性的图结构在资料中称为 LPG。

GraphRAG 借助大语言模型从文本中生成图谱。核心流程包括：

1. 识别实体，并按照预先设定的类型分类。示例类型包括人、物体和味道；资料所述 GraphRAG 默认类型包括团体、人、位置和事件。
2. 识别实体之间的关系。
3. 按约定格式输出实体、类型和关系。
4. 为每个实体和关系生成简要文字描述。

前两步分别对应命名实体识别（Named Entity Recognition）和关系抽取（Relation Extraction）。过去需要专门模型完成的任务，现在可以通过 Prompt 交给大语言模型处理。

大模型生成的结构化结果不保证与原文完全一致，也可能编造信息。因此，提示词通常需要明确禁止虚构。GraphRAG 还会把已经生成的图谱与原文再次交给模型，询问是否存在遗漏；如果仍有遗漏，就继续补充和检查，直到模型表示不再需要补充。资料将这个反复提取信息的过程称为 Data Gleaning。

## 合并片段级图谱

GraphRAG 会分别处理文章中的每个文本片段，再自动合并名称相同的实体，最终形成文章级知识图谱。实体类型取决于提示词中的预先定义：如果“味道”被列为实体类型，“甜”也会被识别为实体。

同名实体合并时，分散在不同节点或边上的描述也会一并聚合。GraphRAG 再让大语言模型把这些描述整理为更完整、通顺的总结性描述，作为合并后的最终描述。最终图谱同时包含结构化的点与边，以及由模型整理的自然语言说明。

GraphRAG 还会维护图谱与原文之间的对应关系。系统既能从实体或关系追溯到生成它们的原文片段，也能从一段原文定位到对应的实体和关系。这种双向映射会在后续查询中继续使用。

## 通过社区检测建立层级

文章越长，图谱越庞大，直接查询也越困难。GraphRAG 使用 Leiden 社区检测，把连接密集的节点聚合成子图，再根据每个子图中点和边的描述生成更高层的总结。

资料中的示例把相互连接较多的四个节点归为一个整体，把“味道”单独归为另一个整体。模型可以从子图信息中总结“老王爱吃瓜和桃，小王爱吃瓜”，还可能结合“小王只爱吃瓜”推断出“小王不爱吃桃子”。该推断没有直接出现在原文中，而是模型根据图谱关系生成的结果。

如果图谱仍然过于复杂，就继续执行合并、总结和向上抽象，最终形成层级结构：越高层的信息越抽象、精炼，越低层的信息越接近原文细节。

## 将图谱转化为可检索索引

完成知识图谱后，系统还需要把它转化为可快速查询的索引。GraphRAG 将节点、边、实体信息和总结性描述视为文本片段，分别生成 Embedding 并存入向量数据库；原始文本切片也一同进入向量数据库。

查询时，用户问题同样会被转化为向量，再与原文或知识图谱中的 Embedding 匹配。系统可以只查询图谱的某一层或某几层，也可以只查询原文，或者同时检索全部内容。

### Local Search：从细节向外扩展

Local Search 从最底层图谱中寻找与问题最接近的实体。找到相关节点后，系统利用图谱与原文的映射关系，继续取得：

- 生成这些节点和边的原文片段；
- 节点和边所属的上层图谱结构；
- 与它们相邻的其他节点和边；
- 相关的 Covariate 信息。

资料将 Covariate 描述为对原文片段的文字性总结，并称其为实验性功能；作者认为它的实用价值有限，同时提到 `extract_covariates` 与 `claim_extractor` 两个实现文件。

系统把图谱描述、关联原文、相邻信息和用户问题一起交给大语言模型。由于 Local Search 从底层图谱开始，它更适合细节丰富、需要准确定位的问题。

### Global Search：从全局向下追溯

Global Search 从图谱高层开始，再逐层向下追溯。它更适合回答抽象程度较高的全局问题，例如“这篇文章的核心观点是什么”。

Local Search 与 Global Search 分别从细节和全局进入同一套层级图谱，使 GraphRAG 可以在原文片段、实体关系和社区摘要之间选择不同的检索路径。

## 效果与成本边界

从构建图谱、补充遗漏、合并描述到生成社区摘要，GraphRAG 的多个步骤都依赖大语言模型。资料认为，微软论文中的实验结果说明这种方法具有实际效果，但也强调它会消耗大量 Token。

GraphRAG 的核心不是用图谱完全替代向量检索，而是在文本片段之外增加实体、关系、来源映射和分层摘要。零散知识由此逐渐形成相互连接的结构，系统也可能从连接中发现原文没有直接表达的信息；与此同时，这些新增推断仍然来自模型生成，需要结合原文与来源映射审视其可靠性。
