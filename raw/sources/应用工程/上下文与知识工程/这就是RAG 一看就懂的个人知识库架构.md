> 应用工程／RAG 独立专题

当大语言模型没有见过一份内部文档时，它可能给出看似合理、实际却与文档无关的回答。这类脱离可靠依据生成内容的现象，通常被称为大模型幻觉。

最直接的解决办法，是把文档与问题一起交给模型。但随着文档变长，真正有用的答案可能只分布在少量片段中。把整份文档全部放入上下文，不仅浪费空间，也可能使模型难以抓住重点。

RAG（Retrieval Augmented Generation，检索增强生成）提供了另一种思路：不发送整份文档，而是先找到与问题真正相关的片段，再将这些片段和问题一起交给大语言模型。

## Embedding：把文本映射为向量

判断文字与问题是否相关，需要先把文本转换成便于比较的形式。Embedding 模型接收一段文字，输出一个固定长度的数字数组，也就是向量。无论输入是一句话还是一整段文字，同一个模型输出的向量长度都保持一致。

OpenAI 的 `text-embedding-3-small` 模型输出 1536 维向量，`text-embedding-3-large` 模型输出 3072 维向量。向量可以理解为对原始内容的有损压缩：部分信息被舍弃，但语义关系仍被保留。意思相近的文本会被映射到向量空间中距离较近的位置，意思差异较大的文本则相距更远。

为了便于理解，可以先把向量空间简化成二维坐标系。“老王爱吃瓜”和“老王喜欢吃瓜”意思接近，因此对应的点也会靠得很近；“我也爱 Python”与前两句话存在较弱联系，距离会稍远一些；“刚买的飞机被打了”与它们的语义差异很大，会落在非常远的位置。

二维空间无法准确容纳大量文本之间的复杂关系。现实中的 Embedding 模型通常使用上千维甚至数千维的向量空间，从而更准确地表达句子之间的语义距离。

当用户询问“老王爱吃什么”时，可以用同一个 Embedding 模型把问题转换为向量。系统随后计算问题向量与已有文本向量之间的距离，找出距离最近的几个文本片段，并将它们作为上下文与问题一起发送给大语言模型。模型得到的上下文更加集中，产生幻觉的风险也会降低。

## 文档预处理：分块、编码与存储

长文档需要在用户提问之前完成预处理，整个过程包括三个步骤。

### 分块

系统先把文档切成多个较小的片段。分块可以按照字数、段落或句子进行，也可以使用更复杂的策略。这个过程通常称为 Chunking。

### 编码

每个文本片段都交给 Embedding 模型处理，转换成长度一致的向量。系统必须同时保留向量与原始文本片段之间的对应关系，才能在检索到向量后取回原文。

### 存储

传统数据库擅长根据明确数值执行精确查询，但这里需要解决的问题是：哪个向量与问题向量最接近。向量数据库正是为这类相似性检索设计的。每条数据可以关联一个向量；查询时输入问题向量，数据库便返回距离最近的若干条数据。常见选择包括 Pinecone、ChromaDB，以及 PostgreSQL 配合 pgvector 插件的组合。

完成分块、编码和存储后，所有文本片段及其 Embedding 都已准备好等待检索。

## 一次完整的 RAG 查询

当用户提出问题时，系统依次完成以下操作：

1. 使用与文档相同的 Embedding 模型把问题转换成向量。
2. 从向量数据库中检索距离最近的若干文本片段。
3. 将检索结果与用户问题共同组成上下文。
4. 把上下文交给大语言模型生成回答。

这条链路把原本过长的文档压缩为少量相关片段，使模型能够在有限上下文中优先看到可能包含答案的内容。

## RAG 的先天限制

RAG 并不是完美架构，它至少存在两类难以彻底消除的问题。

### 分块可能破坏语义关系

每篇文章的结构都不同。无论按照句子、段落还是更复杂的规则分块，都很难适配所有场景。

例如，“我是程序员老王，我爱吃瓜”包含明确的指代关系。如果这句话被拆成两个片段，后半句中的“我”便可能失去与“老王”的联系。当用户询问“老王喜欢吃什么”时，问题与“我爱吃瓜”之间的向量距离可能因此变远，导致系统漏掉相关片段。

更复杂的分块策略只能减少这类误伤，无法彻底避免。

### 局部检索缺少全局视角

如果用户询问“一篇文章里一共出现了多少个‘我’字”，答案与文章中的每个片段都有关系，却没有任何一个片段与问题特别相关。RAG 擅长寻找少量高度相关的局部内容，不擅长处理这种需要遍历全文的全局问题。

## 改进方向与边界

针对分块和指代问题，可以在预处理阶段把代词替换为明确对象，也可以让大语言模型参与分块，根据语义判断断点。但这些方案都只能改善特定问题，目前没有一种方法可以适配所有文章和查询。

RAG 更像是大模型上下文有限时的一种妥协。它通过分块、筛选和检索保留重要内容、舍弃不相关内容，能够解决一部分问题，却无法处理所有问题。新的改进方案仍在持续出现，真正突破这种妥协的下一代架构仍有待探索。

## 从信息取舍到生活取舍

RAG 本质上是一种压缩：文档太长，就先切块、建立索引，再筛选出重要内容。人的生活也存在类似过程。面对越来越多的人和事情，人们逐渐学会分类与取舍：有些事情必须及时处理，有些可以稍后完成；有些需要记住，有些则会慢慢遗忘。

这种选择常被视为成熟和清醒，但当信息被切得太碎时，人也可能失去上下文、误解原意，使原本重要的人和事情断开联系。老同桌或停留在“哈哈哈”的最后一条消息并没有变得不重要，只是彼此生活中的“向量坐标”越来越远。

作者最后提到，偶然翻到一张过去一起玩游戏的截图，盯着看了很久，忽然发现：那时候队友的 DPS 确实很低。
