> 上下文工程系列 第八期

前七期已经介绍了检索、压缩、结构化、隔离和失效修复等工具。本期不再增加单点工具，而是把它们组合成 2026 年智能体生产环境中的五层架构：

1. Agent Skills 通过渐进式披露按需加载能力。
2. 滑动窗口与摘要组成混合压缩。
3. 上下文路由在信息进入窗口前拦截无关内容。
4. Agentic RAG、GraphRAG 和 Self-RAG 让检索成为智能体的自主行为。
5. MCP 与 Skill/CLI 按交互类型分工，并共同解决工具定义的上下文成本。

五种模式不是替代关系，而是分层叠加。每层节省一部分 Token，最终把注意力留给真正影响任务结果的信号。

## 五层架构：从按需加载到工具管理

五层架构从底向上解决不同问题：

- **Agent Skills** 决定能力信息如何按需加载。
- **混合压缩** 决定长任务中哪些内容保留原文，哪些内容转为摘要。
- **上下文路由** 决定信息是否有资格进入当前窗口。
- **自主检索** 决定何时检索、采用何种方式以及何时停止。
- **工具管理** 决定模型如何连接外部系统，以及当前应该看到哪些工具。

核心洞察可以归结为一句话：**找到尽可能小、尽可能高信号的 Token 集，最大化期望结果出现的概率。**

## 第一层：Agent Skills 让一个智能体按需切换能力

Anthropic 于 2025 年 12 月发布 Agent Skills 标准。它的核心不是为每个领域建立一个子智能体，而是让同一个智能体在需要时加载专用技能，任务结束后回归基准身份。

### 三层渐进式披露

Agent Skills 的关键是三层加载：

1. **发现层**：启动时只读取技能名和一句描述。资料估算每个技能约占 80 Token，17 个技能的发现成本约为 1700 Token。
2. **指令层**：模型判断某个技能与当前任务相关时，才加载完整指令。
3. **资源层**：只在真正需要执行脚本或查阅参考材料时才进一步加载。

未被触发的技能不占用当前注意力，从而避免把所有领域指令一次性加载到窗口。

### 技能可以从成功经验中演化

智能体反复完成同类任务后，可以观察自己的成功模式，把稳定流程提炼为新的技能文件。人提供初始技能，智能体再从经验中扩展技能库，形成人机协作的演化闭环。Claude Code 中的技能创建功能展示了这种工作方式。

规模化之后会出现新问题。当技能超过 100 个，描述开始重叠，模型容易误激活无关技能。因此，技能库扩张后必须治理技能描述的质量、边界和重复内容。

## 第二层：滑动窗口与摘要的混合压缩

纯滑动窗口会丢失旧信息，纯摘要又会丢失工具调用细节。资料认为，2025 年的生产实践已逐步收敛到混合方案：

- 最近几轮对话和工具调用保留原始格式。
- 较旧内容由 LLM 生成高密度摘要。

近期工具返回不能过早压缩。模型需要看到原始返回值，才能判断下一步；摘要可能保留结论，却丢掉执行节奏和调试线索。

Manus 在多次架构重写中还强调了另一个信号：**尚未解决的失败尝试不要从上下文中删除。** 模型看到自己的错误栈和失败路径后，会修正内部判断，降低重复犯错的概率。

因此，压缩不只是节省 Token，更是一项信号工程：压缩已稳定、已过时的内容，保留会影响当前决策的原始信号。

## 第三层：上下文路由把拦截线前移

前两层关心信息怎样装进窗口，上下文路由则先问：这些信息是否应该进入窗口？

多领域智能体不能把计费、技术支持、退款和入职等所有指令同时加载。正确流程是先对查询分类，再只加载当前领域的指令、知识和工具。无关信息不是进窗口后再修剪，而是根本不进入窗口。

### 四种路由方案

- **LLM 路由**：语义分类更准确，但会增加一次推理调用、延迟和成本。
- **规则路由**：关键词匹配快且便宜，但难以处理规则之外的查询。
- **层次化路由**：先由引导智能体分流，再交给专业智能体，代价是系统结构和调度更复杂。
- **混合路由**：用规则处理稳定模式，用 LLM 处理语义边界，需要同时维护两条路径。

多数生产系统使用 LLM 与规则的混合方案，在准确率、延迟和成本之间取得平衡。

Manus 还采用了更接近底层的方法：不动态增删工具定义，以避免破坏 KV 缓存；而是由状态机在解码层屏蔽当前不可用的工具。它与上下文路由的共同原则是：**并非所有信息都应进入模型上下文。**

## 第四层：RAG 从固定流程进化为自主检索

传统 RAG 是固定流程：查询进入、向量搜索、注入结果、生成答案，一轮结束。智能体时代的核心变化，是让检索从被动的数据搬运变成智能体自主认知的一部分。

### Agentic RAG：自主调整检索策略

Agentic RAG 让智能体决定检索策略。一次搜索不够时，它可以改写查询重试；当前角度不对时，可以更换搜索策略。循环在达到信心阈值或轮次上限时停止。

### GraphRAG：补充跨文档关系推理

GraphRAG 使用知识图谱和社区检测组织实体与关系，补上向量检索难以完成的跨文档关系推理。

### Self-RAG：判断是否需要检索

Self-RAG 让模型判断当前问题是否需要检索，以及检索结果的质量是否足够支持答案。

三者组合后，Agentic RAG 管理搜索策略，GraphRAG 管理关系推理，Self-RAG 管理检索必要性和结果质量。

## 第五层：MCP 与 Skill/CLI 的分工

MCP 是 Anthropic 于 2024 年发布的标准化工具协议，解决智能体如何与数据库、API 和文件系统进行结构化交互。Skill/CLI 走另一条路线：智能体根据 Markdown 技能文件中的指令和命令模板，直接执行命令行工具。

- **MCP**：优势是类型安全、Schema 校验、跨工具编排和企业权限控制，局限是工具定义会占用大量上下文。它更适合查询数据库、调用 API 和需要类型校验的结构化交互。
- **Skill/CLI**：优势是简单、零网络协议开销，并符合开发者的既有习惯；局限是输入输出更非结构化、安全面更大，也更难实现企业权限管理。它更适合写代码、读文件、跑测试和代码审查等执行任务。

资料将两者的关系归纳为分工而非替代：结构化数据交互使用 MCP，执行类任务使用 Skill/CLI。MCP 逐渐聚焦数据层，Skill/CLI 侧重执行层。

不过，MCP 统一了连接标准，却没有自动解决工具定义占用上下文的问题。资料给出的数据是，90 个以上的工具定义可以消耗约 5 万 Token。无论选择哪条路线，真正的问题都是如何只让模型看到当前任务所需的工具。

## 五层如何在生产系统中叠加

一个完整的任务可以按以下顺序流动：

1. 智能体启动时只读取技能元数据。
2. 路由器对用户查询分类，拦截无关领域的信息。
3. 模型加载命中的技能指令、知识和工具。
4. 如果需要外部知识，智能体自主选择检索策略，并根据质量重试或停止。
5. 任务持续进行时，保留近期工具调用和失败证据的原始格式，把旧历史压缩为摘要。

这套架构的目标不是追求更大的上下文，而是让无关信息不进窗口、过时信息不留在热区、关键信号不被有损压缩。

## 总结

本期内容可以归纳为五点：

1. Agent Skills 用三层渐进式加载，让一个智能体按需切换能力，未触发技能不消耗当前注意力。
2. 上下文压缩采用“近期原文加旧历史摘要”的混合方案，尚未解决的失败证据必须保留。
3. 上下文路由把拦截线前移，先分类查询，再只加载相关的指令、知识和工具。
4. Agentic RAG、GraphRAG 和 Self-RAG 分别负责检索策略、关系推理和质量把关，把检索变为智能体的自主行为。
5. MCP 与 Skill/CLI 不是替代关系：结构化交互偏向 MCP，执行任务偏向 Skill/CLI，两者都必须控制模型可见的工具数量。

上下文工程系列到此完结。管好信息只是智能体系统的第一层底座，下一个问题是管好决策流：智能体如何自主循环，什么时候停止，出错后如何回退。这些问题属于 Loop 工程。
