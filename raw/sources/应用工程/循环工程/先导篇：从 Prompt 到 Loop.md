> 循环工程系列 先导篇

如果要用一句话概括 2026 年 AI 工程的变化，那就是：不要再逐句 Prompt AI，而要开始设计能够自己生成 Prompt、自己执行并自己停下来检查的循环。

这个领域叫 Loop Engineering，也就是循环工程。它标记的不是又一个换皮术语，而是人的位置发生了变化：从循环内部操作 Agent，转向循环外部调度 Agent。

## 从 Prompt 到 Loop 的四层预告

先导篇用四层结构概括循环工程建立在什么能力之上：

1. **Prompt**：告诉模型当前要做什么。
2. **Context**：管理模型在当前轮次能够看到什么。
3. **Harness**：提供工具、执行环境、约束和安全边界。
4. **Loop**：让系统自行组织下一轮任务、执行、检查、反馈并停止。

四层不是互相替代。Prompt 负责表达，Context 负责信息，Harness 负责执行，Loop 负责跨轮次的决策流。只有前三层稳定，循环才能可靠运行。

## 从循环里的人肉时钟到循环外的设计者

过去，人坐在循环内部，一句句编写 Prompt。Agent 完成一轮后停下来，等待人的下一条指令。人承担了触发、判断和推进任务的工作，相当于循环里的“人肉时钟”。

循环工程把这些动作交给系统：

- 自行决定下一步任务。
- 自行完成分工与执行。
- 自行把结果反馈给下一轮。
- 自行检查是否需要继续或停止。

人的职责不再是逐轮推动 Agent，而是设计循环的目标、边界、反馈方式和停止条件。

这不是单纯的降本增效，而是工作模式的变化：**从操作 Agent 的人，变成调度 Agent 的人。**

## 循环能力越强，边界越重要

循环能够减少人工逐轮介入，但不会自动消除风险。它运行得越久、权限越大，错误就越可能被带入下一轮并持续放大。

因此，循环工程不仅要设计“怎样继续”，还必须设计：

- **验证机制**：怎样确认每轮结果可以进入下一轮。
- **停止条件**：什么时候任务已经完成，什么时候必须中止。
- **回退机制**：出错后怎样恢复到可信状态。
- **成本边界**：怎样防止 Token 和执行资源失控。

先导篇没有给出这些机制的完整实现，但明确把它们列为循环设计必须偿还的工程账目。

## 总结

四句话说完：

1. Loop Engineering 管理跨轮次决策流，让系统自行生成任务、执行、检查、反馈和停止。
2. Prompt、Context、Harness 和 Loop 构成逐层建立的四层结构，前三层是循环可靠运行的基础。
3. 人的角色从循环里的逐轮操作者，转向循环外的目标、边界、反馈和停止机制设计者。
4. 循环越强，验证、理解、认知和 Token 成本的边界越重要。
