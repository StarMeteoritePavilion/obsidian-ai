> 上下文工程系列 第七期

前六期介绍了如何建设上下文，本期则从相反方向分析上下文如何失效。

上下文会以四种方式失效：毒化（Poisoning）、分心（Distraction）、混淆（Confusion）和冲突（Clash）。它们分别对应错误自我强化、历史淹没知识、噪声干扰信号和矛盾撕裂决策。

底层原则只有一句：**每个 Token 都在消耗注意力。**

## Context Rot：长度与质量共同决定退化

Chroma 团队对 18 个模型进行了 194,480 次调用，把 NIAH 从“找到原文”扩展为四维实验。横轴是上下文长度，纵轴是信号质量。结果显示，没有模型能完全避开上下文退化，即使机械的重复词任务也会随长度增长而下降，只是退化方式不同。

四类失败共同分布在上下文长度与信号质量两个维度上，长度增加和信号质量下降都会带来退化，具体表现因失败类型而异。前六期的检索、压缩、结构化和隔离，本质上都在对抗这种 Context Rot。

## 四类失败案例

### 毒化：幻觉写回后自我强化

毒化最为隐蔽。多轮智能体会不断把工具结果和中间状态写回上下文，一次幻觉就可能污染后续所有判断。

Gemini 玩宝可梦的案例中，模型编造的游戏状态被写入目标区后，智能体开始执着于一个不存在的目标，还会引用已经被污染的信息证明自己正确。错误不再只是一次输出，而是变成后续推理的事实来源。

### 分心：历史压制新的推理

窗口越大，不代表模型越能创新。Gemini 有 100 万 Token 窗口，但超过 10 万 Token 后开始重复历史行为；Llama 3.1 405B 在 32K 就触发分心。

长上下文适合查找已经存在的信息，但多步推理需要从历史中提炼新见解。历史过长时，模型容易重复既有路径，而不是形成新的判断。

### 混淆：无关内容淹没信号

无关内容一旦进入上下文，模型就不得不分配注意力。Llama 3.1 8B 在提供 46 个工具时直接失败，减少到 19 个工具后恢复，而此时窗口仍在 16K 以内。

问题不是容量耗尽，而是工具定义产生的噪声淹没了任务信号。

### 冲突：早期结论撕裂后续决策

分阶段提示实验中，信息被分片提供，而不是一次给齐。OpenAI o3 的成绩从 98.1 降到 64.1。模型在信息不完整时提前形成错误结论，后续补全信息也很难纠正。

智能体每轮分阶段接收信息，天然容易遇到同类问题：旧结论留在上下文里，与新事实持续冲突。

## 四维 NIAH：真实长上下文比找原文更难

Chroma 团队把标准 NIAH 扩展为四个维度：

1. **语义匹配**：经典 NIAH 依赖词汇匹配，问题和答案换成语义相同但用词不同的表达后，长上下文性能明显下降。真实检索文档不会恰好复用问题中的词。
2. **干扰项**：只加入 1 个意思相近但内容不同的句子就会降低性能，加入 4 个后复合恶化，而且不同干扰项的破坏力并不相同。
3. **针与草堆的语义相似度**：针融入同领域草堆时并不会更容易找到。在论文草堆中，领域内的针反而更难识别。
4. **草堆结构**：逻辑连贯的原文比句子打乱后的文本更难检索，18 个模型表现一致。连贯的逻辑流本身也可能成为干扰。

## 四类模型的退化表现

- **Claude：保守型**。找不到时倾向于拒绝回答。
- **GPT：自信型**。GPT-4o 和 GPT-4.1 在干扰下仍会自信作答，甚至编造。
- **Gemini：退化型**。Gemini 2.5 Pro 超过 100K 后可能输出随机字符。
- **Qwen：失控型**。Qwen3-8B 在 5000 词后会说“我需要休息”。

不存在完全避免退化的模型，不同模型只会呈现不同的失败方式。

## 六种解决方法

### 1. RAG：替换毒化数据

上下文被幻觉污染后，重新检索外部知识，用可追溯的事实替换幻觉数据。RAG 不只是补知识，也承担筛选和纠错作用。

### 2. 工具负载：减少工具混淆

把工具定义存入向量库，按当前任务只检索相关工具。资料图表显示，DeepSeek-v3 将工具限制在 30 个时，准确率提升 3 倍；资料旁白称，Llama 3.1 8B 加入工具推荐器后，一项指标提升 44%、功耗降低 18%、速度提升 77%。

### 3. 上下文隔离：阻断混淆与冲突

让子智能体使用独立上下文探索，主智能体只接收蒸馏摘要。资料引用 Anthropic 的结果称，多智能体系统比单智能体提升约 90%（图表标注 90.2%）。隔离使局部噪声和错误不会直接污染全局。

### 4. 上下文修剪：删除低价值内容

Provence 模型大小为 1.75GB，可以删除 Wikipedia 文章中 95% 的内容。修剪只作用于文档和历史区段，主指令必须保留，避免在去噪时破坏任务边界。

### 5. 上下文摘要：在分心前浓缩历史

即使窗口容量为 1,000,000 Token，也应在 100,000 Token 时触发摘要。定期浓缩历史，让模型基于高密度摘要重新推理，避免长历史压制新判断。

### 6. 上下文外移：把中间推理放到窗口外

为模型提供便签本或 `think` 工具，把中间推理写到上下文之外，需要时再检索。特定基准中，这种方法提升 54%。它最适合三类场景：工具输出需要回溯、政策密集任务需要反复验证，以及顺序决策中每一步都依赖上一步。

## GraphRAG：补上全局意义

向量 RAG 擅长找到语义相似的文本块，适合回答“某件事什么时候发生”这类局部事件问题。但“整个数据集的核心主题是什么”需要理解全局结构，不能只靠几个相似片段。

GraphRAG 的流程是：

1. 源文档切成文本块。
2. LLM 从文本块中抽取实体与关系。
3. 构建知识图谱。
4. 使用 Leiden 算法做社区检测。
5. 为各层社区生成摘要。
6. 通过 Map-Reduce 汇总答案，回答全局问题。

在 100 万 Token 数据集上，GraphRAG 的全面性胜率为 72%～83%，多样性胜率为 62%～82%。根层摘要只占原数据 Token 的 2%～3%，节省超过 97%。

GraphRAG 不替代向量 RAG。向量 RAG 负责局部事件，GraphRAG 负责全局主题，两者互补，才能覆盖从局部检索到全局意义构建的完整范围。

## 总结

本期内容可以归纳为八点：

1. 上下文以毒化、分心、混淆和冲突四种方式失效，底层原因都是有限注意力被错误信息、长历史、噪声或矛盾消耗。
2. Chroma 对 18 个模型完成 194,480 次调用，把 NIAH 扩展为语义匹配、干扰项、语义相似度和草堆结构四维实验。
3. 毒化会让错误写回后自我强化，分心会让历史压制创新，混淆会让无关内容淹没信号，冲突会让早期错误结论抵抗新事实。
4. Claude、GPT、Gemini 和 Qwen 会分别表现出保守、自信、退化和失控四种状态。
5. RAG、工具负载、上下文隔离、上下文修剪、上下文摘要和上下文外移是六种独立解法。
6. 修复的核心不是填满窗口，而是持续维护最小、高信号、无冲突的 Token 集。
7. 向量 RAG 解决局部检索，GraphRAG 通过实体图谱、社区检测和 Map-Reduce 补上全局意义。
8. 长上下文能力不是一个窗口数字，而是模型、信息质量和上下文治理共同作用的结果。
