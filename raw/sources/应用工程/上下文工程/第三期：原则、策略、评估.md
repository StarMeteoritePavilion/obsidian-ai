> 上下文工程系列 第三期

这次我们往上走一层。窗口有物理上限，注意力有衰减规律。往这个有限容器里装什么、怎么装、装完怎么验证，就需要一套系统方法论。

本期拆三件套：

- **七项设计原则**：装什么、不装什么。
- **四大策略框架**：从存储、检索、压缩到隔离的完整流水线。
- **三层评估体系**：不再靠感觉“还行”，而是用数字说话。

## 方法论全景

七项设计原则回答往上下文里装什么、怎么组织；四大策略框架回答信息怎么留，通过外部存储、检索选择、压缩优化、隔离组织形成一条完整流水线；三层评估体系回答装得好不好，检索准不准、生成对不对、端到端效果行不行，每层都有量化指标。

这套方法论下面压着一个核心工程隐喻：**注意力预算**。

Transformer 架构下，每个 Token 之间产生 N² 个成对注意力关系。上下文越长，这些关系被拉伸、变薄。所以每一个塞进窗口的 Token 都在消耗注意力资源，必须精挑细选。

七项原则是规则，告诉你选什么、怎么排；四大策略是执行流水线，让信息从外部存储一路流到最终上下文；边界泄漏防护是安全护栏；三层评估是质检站。四个模块环环相扣。

## 注意力预算

Transformer 让每个 Token 关注所有其他 Token，产生 N² 个成对注意力关系。上下文越长，这些关系被拉伸、变薄，模型要维护的信息通道越来越多，每条通道的精度自然下降。

再加上训练数据里短序列天然比长序列多，模型对长上下文的经验更少；位置编码则以精度下降为代价，换取更长的长度。这三股力合在一起，不是让模型突然崩溃，而是制造一个逐渐衰减的性能梯度。

是梯度，不是悬崖。

核心原则就一句话：**找到最小可能的高信号 Token 集。**

## 七项设计原则

七项原则不是让你逐条背，而是让你每次往上下文加内容前形成一套判断习惯。

1. **相关性优先**：这是第一道筛子。不相关信息浪费空间是小事，真正致命的是干扰判断。
2. **信息密度优化**：把 Token 当钱花，砍冗余，用结构化格式替代散文式描述。
3. **结构化组织**：解决模型分不清的问题，用 XML 标签把指令和文档分开。
4. **上下文分层**：按稳定性切分。系统层是模型角色和行为底线，可以缓存复用；知识层按需更新；任务层是当前目标；交互层是这一轮的输入。最稳定的放底层，最动态的放顶层，维护复杂度直接降一半。
5. **显式优于隐式**：用“第三人称”“不用表情符号”“每段不超过三句话”，比“请专业地回答”有用得多。
6. **渐进式提供**：窗口有限，别一次性塞满，需要时才加载。
7. **高度校准**：写得太死就脆、难维护，写得太虚就等于没写。恰到好处的那根线，是给出清晰的行为信号和启发式，而不是硬规则。

## 四大策略

四大策略是一条完整流水线：从信息不在上下文里，到最终干干净净地呈现在模型面前。

### 写入策略

写入策略解决“存”的问题。窗口是短期工作记忆，写入策略把信息存到外部向量数据库、知识库。记忆架构是整条链路的基础。

### 选择策略

选择策略解决“找”的问题。存了海量信息，但窗口装不下，就按需检索最相关的内容。

核心手段是混合检索：语义向量搜意思相近，关键词搜字面匹配，再加一层重排序。这是 RAG 最核心的一环。

### 压缩策略

压缩策略解决“挤”的问题。压缩有四类：

- **抽取式**：保留原文关键句。
- **生成式**：用大模型做摘要。
- **结构化**：把自由文本转成三元组。
- **层次化**：按粒度保留信息。

### 隔离策略

隔离策略解决“分”的问题。用 XML 标签分层指令，分级子智能体、独立上下文，让每类信息待在它该待的地方。

这四个策略是迭代的：检索发现信息不够，触发新写入；压缩丢了关键信息，调整压缩策略。

## 边界泄漏

四大策略协作有一个隐蔽风险：边界泄漏。

写入、选择、压缩，任何一环都可能把一段看起来像指令的文本带进上下文。模型分不清这是用户命令，还是检索文档里的一句话。

后果很严重：

- **提示注入**：外部文本被当成系统指令执行。
- **事实覆盖**：旧记录被当成比新信息更权威。
- **数据串扰**：A 用户的信息混进 B 用户的上下文。

三道防线：

1. **保留元数据**：这段信息哪来的、谁写的、可信度多高。
2. **明确标记**：进入最终上下文后，用标签包住，说明它只是数据。
3. **边界审查**：每个策略边界处审查检索结果有没有夹带指令性文本，摘要有没有丢失来源标记。

## 三层评估体系

怎么知道装进上下文的东西是对的？没有系统评估，优化就是在黑暗中摸索。

三层金字塔从底到顶，成本递增，准确性递增。

### 底层：检索质量

看该找的都找到了没有，第一个结果是否正确，排序质量好不好。

检索是第一道关卡。检索差，生成一定差，垃圾进、垃圾出。

### 中层：生成质量

传统的词重叠指标正被淘汰。现在主流用 Bird Score，基于语义算相似度，或者用更强的大模型当裁判打分。

但发布前必须跟人工评估交叉验证。

### 顶层：端到端评估

人工评估最准，也最贵；A/B 测试看真实用户反馈，这是最终防线。

实践中最推荐 ROGAS 框架，四项指标覆盖检索和生成两个阶段，还能集成到 CI/CD。每次改了 Prompt 或检索策略，自动跑一遍，分数掉了就警报，这才叫工程化。

## 总结

- **注意力预算**是底层隐喻：每个 Token 都在花钱，找到最小、高信号集合。
- **七项原则**是设计直觉：相关性、密度、结构、分层、显式、渐进、校准。
- **四大策略**是工程流水线：写入做存储，选择做检索，压缩提密度，隔离分清楚。
- **边界泄漏**是隐蔽杀手：三道防线从元数据、身份标记到边界审查。
- **三层评估**从检索到生成再到端到端：没有量化就没有优化，RAGAS 是当前的务实之选，接入 CI/CD 才算真正工程化。
