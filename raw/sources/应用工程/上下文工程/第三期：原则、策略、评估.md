> 上下文工程系列 第三期

本期在窗口物理上限与注意力衰减规律的基础上，进一步讨论有限容器应接收哪些信息、如何组织，以及如何验证效果，并建立一套系统方法论。

这套方法论包含三个部分：

- **七项设计原则**：决定纳入或排除哪些信息。
- **四大策略框架**：从存储、检索、压缩到隔离的完整流水线。
- **三层评估体系**：以量化指标替代主观判断。

## 方法论全景

七项设计原则回答上下文应包含哪些信息、如何组织；四大策略框架回答信息如何保留，通过外部存储、检索选择、压缩优化和隔离组织形成完整流水线；三层评估体系回答上下文质量、检索准确度、生成正确性和端到端效果，每层都有量化指标。

这套方法论建立在一个核心工程隐喻之上：**注意力预算**。

Transformer 架构下，每个 Token 之间产生 N² 个成对注意力关系。上下文越长，这些关系被拉伸、变薄。因此，每个进入窗口的 Token 都会消耗注意力资源，需要严格筛选。

七项原则规定信息的选择与排序，四大策略构成从外部存储到最终上下文的执行流水线，边界泄漏防护充当安全护栏，三层评估则负责质量检查。四个模块相互衔接。

## 注意力预算

Transformer 让每个 Token 关注所有其他 Token，产生 N² 个成对注意力关系。上下文越长，这些关系被拉伸、变薄，模型要维护的信息通道越来越多，每条通道的精度自然下降。

再加上训练数据里短序列天然比长序列多，模型对长上下文的经验更少；位置编码则以精度下降为代价，换取更长的长度。这三股力合在一起，不是让模型突然崩溃，而是制造一个逐渐衰减的性能梯度。

是梯度，不是悬崖。

核心原则就一句话：**找到最小可能的高信号 Token 集。**

## 七项设计原则

七项原则无需逐条记忆，其作用是在每次向上下文加入内容前形成一套判断方法。

1. **相关性优先**：这是第一道筛选。无关信息不仅浪费空间，更会干扰模型判断。
2. **信息密度优化**：把 Token 视为成本，删除冗余内容，用结构化格式替代散文式描述。
3. **结构化组织**：解决模型分不清的问题，用 XML 标签把指令和文档分开。
4. **上下文分层**：按稳定性切分。系统层包含模型角色和行为底线，可以缓存复用；知识层按需更新；任务层记录当前目标；交互层承载本轮输入。最稳定的信息置于底层，最动态的信息置于顶层，可以使维护复杂度直接降低一半。
5. **显式优于隐式**：用“第三人称”“不用表情符号”“每段不超过三句话”，比“请专业地回答”有用得多。
6. **渐进式提供**：窗口容量有限，应按需加载信息，避免一次性填满。
7. **高度校准**：约束过于严格会使系统脆弱且难以维护，过于宽泛又无法发挥作用。适当的做法是提供清晰的行为信号和启发式，而非硬性规则。

## 四大策略

四大策略构成一条完整流水线，使上下文之外的信息经过处理后，以清晰形式呈现给模型。

### 写入策略

写入策略解决信息存储问题。窗口属于短期工作记忆，写入策略把信息保存到外部向量数据库或知识库。记忆架构是整条链路的基础。

### 选择策略

选择策略解决信息查找问题。当存储的信息量超出窗口容量时，系统按需检索最相关的内容。

核心手段是混合检索：语义向量搜意思相近，关键词搜字面匹配，再加一层重排序。这是 RAG 最核心的一环。

### 压缩策略

压缩策略解决有限窗口中的信息容纳问题。压缩分为四类：

- **抽取式**：保留原文关键句。
- **生成式**：用大模型做摘要。
- **结构化**：把自由文本转成三元组。
- **层次化**：按粒度保留信息。

### 隔离策略

隔离策略解决信息分离问题。通过 XML 标签划分指令层级，并使用分级子智能体和独立上下文，使每类信息保持在相应范围内。

这四个策略是迭代的：检索发现信息不够，触发新写入；压缩丢了关键信息，调整压缩策略。

## 边界泄漏

四大策略协作有一个隐蔽风险：边界泄漏。

写入、选择和压缩中的任何环节都可能把看似指令的文本带入上下文，使模型无法区分用户命令与检索文档中的普通内容。

后果很严重：

- **提示注入**：外部文本被当成系统指令执行。
- **事实覆盖**：旧记录被当成比新信息更权威。
- **数据串扰**：A 用户的信息混进 B 用户的上下文。

三道防线：

1. **保留元数据**：记录信息来源、作者和可信度。
2. **明确标记**：进入最终上下文后，用标签包住，说明它只是数据。
3. **边界审查**：在每个策略边界检查检索结果是否夹带指令性文本，以及摘要是否丢失来源标记。

## 三层评估体系

判断上下文内容是否正确需要系统评估；缺少评估时，优化无法获得可靠依据。

三层金字塔从底到顶，成本递增，准确性递增。

### 底层：检索质量

检查所需内容是否全部找到、首条结果是否正确，以及排序质量是否达标。

检索是第一道关卡。检索质量不足会直接影响生成质量，即输入质量决定输出质量。

### 中层：生成质量

传统词重叠指标正逐渐被替代。当前主流方法使用 Bird Score 计算语义相似度，或使用更强的大模型充当裁判进行评分。

但发布前必须跟人工评估交叉验证。

### 顶层：端到端评估

人工评估最准确，成本也最高；A/B 测试用于观察真实用户反馈，是最终防线。

实践中最推荐 ROGAS 框架，其四项指标覆盖检索和生成两个阶段，还可以集成到 CI/CD。每次修改 Prompt 或检索策略后自动运行评估，并在分数下降时发出警报，从而形成工程化流程。

## 总结

- **注意力预算**是底层隐喻：每个 Token 都会产生成本，应找到最小的高信号集合。
- **七项原则**是设计直觉：相关性、密度、结构、分层、显式、渐进、校准。
- **四大策略**是工程流水线：写入负责存储，选择负责检索，压缩提高密度，隔离划分边界。
- **边界泄漏**是隐蔽风险：三道防线依次是元数据、身份标记和边界审查。
- **三层评估**从检索扩展到生成和端到端流程：量化是优化的基础，RAGAS 是当前的务实选择，接入 CI/CD 后才能形成完整工程化流程。
