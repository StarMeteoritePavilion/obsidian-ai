> Agent 世界模型：服务于行动的选择性压缩

一个邮件服务器配置案例揭示了 Agent 反复失败的深层原因：Agent 不断修改路由规则，系统却始终返回“查无此人”，直至任务超时。真正的问题并不在某一行路由配置，而在请求进入路由前已经被前置规则拒绝。Agent 对系统处理流程的理解从第一步就错了，因此后续每次修改都在错误的因果图上继续搜索。

这类失败指向一个比“模型是否足够聪明”更基础的问题：Agent 怎样表示自己正在操作的世界，又怎样预测一个动作会让世界发生什么变化。

## 服务于行动的选择性压缩

世界模型不必完整模拟外部世界。对 Agent 而言，它可以被理解为一张压缩图：当前有哪些关键对象和状态，动作会触发哪些变化，哪些反馈意味着成功或失败。这里采用的是比部分论文严格定义更宽的工程口径。

从第一性原理看，世界模型是**服务于行动的、有选择性的压缩**。压缩的关键不在于保留最多信息，而在于保留足以支持下一步判断的信息。进入这张图的信息至少应符合四项标准：

1. 与当前目标相关。
2. Agent 能够影响。
3. 失败后有助于恢复。
4. 可以验证并复用。

David Ha 与 Jürgen Schmidhuber 在 2018 年的《World Models》中，也采用了把复杂环境压缩成关键变量、再预测下一状态的基本思路。工程系统需要回答的并不是“是否完整复制世界”，而是“为了采取正确行动，哪些状态绝不能被压缩掉”。

## 环境、判断与知识三层结构

Agent 与世界的关系可以拆成三层：

- **环境层**是真实网页、代码仓库、服务器或机器人厨房。它客观存在，Agent 只能通过观察和动作获得反馈。
- **判断层**是 Agent 在当前任务中形成的主观压缩图，包括对象、状态、因果关系与下一步预测。它容量有限，而且可能从一开始就错误，也可能在任务进行中失效。
- **知识层**保存代码、测试、文档、规则和已经验证的经验。它更持久，可以在多次任务或多个 Agent 之间共享。

三层不能混为一谈。环境没有因为 Agent 的判断而改变；知识库中存在正确文档，也不等于当前判断已经采用正确流程。最容易被忽略的是判断层：Agent 可能掌握大量知识，却仍然把当前系统状态拼成一张错误的图。

## 记忆会过期，也会保存错误

世界模型依赖记忆，但记忆不是永久有效的事实。API、权限、网页结构和业务规则变化后，旧经验可能从帮助变成误导。相关 `STALE` 基准中，即使表现最强的模型，正确识别过期记忆的比例也只有五成出头；而识别某条记忆已经过期，与实际行动时不再使用它，还是两个不同问题。

《Honest Lying》讨论了另一个风险：模型可能把一段表达得非常自信、实际却错误的总结保存成经验。之后的检索与复用会把一次判断错误放大为持续错误。记忆系统因此不能只负责写入和召回，还必须记录来源、时效、验证状态和失效条件。

## 世界模型也可以是一段检查代码

当主要失败来自明确的非法动作时，系统不一定需要学习一个完整预测模型，一个小型检查器就可能足够。

公开 AI 下棋比赛中，某模型败局的 78% 可以归因于非法走子。即使单步合法率达到 90%，连续走 30 步时，整局保持全部合法的概率也只有约 4%。局部看似较高的可靠率，在长链路中会迅速累乘为整体失败。

`AutoHarness: improving LLM agents by automatically synthesizing a code harness` 让 Agent 自动迭代生成动作合法性检查器。资料展示的结果中，加入检查器后合法动作率几乎达到 100%；在易犯规游戏的对比中，大模型不使用检查器达到 71%，小模型配合检查器达到 94%。这些数字属于对应游戏和实验设置，但说明了一条实用原则：先识别最大的失败来源，再判断一个确定性检查器是否已经足够，不必默认构造完整世界模型。

检查器也不等于真理。训练越依赖检查器，Agent 越可能寻找其判定漏洞；错误检查器还会稳定地拒绝正确动作或放过错误动作。它必须接受独立测试和持续校准。

## 两条构建路线

构建 Agent 世界模型可以沿两条路线推进。

### 把世界写出来

代码、数据库约束和确定性可执行环境适合规则明确、状态可枚举的任务。系统能够在每一步验证动作是否合法、状态是否按预期变化，并在失败时返回精确错误。合法性检查器就是这条路线的最小实现。

它的优势是可解释、可测试和可复现；限制是只能覆盖已经被工程师表达出来的规则。开放网页、自然语言交互和不断变化的外部系统，很难完全写成静态规则。

### 把世界学出来

`Qwen-AgentWorld: Language World Models for General Agents` 代表学习型路线：语言世界模型根据当前状态和动作预演环境反馈，使 Agent 可以在真正执行前比较不同路径。资料转述的实验中，在完全虚构、可控的模拟世界中训练，结果略微超过在真实环境中训练。原因不是模拟天然优于现实，而是模拟器可以稳定制造网络错误、结果只返回一半、分页等真实轨迹中难以均匀采集的意外。

两条路线都越来越依赖合成环境。真正的分歧不是现实与模拟，而是用确定性代码表达世界，还是用学习型语言模型近似世界。后者仍需要大量真实轨迹校准，否则模拟器的偏差会成为 Agent 的新盲区。

## 两个无法绕开的陷阱

第一，验证器和检查器会被利用。只要它参与训练或优化，Agent 就可能学会提高检查分数，而不是真正完成任务。世界模型提供的预测也需要由真实环境和独立评测复核。

第二，世界模型本身也是一种记忆。API 更新、权限调整、规则变化或页面改版都会让原本正确的因果图过期。系统不仅要建立世界模型，还要知道它由什么证据形成、何时验证、哪些变化会使它失效。

## 总结

评价 Agent 世界模型，不应只看它描述了多少对象、规则和状态，而应看它压缩掉了什么、保留了什么，以及这些信息是否真正支持行动、验证和失败恢复。

更真实的模拟器、更聪明的检查器、记忆过期判断，以及“学习模型还是编写代码”，都是同一问题的不同实现路径。不存在适用于所有任务的标准答案；最小而可靠的世界模型，应从当前系统最主要的失败原因出发构建。
