# 词向量：文字变成数字

一个数字常常不够把两类对象分开，一个字也常常不够表示一个词。编号先说明升维怎样让划分变简单，然后说明文字为什么要变成高维向量：人工指定每一维，以及独热编码，都走不远；word2vec 能训练出带相似性的静态词向量；BERT 和 GPT 则把嵌入矩阵随机初始化，并让它跟着模型一起更新。

## 一个数字分不开，两个数字可以

女生的编号是 2、4、8，即 $2=2^1$、$4=2^2$、$8=2^3$，都是 2 的幂次；男生是 1、3、5、6、7。只用这一个数字时，可以用“是不是 2 的幂次”区分性别。换成两个数字之后，只要看第一个数是 0 还是 1，比刚才的规则更简单。对应关系是：1 为 $(1,1)$，2 为 $(0,1)$，3 为 $(1,2)$，4 为 $(0,2)$，5 为 $(1,3)$，6 为 $(1,4)$，7 为 $(1,5)$，8 为 $(0,3)$。粉色的 2、4、8 第一个数都是 0，其余编号的第一个数都是 1。

放到一维数轴上，黑点和粉点交错。一根直线做不到把它们一分为二，或许只能用一根拐得很厉害的线。升到二维之后，同样这些点可以用一条直线切开，第一个数表示性别。第二个数还可以用来表示内向或外向，那样也能用一条直线划分。这是在这个例子上追加的一种用法，不是说第二个数已经被定义成性格。

一个数叫做一维向量，两个数叫做二维向量。就这个例子而言，二维向量表达更灵活，也更容易变得线性可分。把向量从低维变到高维叫做升维，反过来叫做降维。

## 一个词需要足够长的向量

一个数字表示一个字，灵活度不够，需要维度足够多的向量。最小单位先从一个字改成一个词。最终让大模型理解的最小单位叫做词元（Token）；把句子分成词元的过程叫做分词（Tokenize）。

可以给每个位置人为规定一种特征。其中一列是“食物属性”。填完的向量是：

- 我：$45, 1, 8, 62, 3, 8, 42, 99, 23, 12$
- 喜欢：$2, 65, 2, 65, 2, 48, 90, 16, 65, 2$
- 苹果：$22, 23, 89, 51, 12, 31, 11, 28, 3, 45$

食物属性是第三个数：苹果 89，喜欢 2，我 8。苹果的食物属性很高，喜欢几乎没有，我可能稍微有一点。这些是教学例子里的数，不是语料统计出来的。

这些高维向量处在高维空间，不好画。类比到二维时，上面三个词只用前两个数：我 $(45,1)$，喜欢 $(2,65)$，苹果 $(22,23)$。三者离得很远，彼此并不相配。苹果最终可能和香蕉很近，因为都是水果；同时又可能和小米很近，因为都是电子设备。香蕉是 $(24,20)$，小米是 $(19,26)$。更准确的说法不是距离近，而是方向一致。用数学语言说，就是两个向量的点积或余弦相似度较大：

$$
A \cdot B = \sum_i a_i b_i
$$

$$
\cos(\theta) = \frac{A \cdot B}{\|A\| \|B\|}
$$

人工给每个维度规定含义，几乎是不可能完成的任务。每个词的含义和变化太丰富；就算有人把这样的向量做出来，特征含义也可能极其抽象。有一列没有可解释名称，叫做“呜了哇啦属性”；作者、飞天、闪客在这一列上分别是 16、28、99。

## 独热编码量不出相似

另一种极端做法，是让向量维度等于整个词表大小，每个词只有一个位置是 1。这种编码叫做 one-hot，中文是独热编码：只有一个位置是“热”的。作者、飞天、闪客各自只占一位，维度和词表一样大。

这样有两个问题。词表太大会让向量维度太大。不同的词之间也无法度量相似性，因为任意两个不同词的点积或余弦相似度都是 0。

## 含义先空着，用上下文把它训练出来

因此不去规定每个特征到底是什么。每个位置先随机初始化一个值，作为模型参数，再指定一类任务去训练；训练出什么数就是什么数，不必事先解释含义。

所有词的词向量拼成一个大矩阵。纵向是词表大小，横向是每个词的向量维度，一开始都是随机的。准备大量句子作为语料，先分词，选择一个中间词，其余作为上下文词。训练目标是让中间词与上下文词的点积越大越好，同时选出一些不相关的负样本，让它们的点积越小越好。中间词是“飞天”，两边的上下文是“作者”和“闪客”，这两项点积要增大；负样本“帅哥”和“富豪”的点积要减小。大量正负样本之后，这个矩阵就算训练好了。这种方法叫做 word2vec。实际方法里，中心词和上下文词各自使用一个矩阵，这里简化成了一个。

这样训练出的词向量会表现出一些突出效果。为了观察，可以把它们降到三维；相似的词距离很近，还会出现

$$
\mathrm{man} - \mathrm{woman} \approx \mathrm{king} - \mathrm{queen}
$$

投影里的 man、king、woman、queen 就是这个关系上的四个点。这是该演示中的结果，不是普遍的词义定律。

word2vec 有两个主要问题：

1. 静态词向量，与上下文无关。两句是「我喜欢苹果，不喜欢香蕉」和「我喜欢苹果，但更喜欢小米」，其中的“苹果”意思完全不同。
2. 固定矩阵，无法端到端训练。它往往作为下游任务的一个固定输入：文本先经过已经定住的 word2vec 矩阵，再送到下游任务。下游训练时通常固化这份已经训练好的矩阵，作者认为两边有割裂感。

## 嵌入矩阵跟着模型一起变

为了处理这两个问题，并且随着算力提高，后来基于 Transformer 的 BERT 和 GPT 直接随机初始化这个词向量矩阵。它的正式名字是嵌入矩阵（Embedding Matrix），作为进入 Transformer 模块的第一步。结构图里的其余模块这里没有展开。

整个流程是：一句话先分成一个一个词元，在计算机里就是一个一个数字，而且现在可以代表嵌入矩阵中的索引，叫做 ID；再按 ID 取出对应的词向量，正式叫做词嵌入（Token Embedding）；然后送入 Transformer。「作者飞天闪客」分成作者、飞天、闪客，ID 分别是 1、4、6，再从矩阵中取出这三行。「今天天气真」分成今天、天气、真三个词元。这些 ID 和切分都是教学例子。

进入 Transformer 之后的部分还没有展开。嵌入矩阵会随着后续训练不断更新。经历多年演进之后，作者把这个嵌入模型说成最简单的样子：它仅仅是一个随机矩阵。示例代码是：

```python
import torch.nn

vocab_size = 50257
embedding_dim = 768

embedding_matrix = nn.Embedding(
    vocab_size, embedding_dim)
```

其中 768 被用作 GPT-2 的词向量维度。50257 与 768 都写在这段代码里。

文字怎样变成数字，到这里就讲完了。把文字变成数字的模块叫做词嵌入（Token Embedding）。把一句话拆成多个词的过程叫分词（Tokenize），分出的每个单位叫词元（Token）。从下到上是「今天天气真」、词嵌入，以及今天、天气、真三个词元，词向量维度仍是 768。再往上是一个很大的神经网络；输出一侧的词表大小是 50257，其中一个位置是「好」。作者认为，这个神经网络其实是最简单的部分，也是很多初学者对 Transformer 最困惑的地方。下一期再把它具体化，内部这里没有展开。

## 人要决定的是输入和输出的形式

定义问题在这里仍然关键。当前要解决的就是把文字变成数字。变成一个数还是多个数，就这个定义本身可以无所谓；只用一个数的话，后面神经网络的训练和处理都会很不方便。作者认为，AI 里的很多问题都是先把问题定义清楚，再考虑以什么形式把输入和输出交给神经网络，训练才会更方便。人在这里做的努力，是决定一个文字转换成多少个数字比较合适。单个数字不合适；多个数字应该是多少，需要不断实践才能得出，这里没有给出现成的个数。

输出同样可以有很多形式，最终都是要预测下一个词。作者认为，把它当成一个特别大的分类问题比较方便：既能直接得到下一个词是什么，也方便设置策略。例如在前 5 个词里随便选一个，或者只选最大的那一个；其他策略也可以。模型架构不变，只加薄薄的一层筛选就能做到。人所做的努力落在整个问题的输入和输出；不能写成数学公式的部分，仍然交给神经网络。
