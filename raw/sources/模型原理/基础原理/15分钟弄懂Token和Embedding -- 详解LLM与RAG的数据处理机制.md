> “从0开始一起学大模型”合集第六条／Token 与 Embedding 专题

大语言模型接收的是文字，进入模型计算的却不是原始字符，而是经过 Tokenization 和 Embedding 转换后的数值表示。RAG 也使用 Embedding，但它与大语言模型输入端的 Token Embedding 不是同一个训练结果。理解这两层转换，有助于区分离散编号、模型内部向量和用于语义检索的文本向量。

## Tokenizer 把文字转换为离散编号

计算机以离散字符保存文字。资料以 `Apple` 为例：如果模型直接从 `A`、`p`、`p`、`l`、`e` 五个字符学习“苹果”这一概念，就必须先从更细粒度的字符组合中识别词义。在算力有限的条件下，先把常见字词和词片段映射为编号，可以降低模型处理语言的难度。

这些编号就是 Token ID。假设 `1` 代表 `apple`、`2` 代表 `banana`、`3` 代表 `pear`，模型便可以直接处理这组数字。Token 与单词并非严格一一对应：`oldest` 可以拆成 `old` 与表示最高级的 `est`；即使 `goodest` 不是标准单词，模型仍能通过 `good` 与 `est` 的组合处理它。

负责在文字与 Token ID 之间转换的程序称为 Tokenizer。资料列举 OpenAI 的 `tiktoken` 和 Google 的 WordPiece：前者使用 BPE，后者使用 WordPiece 算法；具体实现不同，作用都是把文字切分并映射到词表编号。

Tokenizer 能识别的 Token 总数称为词表大小（Vocabulary Size）。资料以 GPT-2 的 `50,257` 个 Token 为例：其词表对中文覆盖有限，多数汉字各占一个 Token，少见字符甚至需要多个 Token 表示，因此中文处理效率较低。资料又以 `tiktoken` 的 `o200k_base` 为例，指出 GPT-4o 使用约 20 万规模的词表，并将更充分的中文词汇覆盖视为中文处理效率提高的原因之一。

Tokenization 属于数据预处理，不是模型内部的可训练模块；训练大语言模型时，Tokenizer 本身保持固定。

## 单个 Token ID 无法表达多重关系

大语言模型可以近似看作一个复杂的连续函数。资料据此提出一个训练直觉：如果含义相近的输入在数值空间中也彼此接近，模型更容易为它们形成相似输出。

“老王爱吃苹果”“老王爱吃 Apple”“老王爱吃 リンゴ”表达相近含义，但单个数字只有一个排列方向，难以同时表达语言、类别、颜色和形状等多种关系。例如，香蕉与苹果同属水果且都是中文词，香蕉与 `Apple` 则既不是同一对象，也不是同一语言；单一编号无法同时呈现这些不同维度上的远近。

解决方法是把 Token ID 再映射为多维向量。资料用四个可读维度作教学示意：语言、形状、颜色和类别。苹果可以写成 `[1, 1, 1, 1]`，`リンゴ` 为 `[2, 1, 1, 1]`，`Apple` 为 `[3, 1, 1, 1]`，香蕉为 `[1, 2, 2, 1]`。这些人工标签只用于解释向量距离，不代表真实模型中的单个维度具有这些固定含义。

## Token Embedding 是模型的一部分

把 Token ID 转换为多维向量的过程称为 Embedding。资料给出的实例中，GPT-2 XL 的 Embedding 维度为 `1,600`，DeepSeek R1 为 `7,168`；画面同时列出未公开维度的 Gemini 3 与 GPT-5，并由作者猜测这类模型可能已经超过一万维。后一个判断是作者推测，不是厂商公布的架构规格。

资料画面将向量维度标为 `d_model` 或 `n_embed`。更高维度为模型提供了表达更多关系的空间，但真实向量并不是由人手工填写。Token Embedding 是随大语言模型共同训练的参数，模型会在训练中自动形成特征组合并为每个 Token 分配向量。人类目前无法稳定地把每个数字解释为一个独立特征，也无法确认一个特征究竟由单个数字还是多个数字共同表示。

Tokenizer 与 Embedding 的边界由此明确：Tokenizer 把文字转换为固定词表中的 Token ID；Embedding 把 Token ID 转换为模型可以继续计算的连续向量。前者在模型训练期间固定，后者属于模型参数并通过训练得到。

## Embedding 可以视作线性映射

以词表大小 `50,257`、Embedding 维度 `1,600` 为例，每个 Token ID 都可以先写成一个 `50,257` 维的 One-Hot 向量：只有对应位置为 `1`，其他位置均为 `0`。Embedding 随后把这个向量映射为 `1,600` 维表示。

资料使用普通 Linear 层解释这一数学过程：输入是 `50,257` 维 One-Hot 向量，输出是 `1,600` 维 Token Embedding。工程实现不必真的创建完整 One-Hot 向量，也可以直接查表或使用稀疏矩阵；这些实现遵循相同的映射关系。

Transformer 主体继续处理这些向量，最后再用一个 Linear 把输出表示映射到词表空间。资料将这一步类比为 Embedding 的逆向操作：模型内部处理连续向量，输出端重新得到人类程序可以解释为 Token 的词表结果。

## RAG Embedding 与 Token Embedding 的区别

Token Embedding 针对单个 Token，把离散编号映射为模型输入向量；RAG Embedding 针对一段文本，把整段内容压缩为概括其含义的向量，以便比较文本之间的语义距离。

二者都建立在相近的神经网络组件上，却不能通过训练一次模型同时得到。大语言模型的 Token Embedding 随下一个 Token 预测任务训练；RAG Embedding 模型则需要单独训练，并通常在模型输出后加入 Pooling 等处理，把多个位置的表示汇总为一个文本向量。资料还将常见 RAG Embedding 模型概括为不使用因果 Mask 的 Encoder-only／BERT 路线。

两类模型最重要的差异来自训练目标。大语言模型学习文字接龙：输入“老王”预测“爱”，输入“老王爱”预测“吃”，输入“老王爱吃”预测“苹果”。RAG Embedding 模型则学习文本间的语义距离。

以“老王爱吃苹果”为锚点，“小王爱吃香蕉”同样描述某人喜欢某种食物，因此作为正样本，训练目标是缩小两段文本向量之间的距离；“老李找到了女朋友”与前一句无关，因此作为负样本，训练目标是拉大两者的距离。这种方法称为对比学习（Contrastive Learning）。

相近的模型结构在不同训练目标下会形成不同能力。离散 Token ID、Token Embedding 与 RAG Embedding 都以数字承载信息，但它们分别服务于文字切分、模型内部计算和语义检索，不能仅因名称相同而混为一谈。

## 总结

完整链路可以概括为：文字先经 Tokenizer 转换为 Token ID，再经 Token Embedding 进入连续向量空间，经过 Transformer 计算后映射回词表结果。RAG Embedding 则使用单独训练的模型，把整段文本压缩为便于语义比较的向量。

模型结构提供了处理信息的方式，训练目标决定了这些结构最终学会什么。相同的底层组件在不同数据与目标下形成不同功能，正如相近的起点也会因不同经历产生不同轨迹。
