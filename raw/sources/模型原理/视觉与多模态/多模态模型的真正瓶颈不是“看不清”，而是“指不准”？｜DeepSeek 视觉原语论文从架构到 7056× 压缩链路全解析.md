> 第十期（上）：用视觉原语来思考

DeepSeek-AI、北京大学与清华大学联合发布的技术报告《Thinking with Visual Primitives》，讨论多模态模型怎样把点和边界框用于推理。它指出的关键问题并非模型能否看见更多像素，而是模型能否稳定地说明自己正在引用图像中的哪个对象。

## 从 Perception Gap 到 Reference Gap

多模态模型的常见改进路线主要针对 **Perception Gap（感知缺口）**：提高输入分辨率、动态切图、多尺度局部裁剪，或者增加视觉 Token，让模型看清小目标、文字与遮挡细节。这些方法解决“看不清”，却不能保证模型在语言推理链中稳定引用已经看见的对象。

技术报告把后一类问题称为 **Reference Gap（指代断裂）**。例如，一张图片中有二十个人，模型先说“左边穿红衣服的人”，随后引用“他旁边的人”，最后开始计数。自然语言看似连贯，内部指代却可能已经从对象 A 漂移到对象 B。类似地，模型先找到树上的熊，再讨论“剩下的熊”，长推理链中的“熊”未必仍指向此前定位的视觉实体。

“左边那个”“中间那个”“第二排那个”都不是视觉空间中的精确地址。场景越复杂、相似物体越多、遮挡越严重，这类描述越容易产生歧义。语言变量在纯文本任务中可以承担推理变量，却未必能在连续视觉空间中保持唯一指向。

## 把框和点写进推理链

《Thinking with Visual Primitives》的核心思路，是把点和边界框提升为推理链中的“最小思维单元”。它们不再只是最终检测结果或答案生成后的补充证据，而是在中间推理开始时写入的坐标指针。

以三只熊的计数为例，旧式 Grounded CoT 可能先得到“两只熊在地上”的答案，再绘制边界框证明答案；视觉原语方法则先在推理中写出每只熊对应的框，再根据各框的位置和属性判断哪只在树上、哪两只在地上，最后完成计数。坐标先进入推理过程，后续步骤围绕这些稳定指针展开。

只写“熊”类似一次模糊查询；“熊＋边界框”则相当于为对象建立可追踪 ID。这种能力可以理解为“指代带宽”：模型能够以多高的精度，把语言中的对象绑定到图像坐标。视觉原语的价值因此不是让模型看得更多，而是让模型指得更准。

## 类 LLaVA 架构

系统采用类 LLaVA 架构。图像先由从头训练的 DeepSeek-ViT 编码为视觉 Token，文本问题由分词器编码为文本 Token；两类 Token 拼接后输入 DeepSeek-V4-Flash，由语言模型生成带视觉原语的回答。

DeepSeek-V4-Flash 是总参数 284B、推理时激活 13B 参数的 Mixture-of-Experts 模型。DeepSeek-ViT 支持任意分辨率输入，但任意分辨率不等于把任意数量的视觉 Token 全部送入语言模型。为了平衡性能与计算成本，ViT 输出的视觉 Token 被限制在 81～384；超出范围的图像会在保持长宽比的前提下缩放。

## 两层视觉压缩

视觉链路包含两层压缩：

1. **ViT 端 3×3 空间压缩**：每 9 个相邻 Patch Token 沿通道维合并为 1 个视觉表示。
2. **语言模型端 Compressed Sparse Attention（CSA）**：每 4 个视觉 Token 在 KV Cache 中压缩为 1 个条目。

一张 $756\times756$ 的图像包含 571,536 个像素。使用 $14\times14$ Patch 切分后得到 $54\times54=2,916$ 个 Patch Token；经过 $3\times3$ 空间压缩后，进入语言模型 Prefill 的视觉 Token 减少为 324；CSA 再把它压缩为 81 个视觉 KV Cache 条目：

$$
571{,}536\ \text{pixels}\rightarrow2{,}916\ \text{patch tokens}\rightarrow324\ \text{LLM visual tokens}\rightarrow81\ \text{KV entries}
$$

从原始像素数到最终 KV Cache 条目数的比值为 7,056×。这个数字不是信息论意义上的无损压缩率，而是像素数量与缓存条目数量之间的工程口径。

技术报告针对 $800\times800$ 图像给出的对照中，本文模型使用约 90 个视觉 KV Cache 条目，Claude Sonnet 4.6 约为 870 个，Gemini 3 Flash 约为 1,100 个。在论文选取的七项计数与空间推理评测中，本文模型平均分为 77.2，Gemini 3 Flash 为 76.5。报告明确说明，这些分数只覆盖与论文研究重点直接相关的部分评测维度，不能代表模型整体能力。

## 两类视觉原语

技术报告定义了两种视觉原语：

- **边界框**使用左上角和右下角两个坐标，适合数熊、定位汽车、查找文字等具有明确实体边界的任务。框通常与目标名称绑定，既表示位置，也保留宽度和高度等几何信息。
- **点**使用一个坐标，适合迷宫路径、曲线采样和运动轨迹等难以用单个矩形包围的抽象结构。点输出不一定要求对象名称，因为路径和运动过程可能没有标准实体名。

两类坐标都归一化到 0～999 的离散整数网格。边界框对实体定位更确定、信息更丰富，也能自然退化为点表示；点序列则更适合描述连续位置和拓扑结构。

## 把视觉空间变成可写入的地址空间

框和点不是为了让输出更复杂，而是把视觉空间变成推理过程可以写入和再次引用的地址空间。当模型讨论“这个对象”时，它不只留下自然语言短语，还留下坐标；后续推理可以继续引用同一个位置，从而降低对象指代歧义。

这与人在计数、走迷宫或追踪线路时用手指辅助相似。指点并非因为眼睛看不清，而是因为外部指针可以降低工作记忆负担。《Thinking with Visual Primitives》把这种“边指边想”的机制形式化为多模态模型的 Token 序列，让模型不只在内部模糊关注某个区域，而是把区域坐标明确写出。

本期只解释视觉原语要解决的 Reference Gap、框与点的表示方式、模型架构和视觉压缩链路。模型怎样构造数据、训练专家模型、设计奖励，以及为何在迷宫导航和路径追踪任务上取得相应结果，属于下一期内容，本期没有展开证明。

## 总结

视觉推理的瓶颈不只有感知分辨率。模型即使已经看见对象，仍可能因自然语言指代漂移而在复杂结构推理中失去目标。把框和点作为推理变量，可以为视觉实体和路径建立可重复引用的坐标锚点；而 DeepSeek-ViT 的空间压缩与 DeepSeek-V4-Flash 的 CSA，则控制这种显式视觉推理的 Token 和 KV Cache 成本。
