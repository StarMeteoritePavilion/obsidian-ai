> MoBA：面向长序列的混合块注意力

大模型扩展上下文长度时，标准注意力的计算复杂度会成为主要瓶颈。序列中的每个 Token 都与其他 Token 计算注意力；当输入达到十万乃至百万 Token，计算和显存成本会迅速增加。

静态稀疏注意力通过滑动窗口、扩张注意力等固定模式减少计算，动态稀疏注意力则由 Reformer、Routing Transformer 等方法选择连接。资料认为，前者任务特定性较强、通用性有限，后者训练成本较高且难以扩展。

月之暗面的 MoBA（Mixture of Block Attention，混合块注意力）把 Mixture of Experts 的路由思想应用到注意力机制：先把上下文切成块，再为每个查询 Token 动态选择最相关的 Key-Value 块，只对这些块执行注意力计算。

## 从全量查询转向块级选择

标准注意力相当于为一个问题遍历整本书。MoBA 则先把书切成若干章节，估算问题与各章节的相关性，再从中选出最相关的少数章节进行精细计算。

这种设计包含三个关键动作：

1. **块划分**：把长度为 $N$ 的上下文切成多个固定大小的块，块大小是需要调节的超参数。
2. **动态路由**：用 Top-k 门控从历史块中选出与当前 Query 最相关的若干块。
3. **因果约束**：当前块使用因果掩码，保证生成时不能访问未来 Token；历史块已经发生，可以完整参与计算。

每个查询 Token 不再关注全部上下文，而是关注当前块和动态选出的历史块。选择结果随 Query 改变，不依赖预先固定的稀疏模式。

## 块划分与门控得分

输入的 Query、Key、Value 可以表示为形状为 $N\times h\times d$ 的张量，其中 $N$ 是上下文长度，$h$ 是注意力头数，$d$ 是每个头的维度。设块大小为 $B$，则块数为 $N/B$。

系统先把 Key 和 Value 按 $B$ 拆成多个块，再对每个 Key 块执行均值池化，得到块级表示。当前 Query 与各块表示计算相关性得分，Top-k 门控只保留得分最高的若干历史块。

资料用四个候选块说明路由过程：相关性得分分别为 0.92、0.41、0.80 和 0.55，设置 $k=2$ 后选择第一个和第三个块。其余块不进入后续注意力计算。

## 当前块与历史块的因果边界

MoBA 的因果约束只作用于当前块。当前块中的 Token 按自回归顺序生成，只能看到自身及之前的位置，因此必须启用 causal mask。历史块的内容已经全部出现，不需要再屏蔽块内位置。

路由同样不能选择位于当前时间之后的块。因果块约束与当前块内部的因果掩码共同防止未来信息泄漏。

## 五步计算流程

MoBA 的实现流程可以归纳为五步：

1. 根据门控网络和因果约束，建立 Query Token 与 KV 块的映射。
2. 按选中的 KV 块重新排列 Query，使相同块对应的查询能够并行处理。
3. 分别计算各 KV 块与对应 Query 的注意力输出，使用可变长度 FlashAttention 加速不同长度的计算组。
4. 把 Query 恢复到原始顺序。
5. 通过 online Softmax 合并当前块与多个历史块的注意力输出。

当前块和历史块的注意力需要分别计算：前者启用因果掩码，后者不启用。online Softmax 在合并多个结果时保持统一归一化，而不是简单相加不同块的输出。

## 与全注意力的切换

MoBA 支持稀疏注意力与全注意力模式切换。选择较少历史块时，模型以稀疏方式降低成本；扩大选中范围时，行为逐步接近全注意力。这让同一架构可以根据训练阶段、推理预算和上下文长度调整稀疏程度。

资料将其复杂度概括为从标准注意力的 $O(N^2)$ 降至 $O(N\log N)$。这一结论对应来源所讲解的算法和实验配置，实际成本还受块大小、Top-k、注意力头数和实现方式影响。

## 实验结果与适用边界

资料展示了 Llama-8B-1M-MoBA 与 Llama-8B-1M-Full 的比较。在 AGIEval、BBH、CEval、GSM8K、HellaSWAG、LogiQA、Competition Math、MBPP、MMLU、HumanEval、TriviaQA、LongBench 和 RULER 等任务上，两者结果整体接近，MoBA 在部分任务上更高、部分任务上更低。

例如，MoBA 与全注意力在 RULER 128K 上分别为 0.7818 和 0.7849，在 LongBench 32K 上分别为 0.4828 和 0.4821。这些数字表明来源实验中的效果接近，不代表两种机制在所有模型与任务上等价。

在最长一百万 Token 的 Needle-in-a-Haystack 测试中，资料展示的结果图基本保持绿色，表示模型在不同答案位置和上下文长度下维持较高召回。效率实验则显示，在一百万 Token 上下文下，MoBA 的计算时间相对基于 FlashAttention 的全注意力减少约 6.5 倍。

上述性能、召回和效率数字均来自论文的特定模型、硬件、块划分及 Top-k 设置，不能直接外推到其他部署。

## 未来方向

MoBA 的后续研究重点包括：

- 优化块大小和 Top-k 选择策略，使不同任务能够使用更合适的稀疏程度。
- 扩展到多模态输入，研究图像、文本等不同信息如何参与块级路由。
- 检查复杂推理任务中的表现和泛化能力，确认稀疏选择是否遗漏关键的跨块依赖。

MoBA 的核心价值不是简单删减注意力连接，而是把 MoE 的按需激活方式引入注意力层。它在保持 Transformer 架构与因果生成约束的同时，让长序列计算从全量 Token 交互转向动态选择少数相关块。
