> Engram 参数化记忆查找独立专题

大模型的计算并不均质。数学和代码任务需要多步推理，固定搭配、常见实体和局部模式则更接近记忆召回。传统 Transformer 没有原生查表通道，只能让矩阵计算和 Self-Attention 同时承担这些局部记忆工作。Engram 的核心思路，是增加一条参数化的 N-gram 查找路径，把局部模式召回与 MoE 的动态计算分开。

这项设计不只是加入一张更大的表。它同时处理三类问题：神经网络用复杂矩阵计算模拟查找造成的算力错配，Attention Head 被相邻 Token 和 N-gram 模式占用造成的注意力带宽挤压，以及 MoE 专家参数必须常驻 GPU HBM 带来的容量瓶颈。

## MoE 负责动态计算，Engram 负责参数化记忆

输入 Token 在模型中进入两条并行路径。原有 MoE 路径继续承担动态计算；Engram 路径根据 N-gram 键执行哈希查找，取回训练得到的静态 Embedding。两条路径分别处理需要上下文计算的内容与更适合直接召回的局部模式，再把结果注入 Transformer 主干。

Engram 与 RAG 的边界在于，Engram 表是模型参数的一部分，随模型端到端训练；RAG 则从外部、非参数化的知识库检索文本或其他资料。两者都包含检索动作，但检索对象、训练方式和系统位置不同。

## 从 Token 到记忆注入的六步数据流

### 词表投影统一表面形式

输入 Token 先经过词表投影，统一大小写并去除前导空格等表面差异。视频称这一步使词表规模压缩约 23%。BPE 可能因为空格或大小写差异把同一个词映射为不同 ID；如果不先归一化，同一局部模式会分散到多个表项，查表命中率随之下降。视频转述的消融实验显示，移除词表压缩后性能明显下降。

### 多尺度 N-gram 与多头哈希降低冲突

系统为每个位置构建多个粒度的 N-gram 键，例如 2-gram 和 3-gram，再用多组独立哈希函数查询多张 Embedding 表。单个哈希函数可能把不同短语映射到同一地址；多头哈希让一次冲突不必在其他表中同步发生。多组结果拼接后，形成包含不同局部尺度和查找视角的记忆向量。

### 上下文门控过滤多义与碰撞噪声

查到向量并不代表它适合当前语境。Engram 使用简化的 Cross-Attention 式门控：Transformer 当前层的隐藏状态作为 Query，检索到的记忆向量作为 Key 和 Value，相关性经过 Sigmoid 后得到软门控。

当上下文讨论科技公司时，与 Apple Inc. 对应的记忆可以获得较高权重；当上下文描述日落时，同一表面词形对应的不相关记忆会被压低。哈希碰撞产生的无关向量也可以在连续表示空间中被门控过滤。视频转述的消融结果显示，移除上下文门控后性能大幅下降。

### 深度可分离卷积连接相邻查找结果

每个位置独立查表会使相邻输出出现跳变。轻量级 Depthwise Convolution 沿时间轴平滑并组合相邻结果，把分别查到的局部向量组织成连贯短语表示，随后通过残差连接注入主干。视频称这部分只有约 16K 参数，用于缓解离散查表结果与连续特征空间之间的不匹配。

## 输入确定性让 CPU—GPU 预取成为可能

Engram 的查表地址只依赖输入 Token，不依赖中间层计算结果。GPU 开始计算浅层时，CPU 已经能够确定后续 Engram 层需要哪些表项，并通过 PCIe 从主机内存预取到 GPU 缓冲区。只要前置层计算时间覆盖传输延迟，GPU 到达 Engram 层时数据已经就绪。

放置位置因此同时受效果和系统效率约束。Engram 太靠前时，没有足够计算时间掩盖传输延迟；太靠后时，低级局部特征的注入价值已经减弱。视频给出的结论是在 Layer 2 之后放置较合适。

视频转述的系统实验把 100B 参数的 Engram 表全部放入 CPU 内存，使用 H800 推理 8B 模型。开启预取后，吞吐从每秒 6,315 Token 降至 6,140 Token，下降 2.8%。视频同时称 DDR5 每 GB 成本约为 HBM 的五十分之一。该结果说明输入确定的稀疏查找可以利用分层内存，但数字只适用于资料所述的模型、硬件和流水线设置。

## 等预算实验把专家参数换成记忆参数

对照实验让 MoE-27B 基线与 Engram-27B 都保持 26.7B 总参数和 3.8B 激活参数。Engram 版本把路由专家从 72 个减至 55 个，将省出的 5.7B 参数分给查表记忆。收益因此来自同一总参数与激活参数预算下的重新分配，而不是单纯增加模型规模。

知识密集型任务的结果符合查表模块的直接目标：MMLU 提高 3.4 个百分点，CMMLU 提高 4.0 个百分点。视频强调的反直觉结果出现在推理和代码任务：BBH 提高 5.0 个百分点，ARC-Challenge 提高 3.7 个百分点，HumanEval 提高 3.0 个百分点。这些增量属于对应实验，不能直接外推到其他模型规模或任务。

视频根据 LogitLens 和 CKA 分析解释这一现象。Engram 注入后，中间层预测 Loss 更早下降；CKA 热图中，Engram 模型第 5 层的表示与基线模型第 12 层高度相似。作者据此认为，Engram 让浅层更早完成局部模式与基础语义处理，使后续层能够把更多容量用于复杂推理。这是资料对实验现象的机制解释，不等同于对每个内部表示的直接语义读取。

## 长文本收益不由预训练 Loss 差异解释

多针大海捞针任务从 84.2 提高到 97.0，变量追踪从 77.0 提高到 89.0。视频还指出，在预训练 Loss 对齐的条件下，Engram 的长文本结果仍明显领先，因此把收益归因于架构对注意力带宽的释放，而不是训练 Loss 更低。

进一步的 Engram-40B 验证把查表记忆扩大到 18.5B 参数，总参数达到 39.5B，激活参数仍为 3.8B。视频称性能继续提升，认为对应实验范围内的记忆容量 Scaling 尚未饱和。总参数扩大而激活参数不变，并不表示端到端推理的内存访问和通信成本完全消失。

## MoE 与 Engram 的参数比例存在中间最优点

在固定总参数和计算量的实验中，性能随稀疏参数中 MoE 占比呈倒 U 型变化。视频给出的较优范围约为 75%～80% 分配给 MoE、20%～25% 分配给 Engram。全部交给 MoE 时，神经网络仍需承担大量局部记忆；全部交给 Engram 时，动态专家容量不足，复杂逻辑能力下降。

作者把这一结果解释为语言建模中约 20% 的工作更接近记忆或模式匹配、约 80% 更依赖动态计算。这一比例来自资料对特定实验曲线的物理解释，不是不同领域和部署条件下的固定法则。法律、医疗等知识密集任务与代码生成等逻辑密集任务，是否需要不同配比，仍是视频明确提出的待验证问题。

## 工程启示与尚未验证的方向

视频提出两项工程启示。端侧设备通常拥有相对充足的系统内存而算力较弱，Engram 可以用内存容量换取部分动态计算；领域知识也可能通过外挂 Engram 表增强，而不重新训练主干。

视频还提出两个研究方向：直接改写 Embedding 表项以实现低成本 Model Editing，以及把类似查表机制扩展到多模态向量 Patch，以降低部分视觉编码开销。这些内容是后续设想，不是本视频已经验证的结论。
