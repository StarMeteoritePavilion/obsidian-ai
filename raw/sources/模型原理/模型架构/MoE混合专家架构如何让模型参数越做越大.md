# MoE混合专家架构如何让模型参数越做越大

Scaling Law 推动模型参数量、训练数据与算力共同增长，但稠密模型扩大参数时，每个 Token 需要执行的计算也会增加。Mixture of Experts（MoE，混合专家）采用稀疏激活：模型可以保存大量专家参数，而每个 Token 只经过少量被选中的专家，从而把总参数量与单 Token 活跃计算量分开。

资料发布时将 DeepSeek、Qwen 和 Kimi 列为采用 MoE 的开源旗舰模型，并以 Hugging Face 的《混合专家模型（MoE）详解》作为主要参考之一。

## Dense FFN 为什么随参数一起增加计算

资料所示 Transformer Decoder 主要包含 Masked Multi-Head Attention 和 Feed-Forward Network（FFN）。Attention 在 Token 之间交换上下文信息，FFN 再独立处理每个 Token 的上下文表示。

假设输入包含 $n$ 个 Token，每个 Token 的向量维度为 $d$，输入矩阵 $X$ 的形状就是 $n\times d$。FFN 先乘以上升维矩阵 $W_1$，将向量扩展到中间维度 $d_{ff}$；经过非线性激活函数后，再乘以下降维矩阵 $W_2$，恢复为 $n\times d$ 的输出：

$$
Y=\sigma(XW_1)W_2
$$

其中，$W_1$ 的形状为 $d\times d_{ff}$，$W_2$ 的形状为 $d_{ff}\times d$。单个矩阵无法完整替代这个 FFN，因为中间的激活函数使整体成为非线性变换。

Dense Model 让所有 Token 使用同一套完整 FFN，所有相关参数都会参与计算。加宽 FFN 可以增加模型容量，也会同步提高每个 Token 的计算量。

## Sparse Model 动态选择计算路径

MoE 将原来的 FFN 扩展为多个专家网络。每个专家都是一套独立 FFN，但当前 Token 只进入其中一部分，其他专家不会参与这次计算。

资料用 `What is 1 + 1 ?` 说明这种稀疏路径，并将四个专家分别标为标点、动词、连词和数字专家。当输入与数字最相关时，只激活数字专家。这里的名称用于解释动态选择，并不表示专家功能必须由人预先指定。

Dense Model 与 Sparse Model 的差别由此落在活跃路径上：前者让完整 FFN 处理每个 Token；后者可以继续增加专家总数，却不必让每个 Token 激活同样多的专家。

## Router 怎样选择专家

MoE 使用 Router 为 Token 分配专家。资料将 Router 表示为一个小型 FFN 后接 Softmax：输入是 Token 向量，输出是当前 Token 对每个专家的选择概率。若共有 $E$ 个专家，$n\times d$ 的输入会得到 $n\times E$ 的路由分数矩阵。

在 Top-1 示例中，四个专家的概率分别为 `0.45`、`0.19`、`0.05` 和 `0.31`，因此选择第一个专家。该专家的输出再乘以 `0.45`，形成 MoE 层的最终输出。

直接取最大值的选择动作本身无法求导；把选中概率乘入输出后，概率进入最终算式，梯度可以沿这条乘法路径回传到 Router 参数。这使模型能够在训练中调整路由评分。

## 一次完整的前向计算

资料用 6 个 Token、4 个专家展示前向计算的五个步骤。

1. **输入**：6 个 Token 组成 $6\times d$ 的矩阵。
2. **路由打分**：Router 输出 $6\times4$ 的概率矩阵，每行对应一个 Token 对四个专家的选择概率。例如，T1 对第二个专家的概率最高，为 `0.62`；T2 对第一个专家的概率最高，为 `0.70`。
3. **分发（Dispatch）**：按路由结果重新组织 Token。T2、T5 进入 Expert 1；T1、T4、T6 进入 Expert 2；T3 进入 Expert 4；Expert 3 没有收到 Token。
4. **专家计算与加权**：各 Expert 对自己的输入矩阵执行 FFN，再将每个 Token 的结果乘以对应路由概率。
5. **合并（Combine）**：按照原始 Token 顺序重新排列专家输出，恢复为 $6\times d$ 的矩阵。

分发与合并在结构上类似 MapReduce：先按计算路径重组输入，各专家独立处理，再把结果恢复到原位置。每个专家收到多少 Token 完全由当前数据和 Router 决定，因此负载天然可能不均衡，甚至有专家没有输入。

## Top-K 路由混合多个专家

只选择一个专家会限制表达能力。当多个专家分数接近时，很小的分数差异还可能让 Token 走向完全不同的路径。实际示例因此采用 Top-K 路由：选出得分最高的多个专家，让它们分别计算，再对选中分数归一化并加权合并。

若前两个分数为 `0.45` 和 `0.31`，它们的和为 `0.76`，归一化后的权重分别为：

$$
\frac{0.45}{0.76}=0.59,\qquad \frac{0.31}{0.76}=0.41
$$

最终输出由两个专家结果按 `0.59` 与 `0.41` 加权求和。资料列举的发布时配置中，DeepSeek-V4 从 384 个专家中选择 6 个，Kimi-K3 从 896 个专家中选择 16 个。这些数字属于对应模型示例，不是 MoE 的固定 Top-K 设置。

## 负载不均怎样形成专家坍塌

Router 在训练开始时随机初始化。某个专家若碰巧收到更多 Token，就会获得更多梯度并更快更新；Router 随后更愿意继续选择它，使其再次获得更多训练。这个正反馈会让流量逐渐集中到少数专家，其他专家因为很少被选中而几乎得不到训练。

这种 Expert Collapse 会浪费大量专家参数，也会让模型过度依赖少数计算路径。负载均衡的目标是让各专家收到的 Token 尽量接近，使所有专家都有机会训练。

## Auxiliary Loss 约束专家负载

资料用两个量描述一批 Token 对第 $i$ 个专家的路由情况。$P_i$ 是 Router 分配给该专家的平均概率，$f_i$ 是该专家被实际选中的频率：

$$
P_i=\frac{1}{n}\sum_{x\in B}p_i(x)
$$

$$
f_i=\frac{1}{n}\sum_{x\in B}\mathbf{1}\{\arg\max p(x)=i\}
$$

若专家总数为 $E$，Auxiliary Loss 定义为：

$$
\operatorname{Auxiliary\ Loss}=\alpha E\sum_{i=1}^{E}f_iP_i
$$

不均衡示例的平均概率为 `[0.58, 0.19, 0.11, 0.12]`，实际选择频率为 `[1.00, 0.00, 0.00, 0.00]`。暂不计系数 $\alpha$，画面给出的 Auxiliary Loss 为 `2.33`。这表示第一个专家吃掉了全部流量。

均衡示例的平均概率为 `[0.28, 0.23, 0.27, 0.22]`，实际选择频率为 `[0.25, 0.25, 0.25, 0.25]`。在同一归一化口径下，Auxiliary Loss 为 `1.00`。把这项损失加入总损失，可以在训练中推动专家计算逐渐趋于均衡。

## 总参数量与活跃计算量分离

Dense Model 通过加宽同一个 FFN 增加参数，加宽多少，每个 Token 的 FFN 计算量就相应增加。MoE 则增加专家数量，并让每个 Token 只激活固定数量的专家。在这一抽象计算口径下，专家总数可以继续增长，而每个 Token 的活跃专家数不必同步增长。

MoE 的核心不是让全部参数同时工作，而是由 Router 为不同 Token 动态选择少量计算路径，再通过概率加权合并结果。模型总参数量与单 Token 活跃计算量因此成为两个需要分别观察的指标。
