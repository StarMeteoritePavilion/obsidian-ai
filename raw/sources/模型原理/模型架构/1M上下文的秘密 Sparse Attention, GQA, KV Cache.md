> “AI技术”合集／长上下文注意力独立专题

近年的大语言模型不仅持续增加参数、调整架构，也在扩展上下文长度。资料以 GPT-3 时代约 2,000 Token 的上下文为起点，指出当前旗舰模型已经把百万级上下文作为重要指标。长上下文缓解了 AI 应用中的信息容量问题，却不是可以无成本扩展的能力。DeepSeek Sparse Attention（DSA）、MiniMax Sparse Attention（MSA）和 Kimi MoBA 等技术，都在尝试控制超长上下文带来的计算与显存开销。

## 长上下文首先受计算成本限制

主流大语言模型采用多头注意力。以“我是老王”三个 Token 为例，注意力先为每个 Token 计算 Query、Key 和 Value。生成下一个 Token 时，最后一个位置的 Query 分别与各个 Key 计算关联度，经过 Softmax 转换为权重，再用权重对相应 Value 加权求和，得到注意力输出。

模型生成“你好”后，会把已有上下文与新 Token 一起用于下一轮生成。资料用简化比例说明单步解码成本：如果长度为 1 的上下文对应 1 份计算，那么长度为 100 万的上下文，生成下一个 Token 就需要处理约 100 万份历史信息。这个比例用于解释解码阶段随上下文增长的压力，不是完整模型 FLOPs 的精确公式。

上下文越长，生成每个新 Token 时需要参与注意力的历史位置越多。这是长上下文昂贵的第一个原因。

## KV Cache 用显存换取重复计算

自回归生成过程中，已有 Token 对应的 Key 和 Value 不会在每一步发生变化。如果每生成一个新 Token 都重新计算全部历史位置的 K 和 V，会浪费大量资源。KV Cache 把这些结果保存下来，后续步骤直接复用。

Query 不按相同方式缓存。资料的解释是：当前 Query 只在生成当前下一个 Token 时使用一次。例如，“老王”位置的 Query 用于生成“你好”，完成这一步后便不再承担后续查询角色；保存它没有同等复用价值。

KV Cache 降低了重复计算，却引入第二项成本：上下文越长，需要保存的 K 和 V 越多，显存压力越大。

多头注意力进一步放大这项成本。Token 之间不仅存在单一关系，例如“老王”和“我”之间既可以有指代关系，也可以有语法关系。模型通过多个注意力头学习不同投影视角，常见规模包括 32、64 个乃至更多头；如果每个头都保存独立的 K 和 V，计算与缓存都会随头数增长。

## GQA 让多个 Query Head 共享 KV

资料用教学类比区分三种向量的作用：K 和 V 描述 Token 相对稳定的属性，Q 决定当前注意力头从哪个角度查询这些属性。这个类比用于解释设计动机，不代表真实向量中的维度可以直接命名为名词、宾语或指代关系。

Grouped-Query Attention（GQA，分组查询注意力）保留多个 Query Head，却让一组 Query Head 共享同一份 K 和 V。模型接收新 Token 后仍计算多组 Q，每组 Q 再与所属组的共享 KV 完成注意力计算。

资料给出的示例包含 64 个注意力头。传统多头注意力需要保存 64 份 K 和 V；采用 GQA 后，把这些头分成 4 组，每组 16 个 Query Head 共享一份 KV，只需保存 4 份。对应 KV 缓存降至原来的 $4/64=1/16$。资料认为该示例对输出效果的影响并不明显，但这个判断属于所述架构取舍，不能脱离模型和训练条件视为固定结论。

GQA 主要压缩 KV Cache。每个 Query Head 仍需计算 Q，并与共享 KV 分别执行注意力，因此主注意力的计算量并没有按相同比例下降。

## Sparse Attention 只精算高贡献位置

注意力经过 Softmax 后，大部分历史位置的权重可能非常接近 0。资料展示 GPT-2 处理“我是老王”时第一层 Attention 的 Softmax 结果，用来说明许多位置经过 Value 加权和求和后，对最终输出的贡献很小；全量计算这些位置仍会消耗算力。

Sparse Attention 在主注意力之前增加较小的打分注意力层，先为历史 Token 估计重要程度，再选取得分最高的 Top-N 位置进入主注意力。若当前头主要处理指代关系，“我”和“老王”可以获得较高分数，“你好吗？”中的 Token 则得分较低并被排除。

筛选把主注意力实际处理的位置数控制在相对稳定的范围内。即使总上下文继续增长，只要 Top-N 数量不变，进入主注意力的 Token 数量就不会同比增长。

## DSA 按 Token 选择，MSA 按块选择

DeepSeek Sparse Attention（DSA）按照 Token 的重要性得分选择 Top-N Token。资料用“你好吗？我是老王”演示：打分注意力分别给各 Token 评分，主注意力只接收得分最高的位置。

MiniMax Sparse Attention（MSA）进一步按顺序把 Token 分块，资料给出的实际分块示例是每 128 个 Token 一块。每个块使用块内最高的 Token 分数作为整体得分，再选取得分最高的 Top-N 块进入主注意力。

为便于展示，资料把每块缩小为三个 Token：“你好吗？”一块的最高分为 5，“我是老王”一块的最高分为 10，因此后一块被选入主注意力。DSA 控制选中 Token 的数量，MSA 控制选中块的数量；两者都通过限制主注意力的实际输入规模来控制长上下文计算。

## 打分注意力仍然需要处理完整上下文

稀疏筛选没有消除全部成本。打分注意力仍需接收所有历史 Token；上下文越长，它的计算量和显存占用也会增长。区别在于，这个模块只负责打分，不生成后续 Token，规模通常比主注意力小得多。资料将两者的规模差距概括为几十倍，因此把当前资源消耗视为仍可控制。

打分层还可以继续复用主注意力的优化。例如，不同主注意力对应的打分注意力也可以采用 GQA 分组合并，以进一步减少显存占用。相关架构仍在演进，GQA 和 Sparse Attention 不是长上下文优化的终点。

## 上下文已经成为模型能力的基础

长上下文不再只是用来展示规格的指标。它决定模型能够在一次任务中保留多少历史、失败尝试和未完成线索，也直接影响 AI 应用能够处理的问题规模。

资料以一个开放性的想象作结：当未来的人类面对耗尽心智也无法翻越的高墙，或许被不断拉长的上下文会帮助记录每一次失败的尝试，并留下“故事还在继续，我们还有机会”。
