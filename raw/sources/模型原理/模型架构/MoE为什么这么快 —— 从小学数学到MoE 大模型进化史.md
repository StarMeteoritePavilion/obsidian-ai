> 模型架构／混合专家独立专题

DeepSeek 模型为什么速度快、Token 价格为什么较低，可以从大模型内部的前馈神经网络一路追溯到 MoE（Mixture of Experts，混合专家）架构。核心变化并不是让所有参数参与每次计算，而是用路由器为当前输入选择少量专家，在扩大模型总容量的同时控制实际计算量。

## 从线性层到前馈神经网络

线性层接收 $m$ 个数字并输出 $n$ 个数字。每个输出都是输入分别乘以不同系数后求和，再加上一个常数：

$$
y=Wx+b
$$

其中，$W$ 中的系数和 $b$ 中的常数都是模型参数。只有乘法与加法的线性层只能表达线性关系；现实数据通常不是简单直线关系，因此神经网络会连接多个线性层，并在中间加入 ReLU、Sigmoid 等非线性激活函数。

资料将这种线性层与激活层的组合称为前馈神经网络（Feed-Forward Network，FFN）。只要层的宽度和深度足够，理论上可以表示非常丰富的函数。数字图片识别等不依赖上下文的任务，就可以由这样的网络完成。

## 单独的 FFN 无法理解上下文

大语言模型需要根据已有 Token 预测下一个 Token。假设输入是“老王爱”，模型先将三个 Token 转换为 Embedding，再预测后续内容。单独按位置处理的 FFN 只能看到当前位置的输入：如果“爱”总映射到“吃”，那么“老王爱”与“恋爱”中的“爱”就会得到相同处理，它无法知道前面跟的是“老王”还是“恋”。

Attention 解决了这个问题。它先把当前位置与已有上下文融合，使“老王爱”中的“爱”成为包含“老王”信息的上下文表示，再交给 FFN。FFN 本身仍按位置执行，但接收到的输入已经带有上下文，因此能够对同一个字在不同语境中产生不同输出。

## Dense 模型用全部参数处理每个 Token

上下文加入后，FFN 需要处理的输入组合急剧增加。早期的大模型通过继续扩大线性层来提升容量，资料以 GPT-3 和 LLaMA 为例，将这类方案称为 Dense（稠密）模型。

在稠密 FFN 中，每个 Token 都经过同一组庞大参数。无论问题讨论数学还是个人爱好，推理时都要执行完整网络，训练时也会调整整个稠密结构。扩大参数可以提升模型容量，也会同步增加每次计算的成本。

## MoE 把一个大 FFN 拆成多个专家

2017 年的《Outrageously Large Neural Networks: The Sparsely-Gated Mixture-of-Experts Layer》提出稀疏门控混合专家层。它把一个大型 FFN 拆成多个较小的 FFN，每个小网络称为一个 Expert。

资料以 DeepSeek-V3 为例：一个 MoE 层包含 256 个路由专家，每个 Token 只选择其中 8 个参与计算。把某个专家称为“数学专家”或“情感专家”只是教学类比；专家擅长处理什么并非由人类手工指定，而是在训练中形成，其内部含义通常无法直接解释。

## Router 为每个 Token 选择专家

Attention 生成上下文表示后，Router（路由器）为所有专家计算分数。资料中的 Router 是一个普通线性层：分数越高，表示该专家越适合处理当前 Token。系统选出分数最高的若干专家，再把这些分数转换为权重。

选中的专家分别处理同一输入。每个输出乘以对应权重，最后加权求和，得到 MoE 层的输出。“Mixture”描述的就是多个专家结果按权重混合的过程。

不同 MoE 模型选择的专家数量和权重计算方法并不相同。DeepSeek-V3 选择 8 个路由专家，只是该模型的具体配置，不是所有 MoE 的统一规则。

## Dense 与 MoE 的计算取舍

在总参数规模相同时，Dense 模型每次使用全部 FFN 参数，MoE 则只激活与当前 Token 对应的少量专家，因此实际参与计算的参数更少。代价是未选专家不会参与当前输出；资料据此指出，相同总参数规模下，MoE 的表现通常可能不及 Dense，但稀疏激活可以换取更高计算效率。

DeepSeekMoE 论文中的对比表提供了一个具体设置：

- DeepSeek 67B Dense 模型共有 67.4B 参数，每次激活 67.4B；每 4K Token 的 FLOPs 为 2057.5T，Pile Loss 为 1.905。
- DeepSeekMoE 145B 模型共有 144.6B 参数，每次激活 22.2B；每 4K Token 的 FLOPs 为 585.6T，Pile Loss 为 1.876。

资料把这组结果概括为：MoE 使用两倍多的总参数容量，以约三分之一的活跃参数计算量，得到与 Dense 接近的效果，并将其描述为“用约两倍空间换取约三倍性能”。表中记录的是参数、FLOPs 与训练 Loss，不等同于所有硬件和部署环境中的固定三倍端到端速度。

## 共享专家保存通用知识

除 Router 选出的路由专家外，DeepSeek 还引入共享专家。共享专家不经过路由筛选，每个 Token 都会使用，用于承载多个输入都可能需要的通用知识。

一个完整 MoE 层因此同时包含两条路径：共享专家始终参与，路由专家按 Token 动态选择；各专家结果经过加权求和后共同形成输出。

## 从上下文到稀疏计算

这条架构演进可以归纳为三个阶段：

1. FFN 负责把输入映射为输出，但单独按位置处理时无法理解文本上下文。
2. Attention 先融合上下文，再把包含语境的信息交给 FFN。
3. MoE 把庞大的稠密 FFN 拆成多个专家，由 Router 为每个 Token 选择少量路由专家，并结合共享专家完成计算。

MoE 的关键不是创造全知全能的单个专家，而是承认每个专家的局限，通过路由和加权组合使用不同能力。它扩大了模型总容量，却避免让全部参数在每个 Token 上同时运行。

## 总结

MoE 的速度优势来自稀疏激活：模型可以保存大量专家参数，但一次推理只调用少数路由专家和固定共享专家。总参数决定可容纳的能力规模，激活参数更直接影响单次计算量，两者不能混为一谈。

这种方法没有消除成本，只是把问题从“所有参数每次都计算”改为“保存更多专家，并为每个 Token 做正确路由”。最终取舍需要同时观察总参数、激活参数、专家选择和路由结果，不能只依据模型总参数判断。
