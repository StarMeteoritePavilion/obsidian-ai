# 提示词工程：从单轮指令到生产规范

## 总体框架

提示词工程可以按任务难度逐级增加机制，而不是一次堆满技巧：

1. 用清晰指令和输出格式完成零样本任务。（[[wiki/sources/提示词工程：第一期 提示词工程入门|第一期]]）
2. 当模型不理解任务模式时，加入少量一致、相关且多样的演示。（[[wiki/sources/提示词工程：第二期 少样本提示|第二期]]）
3. 当任务需要多步推导时，提供推理过程或要求分步处理。（[[wiki/sources/提示词工程：第三期 让 AI 先想再说|第三期]]）
4. 当单条路径不稳定时，使用多次采样投票；当任务本身过大时，拆成可检查的串行步骤。（[[wiki/sources/提示词工程：第四期 多步编排|第四期]]）
5. 当模型已有知识需要显式唤起时使用生成知识提示；缺少外部知识、精确计算或行动能力时，引入检索、解释器与工具。（[[wiki/sources/提示词工程：第五期 知识增强与工具调用|第五期]]）
6. 生产化时再补上结构化分区、system prompt、证据约束、长上下文排序和输出控制。（[[wiki/sources/提示词工程：第六期 Anthropic 工程规范|第六期]]）

> [!warning] 适用边界
> 第一至第三期资料都强调，提示和推理方法受模型基础能力与规模约束；资料中的具体参数门槛未做外部复核。

## 选择原则

| 问题 | 最小可用方法 |
| --- | --- |
| 任务简单且模型已理解 | 零样本指令 |
| 输出格式或标签不稳定 | 少样本演示 |
| 需要多步推导 | 思维链 |
| 推理偶发走偏 | 自我一致性 |
| 单次任务过于复杂 | 链式提示 |
| 需要显式唤起模型已有背景知识 | 生成知识提示 |
| 缺少实时事实或精确计算 | 检索、解释器或工具调用 |
| 需要团队复用与迁移 | 结构化提示，并在迁移前核对对应模型的官方文档 |

综合判断：优先从能完成任务的较简单方法开始，在出现明确失败类型后再增加机制。自我一致性、思维树、链式提示和工具工作流会增加 Token、延迟或维护成本，是否采用应结合任务评测决定。
