# 多模态推理闭环：感知、指代、操作与验证

多模态推理至少包含四个环节：把像素编码为模型可处理的表示，在语言与视觉之间建立明确指代，按任务需要生成或修改视觉中间状态，再用结果与过程信号验证输出。分辨率提高只能改善部分感知问题，不能自动解决指代漂移、推理操作和奖励验证。

## 感知：从像素到视觉表示

ViT 把图片切成图块，为每块建立局部特征，再由 Transformer 编码器让各图块读取全图关系。资料中的 $224\times224$ 彩色图像被切为 196 个 $16\times16$ 图块，每块包含 768 个 RGB 数字；这些是对应教学配置，不是所有视觉模型的固定输入。（[[wiki/sources/多模态模型：ViT 图像分块与编码|ViT]]）

视觉表示还需要进入语言模型。多模态技术地图列出 MLP Projection、Q-Former 与 Cross-Attention 三类接口，并强调架构之外的数据质量、模态配比与去重。18M 伪三元组并不必然优于约 60K 人工三元组，12M 样本模型也可能不如 260K Mulberry 数据模型；数据量不能替代任务匹配。（[[wiki/sources/多模态模型：架构、数据、推理与检索|多模态技术地图]]）

## 指代：从 Perception Gap 到 Reference Gap

模型看见对象，不代表推理过程能稳定引用对象。自然语言中的“左边那个”或“它旁边的”可能随步骤发生指代漂移。视觉原语把点和框写进推理链，用坐标把语言概念绑定到可重复引用的位置，处理的是 Reference Gap，而不是单纯提升图像清晰度。（[[wiki/sources/多模态推理：视觉原语与 Reference Gap|视觉原语与 Reference Gap]]）

视觉 Token 压缩也必须保留这一边界。两层压缩减少 KV Cache 和计算，但压缩率、坐标精度和任务准确率要同时测量；原始像素数与缓存条目数之比不能直接视为语义信息压缩率。

## 操作：交错生成视觉中间状态

ThinkMorph 的 Interleaved CoT 让模型在文本规划和图像操作之间交替：模型可以生成裁剪、放大、重绘或其他视觉中间结果，再依据新图继续推理。资料报告三类涌现能力：执行训练中未直接出现的视觉操作、自主选择文本或视觉路径，以及通过增加视觉步骤进行测试时扩展。（[[wiki/sources/多模态推理：ThinkMorph 交错思维链|ThinkMorph]]）

这种能力不同于 ViT 编码已有图片。ViT 负责把输入转成表示，视觉原语负责稳定引用，ThinkMorph 负责生成新的可见中间状态；三者可以衔接，但不能互相替代。

## 验证：格式、过程与结果共同约束

视觉原语训练先分别训练框与点专家，再通过 Unified RFT 与 OPD 合并。三层奖励检查坐标格式、原语与答案一致性，以及迷宫或路径任务的合法过程和最终结果。Specialized SFT 采用 70% 通用多模态／纯文本数据与 30% 原语数据；后训练没有中文语料，资料把中文能力归于底座迁移。（[[wiki/sources/多模态推理：视觉原语的数据、训练与奖励|视觉原语训练]]）

要让这类推理进入工程系统，还需要统一原语接口、坐标规范、程序化检查器和原语—答案一致性监控。最终答案正确不能证明中间坐标合法，中间格式正确也不能证明任务完成。

## 检索是另一条轴

跨模态检索解决“从外部集合找到哪段文本、图片或页面”，多模态推理解决“模型怎样处理和操作当前证据”。页面级粗排、元素级精排或 CMR 指标属于检索链路，不能与视觉 CoT 的步骤数或准确率合并成单一排名。（[[wiki/sources/多模态模型：架构、数据、推理与检索|多模态技术地图]]）

DLSS／FSR 的时序图像重建也不属于这条推理闭环。它们使用低分辨率帧、历史帧、运动矢量和渲染辅助参数恢复画面，核心目标是实时重建与帧率取舍，应归入模型工程的推理优化。（[[wiki/sources/图像重建：DLSS 与 FSR 的时序超分辨率|DLSS 与 FSR]]）

## 评估矩阵

多模态系统应分别记录感知准确率、指代一致性、视觉操作合法性、最终任务结果、文本 Token、图像 Token、隐藏计算、延迟与可审计性。不同资料的模型、训练集和基准不一致，不能把各自提升比例拼成统一能力榜。
