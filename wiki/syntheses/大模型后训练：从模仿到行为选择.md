# 大模型后训练：从模仿到行为选择

大模型后训练把基础模型已有的生成能力转化为更符合任务目标的行为。SFT 主要通过示范让模型学习怎样回答；偏好优化与强化学习进一步依据反馈，改变模型在多个合理答案或行动路径之间的选择倾向。（[[wiki/sources/大模型后训练：强化学习如何选择反馈与算法|强化学习专题]]、[[wiki/sources/提示词工程：第一期 提示词工程入门|提示词工程第一期]]）

## 先判断问题属于哪一层

| 问题 | 优先机制 | 判断依据 |
| --- | --- | --- |
| 模型缺少知识或基础能力 | 预训练、数据建设或外部知识 | 现有行为集合中没有可靠答案 |
| 模型不会按指令完成任务 | SFT | 有高质量示范可供模仿 |
| 已有离线偏好对 | DPO | 需要稳定、较低成本的偏好优化起点 |
| 目标依赖人的主观偏好 | RLHF | 帮助性、安全性、表达质量难以程序化判定 |
| 反馈可由 AI 提供 | RLAIF | 接受裁判偏差、迎合风险并具备校准手段 |
| 结果有可靠验证器 | RLVR，可结合 GRPO | 测试、规则或环境结果能提供清晰信号 |

这张表不是算法排行榜。后训练路线由反馈来源、反馈质量和工程约束共同决定；算法跟着反馈走，而不是先选算法再寻找适配信号。

## 从回答优化到轨迹优化

单轮模型的主要对象是答案，多轮 Agent 的对象是完整轨迹。轨迹包括任务理解、计划、工具选择、状态修改、错误恢复和最终结果。只优化最后答案，无法解释中间哪一步造成失败，也无法保证 Agent 在真实环境中持续可靠。

Agent RL 因此需要同时确定五件事：反馈从哪里来，奖励给到多细，训练数据来自离线样本还是在线 rollout，任务是单轮还是多轮，以及推理服务、奖励计算、训练框架、环境沙箱、评测和日志能否形成闭环。（[[wiki/sources/大模型后训练：强化学习如何选择反馈与算法|强化学习专题]]）

## 环境状态也是轨迹的一部分

长时程 Agent 的轨迹不只包含消息和工具调用，还会持续修改文件系统、进程、依赖、数据库和操作系统状态。Kimi K3 的 AgentENV 将这层外部环境与模型版本、消息历史和 KV Cache 分开管理，并通过 Pause and Resume、Fork 与 Snapshot 支持跨等待期和训练迭代的持久化。（[[wiki/sources/Agent 强化学习基础设施：Kimi K3 AgentENV|Kimi K3 AgentENV]]）

Partial Rollout 在一批轨迹完成到设定比例后先更新策略，未完成轨迹暂停并在下一轮优先恢复。它缓解长尾任务拖住整批训练的问题，却也使一条轨迹可能跨越多个模型版本，形成 Off-Policy 数据陈旧；Kimi K3 以逐 Token 正则化限制策略变化。环境快照解决外部世界能否恢复，正则化解决陈旧轨迹怎样参与模型更新，两者不能混为同一机制。

报告中的 51,219,741 个沙箱、1,505,678 种镜像、最低 133/49 毫秒检查点与恢复延迟，以及最高 6.5 倍内存超配都属于 Kimi K3 的训练和评估基础设施条件。这些数字证明环境生命周期已经成为大规模 Agent RL 的资源调度对象，不构成其他训练集群的性能保证。

## 把工具调用训练成原生动作

Kimi K2 Thinking 展示了一条从合成轨迹到长程 Agent 的后训练路径。SFT 数据系统先建立 3,000 多个真实工具与 20,000 多个合成工具的规范库，再生成 Agent、任务、成功标准和交互轨迹；User Agent、Tool Simulator 与 Judge Agent 只保留成功轨迹，编码和软件工程领域还接入真实执行沙箱。函数调用由此不再只是提示词约定，而成为训练数据中的原生动作。（[[wiki/sources/大语言模型：Kimi K2 Thinking 的 MoE 架构与 Agent 训练|Kimi K2 Thinking]]）

强化学习同时使用两类反馈：Verifiable Rewards“Gym”覆盖数学、编码、软件工程和忠实性等可验证任务；Self-Critique Rubric Reward 让 Actor 生成多个回答，再由 Critic 按清晰度、客观性和避免 Sycophancy 等规则排序。Critic 继续接受可验证反馈校准，以降低主观评分完全脱离客观锚点的风险。Budget Control、PTX Loss 与 Temperature Decay 分别控制过长输出、减少灾难性遗忘，并推动训练从探索转向利用。

这套方法仍不能把合成成功轨迹等同于真实可靠性。模拟器、Judge 与 Rubric 可能共享盲点，200～300 次连续工具调用也只来自对应设置。独立沙箱执行、轨迹级评测和调用端模型版本记录仍属于必要基础设施。

## 把 Harness 纳入训练对象

RLM 进一步把后训练对象从模型参数扩展为模型与 Harness 的组合。Harness 通过 Context Offloading 和 Programmatic Subcalls，把长任务或陌生领域拆成局部分布内的调用；强化学习优化的不只是答案或动作，还包括怎样探查数据、切块、派发子调用和汇总结果。（[[wiki/sources/大模型后训练：RLM Harness 组合泛化|RLM Harness 专题]]）

这条路线与“轨迹优化”互补：轨迹仍是训练和评估单位，但泛化目标从复现具体轨迹转为学习可跨长度、跨领域复用的程序骨架。RLM 实验也显示，训练奖励较高的裸模型可能只记住短任务；只有训练外的长任务和新领域评测，才能证明组合泛化。（[[wiki/sources/大模型后训练：RLM Harness 组合泛化|RLM Harness 专题]]）

Harness 并不保证强化学习自动找到通用方案。模型可能把完整输入交给单次子调用，在短任务上形成捷径；提示、奖励和探索仍需推动系统使用真正可扩展的分解。单样本多轮调用还带来 1.5～3.0 倍耗时，必须与长 Context 直接训练的增长成本比较。（[[wiki/sources/大模型后训练：RLM Harness 组合泛化|RLM Harness 专题]]）

## 把轨迹蒸馏为可复用技能

原始轨迹可以为后训练提供数据，却不适合不加处理地充当长期经验。轨迹过长、噪声高，直接检索会消耗上下文，直接用于强化学习又会扩大探索空间。SKILLRL 提供了另一条路径：由教师模型把成功轨迹蒸馏为通用技能，把失败轨迹蒸馏为避坑规则，再让策略模型通过冷启动 SFT 学会使用技能，最后进入技能增强 RL。（[[wiki/sources/大模型后训练：SKILLRL 技能增强强化学习|SKILLRL 专题]]）

这套结构把学习分成两个可更新部分：模型参数负责在任务中选择和执行行为，外部技能库负责保存可迁移、可检索、可增量修订的经验。验证失败同时成为策略评测信号和技能库更新输入，使两者协同演化。

技能外置并不消除工程成本。技能库需要去重、冲突处理和淘汰，在线检索需要延迟预算，教师模型决定蒸馏质量，环境反馈还必须防止模型假装使用技能骗取奖励。数千步任务中的信用分配仍然没有被外部技能库自动解决。

HarnessX 把协同对象从外部技能进一步扩展为完整运行时外壳：不同 Harness 版本为同一任务产生结构化行为差异，Cross-Harness GRPO 再按任务比较这些轨迹并训练模型。共享 Rollout 同时服务于外壳进化和参数更新，降低重复环境采样；但这要求团队同时掌控 Harness 与模型训练，并用独立评测防止外壳与验证器共同过拟合。（[[wiki/sources/驾驭工程：HarnessX 可进化 Agent Harness|HarnessX 专题]]）

## 冻结权重后的运行时学习

MemRL 把强化学习的反馈留在情景记忆层，而不更新模型参数。它先用余弦相似度寻找语义相关记忆，再以历史任务成败形成的 Q-value 精排；环境奖励通过蒙特卡洛规则更新记忆效用，并把新轨迹摘要写回记忆库。（[[wiki/sources/Agent 记忆：MemRL 运行时强化学习|MemRL 专题]]）

这与 SKILLRL 的参数化策略和外部技能协同演化不同：MemRL 的语言模型始终冻结，学习对象是记忆选择。它降低了持续微调和灾难性遗忘风险，却没有消除奖励设计、错误反馈、记忆淘汰和跨 Agent 污染问题。（[[wiki/sources/Agent 记忆：MemRL 运行时强化学习|MemRL 专题]]）

## 合成世界也是训练环境

开放任务无法完全写成确定性规则时，语言世界模型可以预演动作反馈并生成训练轨迹。Qwen-AgentWorld 的资料转述实验中，在完全虚构、可控的模拟世界中训练略微超过真实环境训练，原因是模拟器能够稳定生成网络错误、残缺结果和分页等异常。该结果属于对应实验，不证明合成环境普遍优于真实环境；学习型世界模型仍需真实轨迹校准。（[[wiki/sources/Agent 世界模型：服务于行动的选择性压缩|Agent 世界模型]]）

这条路线与代码检查器共同说明，合成环境既可以由确定性代码构造，也可以由语言模型学习。前者边界清晰但覆盖有限，后者覆盖开放交互但会继承模拟偏差；两者都需要独立验证，不能让训练环境同时成为唯一评测标准。

## 奖励与评测必须分工

奖励用于驱动训练，评测用于判断模型是否真正变好。二者使用同一批数据、同一个评分器或同一类漏洞时，模型可能只学会提高训练分数。独立评测集、对抗样本、人工轨迹抽检和线上行为分析提供训练外证据，用来识别 Reward Hacking。

这与评估工程的原则一致：评分必须有独立标准，Agent 既要保存 Transcript 以定位路径问题，也要检查 Outcome 是否真正完成任务；新失败还应进入回归集。（[[wiki/syntheses/评估工程：从通用基准到业务质量门|评估工程综合]]）

## 最小采用规则

1. 先确认任务存在稳定、可承受成本的反馈。
2. 能用规则、RAG 或 SFT 稳定解决时，不增加 RL。
3. 单轮看答案，多轮看轨迹。
4. 结果奖励承担主目标，过程奖励只覆盖关键步骤，格式奖励保持低权重。
5. 先用离线数据建立基线，再以受控在线采样补充当前失败。
6. 训练奖励必须与独立评测和线上行为交叉验证。
