# 上下文工程：有限窗口中的信息治理

## 总体框架

上下文工程是在有限窗口和有限注意力下管理模型所见信息。目标不是塞入最多内容，而是在每一轮构建完成任务所需的最小、高信号、可追溯，并已识别冲突的 Token 集。（[[wiki/sources/上下文工程：第三期 原则、策略、评估|第三期]]、[[wiki/sources/上下文工程：第七期 上下文是怎么坏掉的|第七期]]）

```mermaid
flowchart LR
    A["外部知识与历史"] --> B["写入与存储"]
    B --> C["检索与选择"]
    C --> D["压缩与分层"]
    D --> E["结构化与隔离"]
    E --> F["组装当前上下文"]
    F --> G["模型生成"]
    G --> H["检索、生成与端到端评估"]
    H --> B
```

## 生产流程

1. 把长期知识、用户偏好、任务状态和证据存到窗口外。（[[wiki/sources/上下文工程：第三期 原则、策略、评估|第三期]]、[[wiki/sources/上下文工程：第五期 上下文工程压缩|第五期]]）
2. 按当前问题检索相关信息，对复杂问题进行查询分解或多跳检索。（[[wiki/sources/上下文工程：第四期 RAG 检索增强生成|第四期]]）
3. 在保证锚点约束和来源元数据不丢失的前提下压缩历史与文档。（[[wiki/sources/上下文工程：第三期 原则、策略、评估|第三期]]、[[wiki/sources/上下文工程：第五期 上下文工程压缩|第五期]]）
4. 用标签或结构化字段区分系统规则、外部文档、示例、工具结果和用户输入。（[[wiki/sources/上下文工程：第六期 结构化与隔离|第六期]]）
5. 默认建立隔离边界，确认需要后再放开，并按风险选择物理、逻辑或沙箱强度。（[[wiki/sources/上下文工程：第六期 结构化与隔离|第六期]]）
6. 分别评估检索质量、生成质量与真实端到端效果。（[[wiki/sources/上下文工程：第三期 原则、策略、评估|第三期]]）

## 2026 年智能体生产架构

系列第八期把前七期的工具组合成五层架构。这些层次不互相替代，而是在信息进入模型之前和任务执行期间逐层减少无关 Token。（[[wiki/sources/上下文工程：第八期 2026 生产实践|第八期]]）

1. **技能加载**：默认只暴露技能名与描述，命中任务后再加载完整指令、参考材料和脚本。
2. **混合压缩**：保留最近对话、工具返回和尚未解决失败的原始格式，用摘要替换旧历史。失败信号在正在引导修正时应保留；当状态已验证、细节不再影响后续决策时，再转为结构化结论或清理。
3. **上下文路由**：先分类查询，再加载相关领域的指令、知识和工具，把选择点前移到窗口之外。
4. **自主检索**：用 Agentic RAG 调度检索策略，用 GraphRAG 补关系推理，用 Self-RAG 判断检索必要性与结果质量，并以信心阈值或轮次上限结束循环。
5. **工具管理**：MCP 和 Skill/CLI 分别偏向结构化交互与执行任务，但都需配合搜索、路由或屏蔽，使模型只看到当前需要的工具定义。

## 与 Loop Engineering 的边界

上下文工程管理“模型在当前轮次看到什么”，Loop Engineering 管理“系统跨轮次怎样继续决策”：怎样触发下一轮、组织执行、检查结果、把结果送回持久状态，以及何时停止。前者提供每一轮的信息治理，后者把这些轮次连接成决策流。（[[wiki/sources/上下文工程：第八期 2026 生产实践|上下文工程第八期]]、[[wiki/syntheses/循环工程：从逐轮操作到外部调度|循环工程综合]]）

Prompt、Context 和 Loop 是三层递进能力，Harness 则是包住三层并横切工具、权限、安全与恢复的工程外壳。人的职责随之从逐轮提供 Prompt，转向在循环外设计调度、反馈、验证与停止机制。自动化能力增强时，还需要管理验证债、理解腐烂、认知投降和 Token 失控；四者会沿状态回写形成因果链，并在循环运行速度超过人的审查速度后持续放大。（[[wiki/sources/循环工程：先导篇 从 Prompt 到 Loop|循环工程先导篇]]、[[wiki/sources/循环工程：第一期 什么是 Loop Engineering？|循环工程第一期]]、[[wiki/sources/循环工程：第二期 三大流派与四笔代价|循环工程第二期]]）

两层复用相同组件，但赋予它们不同职责。Agent Skills 在 Context 层按需加载知识，在 Loop 层固化每轮都要复用的项目规则；Sub-agents 在 Context 层隔离探索并返回摘要，在 Loop 层分离生成者和评判器。工具平台在当前轮承担检索、压缩和结构化，在跨轮流程中承担调度、完成条件、并行隔离与外部连接。（[[wiki/sources/循环工程：第四期 搭好 Loop ≠ 能上线？|循环工程第四期]]）

## 失败诊断

- 错误被后续持续引用：检查毒化与写回策略。（[[wiki/sources/上下文工程：第七期 上下文是怎么坏掉的|第七期]]）
- 模型反复重复旧结论：检查历史分心并触发摘要或重建。（[[wiki/sources/上下文工程：第五期 上下文工程压缩|第五期]]、[[wiki/sources/上下文工程：第七期 上下文是怎么坏掉的|第七期]]）
- 工具多但选择错误：减少工具负载，只提供当前任务相关定义。（[[wiki/sources/上下文工程：第七期 上下文是怎么坏掉的|第七期]]）
- 相同工具失败被重复触发：在问题解决前保留近期调用参数、原始返回和错误栈，不要过早摘要或删除。（[[wiki/sources/上下文工程：第八期 2026 生产实践|第八期]]）
- 新事实无法纠正旧判断：隔离任务上下文，主流程只接收蒸馏摘要。（[[wiki/sources/上下文工程：第六期 结构化与隔离|第六期]]、[[wiki/sources/上下文工程：第七期 上下文是怎么坏掉的|第七期]]）
- 文档存在却答不到：检查分块、检索、排序和 Lost in the Middle，而不是继续扩大窗口。（[[wiki/sources/上下文工程：第二期 窗口与 Token|第二期]]、[[wiki/sources/上下文工程：第四期 RAG 检索增强生成|第四期]]）
