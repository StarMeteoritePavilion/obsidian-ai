# 模型推理优化：Token 成本、KV Cache 与缓存机制

原始资料：[[raw/sources/模型工程/推理与服务/同样100万Token，为什么有的模型贵30倍？大模型 API 到底在卖什么？一口气讲透 Token 成本、KV Cache 和缓存机制|模型 API 的成本结构：输入、输出、缓存与批处理]]

## 核心结论

- API成本应分别计算输入、输出、缓存写入、缓存读取、批处理与重试，比较时固定平台、模型、日期和调用条件。
- Prefill可并行处理完整输入；Decode逐Token生成并受显存带宽和调度影响，但硬件差异不能直接推出所有平台的定价比例。
- KV Cache保存历史Key/Value，长度增加会提高显存占用并压低并发；提示词缓存复用稳定前缀，内容、模型或配置变化后不能无条件命中。
- 资料以2026-09-07读取的Claude价格页复算具体费用。价格属于该日页面快照，不是行业常数，也没有执行真实API调用。

## 限制

低单价不等于任务总成本低，高单价也不保证一次成功。应以完成同一任务的成功成本、延迟和可靠性共同决策。
