# 多模态模型：架构、数据、推理与检索

原始资料：[[raw/sources/模型原理/视觉与多模态/多模态 AI 技术地图：架构、数据、推理与检索|多模态 AI 技术地图：架构、数据、推理与检索]]

## 核心结论

多模态系统是一条连续工程链：视觉编码器保留图像信息，模态接口完成视觉与语言表示对齐，数据工程控制监督质量，MCoT 组织跨模态中间步骤，CMR 与多模态 RAG 从外部视觉资料中检索目标或证据。任何单层优化都不能代替其余层级。

MMLongBench-Doc 案例中，完整视觉内容约需 206M 个视觉 Token，而所比较模型的窗口上限为 128K，相差 1,609 倍；资料据此估算约有 0.06% 的 PDF 信息可以直接进入上下文。这是对应视觉表示和基准下的容量案例，不是所有文档系统的固定比例。

## 架构与数据

典型多模态大语言模型由视觉编码器、模态接口和预训练语言模型组成。接口主要包括 LLaVA 使用的 MLP Projection、BLIP-2 使用且包含 32 个可学习 Query Token 的 Q-Former，以及 Flamingo 使用的 Cross-Attention。资料汇总超过 120 个模型时，画面显示分辨率由 224 提至 336 对应 11.5% 的提升，MLP 换为 Q-Former 对应 1.2%；结果只适用于该汇总口径。Visual Contrastive Decoding（VCD）可在解码期缓解视觉幻觉。

数据工程需要同时处理质量、配比和重复。ShareGPT4V 的 100K 条高质量描述在资料画面中对应约 2% 的核心提升，旁白则概括多个基准提高 3%～8%，本库保留两种口径。MM1 的图文配对、交错图文和纯文本比例为 `5:5:1`。去重分为 Hash 精确去重、MinHash/LSH 近似去重和语义去重。资料还指出，对超过 10B 条图片描述进行过度重写后，ImageNet 准确率下降 1%～3%，说明语言更流畅不等于视觉监督更准确。

资料还以两组跨研究对照说明规模不能替代质量和任务匹配：组合式多模态检索中，18M 个伪三元组并非在所有设置下都优于约 60K 个人工标注三元组；多模态思维链中，使用 12M 样本的模型也不如使用 260K 条 Mulberry 数据的模型。两项比较来自不同研究，不能合并为对训练规模的一般否定。

## 推理、检索与边界

MCoT 的路线从 Prompt 提示、SFT 长链训练发展到 RL。资料称 Mulberry 7B 在 MathVista 上为 63.1，接近所列 GPT-4o 的 63.8；MM-Eureka 38B 在同一基准上为 67.1，高于资料所列 Human 60.3，并出现反思与回溯。可验证奖励适合数学、科学和代码，情感、创意及社会常识等开放任务的奖励仍难定义。

CMR 包括有监督、零样本和半监督三种范式。Pic2Word 将图像映射为 pseudo token，PrediCIR 在 CIRR 上的 Recall@1 为 39.70；CompoDiff 用 Stable Diffusion 构造 18M 个伪三元组，仍需 CLIP 相似度过滤。

ColPali 使用 PaliGemma 和 Patch-level 多向量视觉索引，在 SlideVQA 上的 `nDCG@5` 为 54.4。SimpleDoc 通过页面级粗排与元素级精排结合，在 MMLongBench-Doc 上的 `G-Acc` 为 60.58。资料称当前较优端到端延迟约为 2～5 秒，距离 500ms 工业目标仍有约 4～10 倍差距。

所有数字来自资料转述的对应研究设置，不能合并成统一排行榜或外推为其他模型、任务和部署的普遍规律。资料留下两个开放问题：怎样为开放域多模态 RL 定义可靠奖励，以及怎样融合 CMR 与 RAG。
