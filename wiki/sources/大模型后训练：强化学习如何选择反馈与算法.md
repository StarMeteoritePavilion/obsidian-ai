# 大模型后训练：强化学习如何选择反馈与算法

原始资料：[[raw/sources/模型工程/后训练/大模型强化学习一次讲透：RLHF、DPO、GRPO、RLVR 到底怎么选？|大模型强化学习一次讲透：RLHF、DPO、GRPO、RLVR 到底怎么选？]]

## 核心结论

强化学习不是为模型补知识，而是依据反馈调整模型在多种可能行为中的选择倾向。算法选择应从反馈条件出发：人类偏好对应 RLHF，AI 裁判对应 RLAIF，可靠验证器支持 RLVR，可验证任务还可考虑 GRPO；已有离线偏好数据时，DPO 通常是更稳定的早期起点。

## Agent RL 的工程边界

Agent 的训练对象不是单个答案，而是包含工具调用、状态变化、环境噪声和失败恢复的完整轨迹。资料用代码修复 Agent 说明五个必须先回答的问题：反馈来源、奖励粒度、数据来源、单轮或多轮任务，以及推理、奖励、训练、沙箱、评测和日志能否形成系统闭环。

结果奖励成本低但难以进行信用分配；过程奖励信号细却昂贵且可能互相冲突；组合奖励应以最终结果为主、关键步骤为辅，并降低格式奖励的权重。数据则先以离线样本建立稳定基线，再通过受控在线 rollout 捕获当前模型的新失败模式。

## 奖励黑客

模型会优化实际奖励，而不是设计者未被编码的真实意图。堆砌篇幅、追求空洞排版、写死测试输入输出和迎合 AI 裁判都属于奖励黑客。训练奖励上涨只能证明模型更会得分，不能单独证明能力提升。

资料提出四道防线：独立评测集、对抗样本、人工轨迹抽检和线上行为分析。其共同目的，是把训练奖励与训练外的真实行为证据对照。

## 适用条件

RL 适合有稳定反馈、有迭代空间，并且行为选择确实影响最终结果的任务。没有稳定反馈时应先补评测和数据闭环；规则、RAG 或 SFT 已能稳定解决时不必增加 RL；验证器成本高于收益或线上试错不可控时，也应采用更简单的方案。
