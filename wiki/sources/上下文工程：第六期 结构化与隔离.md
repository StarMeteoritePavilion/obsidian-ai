# 上下文工程：第六期 结构化与隔离

原始资料：[[raw/sources/应用工程/上下文与知识工程/第六期：结构化与隔离|第六期：结构化与隔离]]

## 核心结论

结构化解决同一上下文内部的信息身份与层级问题，隔离解决不同任务之间的约束、状态和结果污染。内容类型少时使用分隔符，复杂内容使用 XML，需要程序化处理时使用 JSON。

## 主要内容

- 结构化遵循分类清晰、层次分明、边界明确和关系显式四项原则。
- XML 标签应统一命名、控制嵌套深度，并对动态用户输入做转义，防止标签注入。
- Prompt 可按稳定性拆成核心身份、任务框架、具体指令和格式约束，复用稳定前缀。
- 物理隔离使用独立调用与上下文，逻辑隔离在共享窗口内分区，代码沙箱隔离执行和大对象。
- 多智能体场景中，子任务使用独立上下文，主流程只接收结构化的必要结论，避免传回完整日志。
- 默认建立隔离边界，确认需要后再放开；隔离强度按风险选择，支付、权限等高风险任务优先使用物理隔离。
