# 大语言模型：Qwen 3.5 的 MoE、混合注意力与应用演示

原始资料：[[raw/sources/模型原理/大语言模型/Qwen 3.5 为何爆火？ 从架构到应用：MoE、混合注意力、Agent 工作流一次讲透|Qwen 3.5 为何爆火？]]

## 核心结论

资料把 Qwen 3.5 定位为面向 Agent 工作流的原生多模态模型。其架构以 397B 总参数、17B 激活参数的稀疏 MoE 分离容量与单 Token 计算，以 75% 线性注意力和 25% 全注意力的交替结构控制长上下文成本，再通过异步强化学习、多 Token 预测、Early Fusion 与视觉 Agent 能力支持多步规划和界面操作。

## 架构与训练口径

画面给出的规格包括 512 个专家、每个 Token 激活 10 个路由专家和 1 个共享专家、60 层、4,096 隐藏维度、248,320 词表、262,144 Token 原生上下文，以及托管版本最高 1,048,576 Token 上下文。资料称成本降低 60%、吞吐提高 8 倍、长上下文最高提高 19 倍，并支持 201 种语言；视频未提供这些数字的完整基准、硬件与比较范围，不能脱离来源口径外推。

训练侧采用 20,000 个并行环境中的异步强化学习，目标是多步规划和工具调用；MTP 让一次前向传播预测多个 Token。资料把该层称为“门控网络＋大规模强化学习训练”，但没有解释门控网络的精确结构或提供训练消融，因此摘要不补写未出现的技术细节。

## 多模态与两组案例

Early Fusion 表示文本 Token 与视觉 Token 从预训练阶段共同处理。资料称图像最高支持 $1344\times1344$，并能处理复杂 PDF 与图表；视觉 Agent 还可以识别界面按钮、输入框和菜单，规划跨应用步骤并生成点击、输入与滑动指令。

网页端太阳系图片案例得到符合作者判断的描述。斯蒂芬·库里视频案例中，模型本次正确识别五次投篮且全部命中，并在错误诱导下坚持原判断；作者也记录此前运行曾误判为七次。两次结果共同说明模型具备视频理解与证据引用能力，但输出存在运行间波动，单次演示不能代替系统评测。

## API 工作流与 Harness 边界

API 演示通过阿里云百炼创建密钥，在 VS Code 的 Cline 中选择 `OpenAI Compatible`，填写 DashScope Base URL、API Key 和 `qwen3.5-plus`，再用 Act 模式生成三维太阳系网页。该链路把模型能力与外部 Harness 清楚分开：Qwen 3.5 负责理解和生成，Cline 负责工具、文件和执行流程，运行环境与人工检查负责验证结果。

资料记录的新账号 100 万 Token 免费额度、640GB 本地显卡需求和“小模型尚未开源”均对应 2026 年 2 月 20 日。产品选项、计费和部署条件变化较快，实际使用前需要重新核对官方信息。
