# 循环工程：第一期 什么是 Loop Engineering？

原始资料：[[raw/sources/应用工程/循环工程/第一期：什么是 Loop Engineering？|第一期：什么是 Loop Engineering？]]

## 核心结论

Loop Engineering 把原本由人承担的逐轮触发、分工、反馈和推进机制交给系统。人的位置由循环内部移到循环外部，从操作 Agent 转变为设计目标、约束、验证、停止条件和恢复机制。

## 三层与外壳

- **Prompt** 管递给模型的一段话。
- **Context** 管当前窗口里装什么。
- **Loop** 管系统怎样自行触发、分工、回写状态并持续运行。
- **Harness** 是包住三层的工程外壳，横切工具、权限、安全与恢复，而不是与三层并列的第四层。

这一结构修正了先前资料中的四层排列。两份资料对 Loop 的职责和人的位置迁移结论一致，但对 Harness 的位置采用了不同表达。

## 循环成立的三个动作

1. 通过定时器自行唤醒和启动。
2. 孵化子 Agent，组织并行分工和相互监督。
3. 把结果写入持久状态，让下一轮能够接力。

缺少自行触发和结果回写，多次运行仍只是由人手动启动的单次执行。

## 失败边界

Prompt 和 Context 的错误通常能在当前交互中被看到；Loop 的错误可能在无人值守时持续累积，并被写回下一轮。循环工程的难点因此不是启动循环，而是设置验证、停止条件、安全权限和失败恢复。

循环本身只是放大器。它既能放大操作者已经掌握的知识，也能放大对理解工作的逃避，因此人离开内层执行后仍需承担外层判断和结果责任。
