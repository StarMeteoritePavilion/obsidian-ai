# 驾驭工程：系列完结，下一步该往哪走？

原始资料：[[raw/sources/应用工程/驾驭工程/系列完结，下一步该往哪走？|系列完结，下一步该往哪走？]]

## 系列收束

本篇是 Harness 工程系列的收尾篇。官方合辑显示该系列共有 28 集；本篇回顾已收录的提示词、上下文、循环与评估四个工程主题，并将后续方向指向观测、优化、安全和 Vibe Coding 实战。

资料把提示词工程概括为让 AI 听懂任务，把上下文工程概括为提供必要的最小范围信息，把循环工程概括为让 AI 自动运行，把评估工程概括为让输出可量化、可拦截、可审计。前四部分的详细结论见 [[wiki/syntheses/提示词工程：从单轮指令到生产规范]]、[[wiki/syntheses/上下文工程：有限窗口中的信息治理]]、[[wiki/syntheses/循环工程：从逐轮操作到外部调度]] 和 [[wiki/syntheses/评估工程：从通用基准到业务质量门]]。

## 作者对 Harness 的定义

资料明确指出 Harness Engineering 没有统一准确定义。作者采用较宽的个人定义：模型之外的部分均属于 Harness，Agent 的治理、优化和编排也在其中；提示词、上下文、循环和评估工程因此都可归入“驾驭工程”。

这一定义与本库此前采用的结构并不相互替代：[[wiki/sources/循环工程：第一期 什么是 Loop Engineering？|循环工程第一期]] 将 Harness 定义为包住 Prompt、Context 与 Loop 的工程外壳，横切工具、权限、安全和恢复。本篇将其作为作者的系列总括口径保留，不把它提升为统一术语定义。

## 后续学习顺序

资料提出三个不再单独展开、但需要自行了解的领域：

1. **观测工程**：观察过程是否正确；与关注结果的评估工程共同为优化提供数据基础。
2. **优化工程**：在成本、效率和质量之间取得更好结果；应在评估与观测建立后进行，避免过早优化。
3. **安全工程**：避免事故，覆盖护栏、合规、权限与审计；生产级应用不能绕开。

资料最后转向 Vibe Coding 实战。该方向属于频道后续安排，不构成上述三个领域已经完成的工程结论。
