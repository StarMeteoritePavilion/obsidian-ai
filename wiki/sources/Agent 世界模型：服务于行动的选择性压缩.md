# Agent 世界模型：服务于行动的选择性压缩

原始资料：[[raw/sources/应用工程/AI Agent/Agent 的“世界模型”到底是什么？从第一性原理，讲透它为什么总在同一个坑里栽倒｜AI Agent 深度解析|Agent 的“世界模型”到底是什么？]]

## 核心结论

资料采用宽泛工程定义，把 Agent 世界模型理解为一张用于判断“执行这一步后世界怎样变化”的压缩图。它不追求完整复制环境，而是按目标相关、可影响、失败后有助恢复、可验证复用四项标准选择信息。邮件服务器案例说明，Agent 即使持续修改配置，只要请求处理流程的初始判断错误，后续搜索仍会反复落入同一失败路径。

## 三层结构与记忆时效

环境层是真实网页、代码仓库或物理环境；判断层是 Agent 当前形成的主观状态与因果图；知识层保存代码、测试、文档和已验证经验。知识存在不等于判断正确，判断层还会随任务和环境变化而过期。

资料以 `STALE` 基准和《Honest Lying》说明两类风险：模型识别过期记忆的能力有限，而且“知道过期”不等于行动时不再采用；表达自信但错误的总结还可能被保存为经验。世界模型和记忆都需要来源、验证状态、时效与失效条件。

## 检查器与学习型世界模型

规则明确时，世界模型可以缩小为一段确定性检查代码。资料所述公开 AI 下棋比赛中，某模型败局的 78% 来自非法走子；单步合法率 90% 连续 30 步后，整局全合法概率约为 4%。AutoHarness 让 Agent 自动生成合法性检查器，在对应实验中把合法动作率推近 100%，并在易犯规游戏的对比中形成“大模型无检查器 71%、小模型配检查器 94%”的结果。

另一条路线由 Qwen-AgentWorld 代表：用语言世界模型预演开放任务的动作反馈。资料转述的实验中，可控虚构环境训练略微超过真实环境训练，因为模拟器可以稳定生成网络错误、残缺返回和分页等异常；学习型世界模型仍需真实轨迹校准。

两条路线的核心差异是确定性代码与学习型语言模型，不是简单的现实与模拟之分。采用前应先确认最大失败来源能否由小检查器解决。

## 边界

检查器用于优化后可能被 Agent 钻判定漏洞，学习型模拟器也可能放大自身偏差。两者都不是环境真理，必须接受真实执行、独立评测和版本治理。世界模型本身会随 API、规则和权限变化而过期，因此评价标准应是它为行动保留了什么，而不是它看起来多完整。
