# 大模型后训练：SKILLRL 技能增强强化学习

原始资料：[[raw/sources/模型工程/后训练/Agent 总犯同样的错？SKILLRL技能增强强化学习：把失败轨迹蒸馏成技能库，胜率硬拉 12%+！冷启动微调 + 验证驱动进化|Agent 总犯同样的错？SKILLRL 技能增强强化学习]]

## 核心结论

SKILLRL 把冗长的成功和失败轨迹蒸馏为结构化技能，再通过冷启动 SFT、技能增强 RL 和验证驱动热更新，让模型参数与外部技能库协同演化。它针对的是 Agent 无法复用高层经验，以及原始轨迹检索带来的噪声、上下文和训练负担。

## 系统结构

系统先收集环境轨迹，由教师模型把成功经验提炼为通用技能、把失败经验提炼为避坑规则；再构造正确使用技能的冷启动数据，让基础模型通过 SFT 学会调用技能；进入强化学习后，每个任务检索相关规则并注入 Prompt，验证失败则触发教师模型识别技能盲区并热更新技能库。

行为锚点约束强化学习后的策略不能偏离冷启动阶段学到的技能使用方式；自适应纠错机制则用验证集失败驱动增量更新。前者防止模型为奖励忽略技能，后者防止技能库长期静止。

## 实验边界

资料转述的消融表中，完整系统在 ALFWorld 和 WebShop 上分别达到 89.9% 和 72.7%。去掉冷启动 SFT 后降至 65.2% 和 46.5%，去掉动态进化后降至 84.4% 和 70.3%；去掉层级技能结构或直接改用原始轨迹也会下降。

这些结果说明各组件在论文实验中共同作用，但不能证明相同收益会出现在其他模型、任务或基础设施中。单条轨迹蒸馏的 10～20 倍压缩，与运行时 Prompt 长度减少约 10.3% 属于不同测量口径。

## 工程限制

技能库持续增长会产生冗余和冲突；强化学习并发采样带来显存压力；教师模型质量限制技能质量；多轮检索增加延迟；不可靠环境反馈会诱发 Reward Hacking。框架还没有解决对中心化强教师模型的依赖，也不能自动解决数千步任务中的信用分配。
