# 评估工程：第四期 评估场景，为什么不需要瑞士军刀？

原始资料：[[raw/sources/应用工程/评估工程/第四期：评估场景，为什么不需要瑞士军刀？|第四期：评估场景，为什么不需要瑞士军刀？]]

## 核心结论

高流量、低延迟、边界稳定的分类评估不一定需要通用 LLM。SLM 裁判把模型容量集中到单一判断，能够以更低成本和延迟覆盖全部流量；代价是适应标准变化和分布外失败的能力较弱。

资料因此不是用 SLM 全面替代 LLM，而是按场景分层：SLM 处理已知分布和高频判断，LLM 接管低置信度、主观、多因素和分布外问题。

## LLM 裁判的生产瓶颈

资料归纳出三项瓶颈：调用成本随流量和指标数量线性增长；1～3 秒延迟难以进入实时链路；成本造成的低比例抽样容易错过罕见但严重的失败。

金融科技案例中的每天 3 万美元降至 600 美元、94% 准确率和全流量覆盖均为本期资料给出的实践数据，适用条件未在视频中展开，不能直接当作其他业务的成本承诺。

## 四类专用裁判

- **Llama Guard 3**：Meta 的安全分类模型；资料介绍的蒸馏版从 8B 压缩到 1B、440MB，F1 下降 1.3%。
- **Luna**：Galileo 的评估模型，直接从 log probabilities 输出结果，侧重低延迟幻觉检测。
- **PHUDGE**：基于 Microsoft Phi-3 3.8B 微调，资料称其在四个基准上取得 SOTA。
- **Prometheus 2**：开放权重的 7B 模型，资料给出其与 GPT-4 评估结果的 Pearson 相关性为 0.6～0.7。

这些指标来自不同任务，不能横向组成统一排行榜。资料用它们说明专用模型各有侧重，而不是证明某个模型适用于所有评估。

## 五步构建路径

1. 准备 300～500 条专家标注测试数据和 1000～10000 条训练样本，并先验证标注者一致性。
2. 根据延迟和准确率要求选择 3B 或 8B 基础模型。
3. 使用 LoRA 微调约 1%～5% 的权重。
4. 在生产样本上测量 F1，并先以影子模式验证。
5. 使用 INT8 量化以及 vLLM 或 TGI 批量部署。

上述数量、时间和成本都是本期资料提供的实施范围。真实项目仍需根据标签难度、硬件和风险要求重新测量。

## 多指标与压缩

LoRA 多指标架构使用一个基础模型和多个小型适配器，资料中的四个适配器合计 55MB，把部署资源从四张 GPU、64GB 显存降为一张 GPU、16GB 显存加适配器。新增指标的主要增量由完整模型变成约 10～20MB 的适配器文件。

压缩路径先用知识蒸馏把 Llama Guard 3 从 8B 压到 1B，再用 INT4 量化得到 440MB 模型。资料称该模型的 F1 只下降 1.3%，并仍在安全分类上超过 GPT-4；这些结论只适用于资料展示的安全分类条件。

## 选型边界

资料给出三个同时满足的切换条件：日评估量超过 1 万条、评估标准稳定两个月以上、任务属于边界明确的二元或分类判断。

SLM 不擅长主观质量、未见失败和多因素上下文判断。最稳妥的生产结构是让 SLM 覆盖稳定高频流量，把低置信度结果升级给 LLM，并继续保留人工黄金集作为校准锚点。
