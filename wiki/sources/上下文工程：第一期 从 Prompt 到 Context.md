# 上下文工程：第一期 从 Prompt 到 Context

原始资料：[[raw/sources/应用工程/上下文与知识工程/第一期：从 Prompt 到 Context|第一期：从 Prompt 到 Context]]

## 核心结论

提示工程关注“跟模型说什么”，上下文工程关注“让模型看到什么”。后者在有限窗口内动态策展系统指令、对话历史、外部知识、工具定义、用户输入和示例样本，是覆盖提示工程的更大工程范围。

## 主要内容

- 六类上下文信息分别承担规则、累积状态、实时知识、能力声明、当前任务和行为示范。
- 每轮交互都会产生工具结果、中间状态与错误，系统需要决定哪些信息写回、保留或丢弃。
- 上下文工程的目标是在正确时间，以正确格式从持续演化的信息中策展出有限的最优信息集合。
- 提示工程、上下文工程、框架工程和记忆工程分别处理指令表达、模型所见信息、安全执行和跨会话记忆。
- 提示工程的静态、单轮和难评测问题，需要通过检索、压缩、记忆、隔离与评估解决。
