# 评估工程：第一期 排行榜遥遥领先，用起来怎么各种拉胯？

原始资料：[[raw/sources/应用工程/评估工程/第一期：排行榜遥遥领先，用起来怎么各种拉胯？|第一期：排行榜遥遥领先，用起来怎么各种拉胯？]]

## 核心结论

通用 Benchmark 衡量模型在统一任务上的能力，不能直接证明模型适合某项业务。评估工程的作用，是用真实业务输入、专家答案和可复现评分，把通用能力翻译成具体场景中的可用性。

完整体系分为四层：黄金数据集提供事实基础；人工、代码和 LLM 三个评分引擎产生判断；评估结果用于改进 Prompt、选择模型、比较版本和降低成本；最终通过 CI/CD 质量门禁阻止不合格变更上线。

## 最小评估集

一套可用的业务评估必须同时包含：

1. 来自真实用户的输入样例。
2. 由领域专家编写的黄金答案。
3. Prompt 与模型的实际输出。
4. 输出相对黄金答案的评分。

资料明确反对让模型自行生成黄金答案，因为这种“自产自销”无法提供独立标准。

## 三种评分方式

- **人工裁判**：适合模糊、主观和强上下文判断，质量高但昂贵、缓慢，无法大规模使用。
- **代码扫描仪**：用精确匹配、关键词和正则表达式检查确定性结果，速度快、成本低，但不适合开放语义任务。
- **LLM 裁判**：速度与语义能力介于两者之间，需要通过明确评分标准和校准限制偏见。

三种方式不是替代关系。成熟评估会把确定性用例交给代码，把可规模化的语义判断交给 LLM，把关键主观问题和抽检留给人。

## 数据规模与分布

资料把 100 对以上作为能够指导决策的黄金数据规模，并将少于 100 对描述为结论不稳定。这个数量是本期资料转述的实践门槛，不是脱离任务分布、错误成本和统计设计即可通用套用的定律。

数据还必须覆盖高频问题、边缘情况和低频长尾，黄金答案由真正理解业务的人标注。样本数量无法补偿错误分布或低质量标签。

## 三阶段成熟路线

1. **Workbench 原型**：以 10 至 20 条真实用例人工评分，快速迭代 Prompt 并建立业务感觉。
2. **半自动过渡**：将标准用例切到代码评分，主观用例保留人工，数据扩展到 100 对以上。
3. **CI/CD 管道**：数据扩展到 1000 对以上，每次修改 Prompt 自动评估，采用自动评分与人工抽检，不及格则阻止上线。

评估数据、维度和评分标准都需要随实际失败持续修订；质量门禁不是一次性配置。
